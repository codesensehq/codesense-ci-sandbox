Arc D · Add user /add-machine-user

Let a teammate onto your machine

The /add-machine-user skill gives a teammate SSH access to a machine, either as their own Unix account or by dropping their public key on a shared account. It only ever handles public keys. Never a private key. Never a password. Never a token.

Own account vs shared account

Pick carefully; the skill recommends own account.

  • Own account recommended — each teammate gets their own Unix login (sam, jo, …). Their files, their agent CLI logins, their keychain. This is CodeSense's private-account mode on this machine. Needs sudo to create the account the first time.
  • Shared account narrow use — everyone works as the same Unix user. Everyone sees and can modify each other's files. No sudo needed to add a key. Fine for a CI box or a lab machine; not for day-to-day.

Walking it

  1. You give the skill four things: the SSH host, the teammate's name for the account (lowercase, e.g. sam), their public key (a single line starting ssh-ed25519 or ssh-rsa, usually from their ~/.ssh/id_ed25519.pub), and which mode: own or shared.
  2. The skill checks the account. ssh <host> 'id -u <name>' tells it whether to create or just add a key.
  3. Own account path. On Linux: shows you the exact sudo useradd -m -s /bin/bash <name> command, waits for your yes, then runs it over ssh -t. On macOS: points you at System Settings → Users & Groups or sudo sysadminctl -addUser. No password is set — the teammate signs in with their key.
  4. Append the key, once. The grep -qxF … || echo … >> pattern guarantees re-running the skill doesn't duplicate the key. Permissions on ~/.ssh (700) and authorized_keys (600) are set to what SSH expects.
  5. Verify & hand over. grep -cxF <key> …authorized_keys prints 1. The skill tells the teammate the host, port, and user name they should use, and points them at Machines → Add machine… in CodeSense.

On a shared Mac

Same skill. The host is the Mac you're adding your teammate to, SSH'd into from your own Mac. CodeSense itself can't onboard a user into another person's local account — that's by design. If two people want to share a Mac for CodeSense work, add the second person as an SSH user on that Mac and treat it as a remote private-account machine from their side.

Make the machine visible to the team

Independently from the SSH authorization, the machine declaration itself (label, host, port, pinned host key) can be shared with your team so every teammate sees the machine in their Machines list and binds their own account to it: 

codesense.invoke('save_machine', {
  label: 'build-box-01',
  host:  'build-box-01.lab',
  port:  22,
  share: { team: 'ops' },
})

The declaration is a team file like any other: it reaches teammates when an agent pushes the context repo and they next pull. Teammates' bindings (their key, their user name) never sync and never leave their own Mac.

Try this now

List the machines this team sees, then run /add-machine-user in a shell tab on your Mac to add your key to one. The skill shows the ssh command before it runs it.

How to do this via MCP

Launch the Machine-setup agent and send it the skill command:

// Open the agent in a tab (or address an existing one via list_sessions).
codesense.invoke('open_terminal_tab', {
  requestId: crypto.randomUUID(),
  launch: { agentKey: 'machine-setup' },
  headed: true,
})

// Drive the skill.
codesense.invoke('run_in_terminal_tab', {
  tab: 'Machine setup',
  command: '/add-machine-user',
})
