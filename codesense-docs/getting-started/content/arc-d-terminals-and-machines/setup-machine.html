Arc D · Setup /setup-machine

Get a machine ready — safely, idempotently

The /setup-machine skill walks a machine from "fresh host" to "CodeSense can run tabs here." It's safe to re-run: it checks before it changes anything, asks before any sudo, and never asks for a password, key, or token. It installs only the agent CLIs and runtimes you actually use.

The five steps

  1. Connect — the skill asks for the SSH host (an alias from ~/.ssh/config or user@host, port if non-22) and runs a cheap probe: ssh <host> 'uname -sm; echo $ID $VERSION_ID'. If it fails, SSH-first: fix the key / host / port.
  2. Check what's there — one ssh round-trip prints which of git curl node npm python3 claude codex is present and whether ~/work exists. The skill shows you the short list.
  3. Install what's missing — one item at a time, with the exact command shown first. Preference order: per-user installs (nvm, pyenv, rustup) over system packages; agent CLIs via their official installers. You sign in to each agent CLI yourself, on the machine.
  4. Test from CodeSense — the skill calls test_machine_connection. First call returns the host-key fingerprint; you confirm; the skill re-runs with that as trustedHostKeyFp. CodeSense pins it.
  5. Summary — what was already there, what got installed, what you still need to do by hand.

Local or remote

The same skill handles both. The only thing that changes is where the shell commands run:

  • Remote (the common case) — commands run as ssh <host> '…'. Your Mac drives it; the remote account is modified. This is the shape the shipped skill assumes by default.
  • Local — if you're bringing up a fresh teammate's Mac under CodeSense, run the skill in a local shell tab and drop the ssh <host> prefix. CodeSense itself needs no local setup, but the agent CLIs do. The same per-user runtime-manager advice applies.

Save it in CodeSense

If the machine isn't in CodeSense yet, either:

  • Use Machines → Add machine… in the UI, or
  • Ask the skill to save_machine for you after you say yes. Choose personal (just you) or team-shared (everyone in the team gets the declaration via the normal sync).

Try this now

Run the connection test the skill ends with. You'll be prompted to confirm the host key fingerprint the first time.

How to do this via MCP 
// First call: no trusted fingerprint — returns the host-key fp.
codesense.invoke('test_machine_connection', {
  input: {
    label: 'build-box-01',
    host:  'build-box-01.lab',
    port:  22,
    username: 'sam',
    signIn: { method: 'agent' },
  },
})

// Second call: confirm the fp.
codesense.invoke('test_machine_connection', {
  input: { /* same */, trustedHostKeyFp: 'SHA256:…' },
  machineId: 'build-box-01-ab12cd',   // if already saved
})

// Save the declaration (public).
codesense.invoke('save_machine', {
  label: 'build-box-01',
  host:  'build-box-01.lab',
  port:  22,
  share: 'personal',   // or { team: 'ops' }
})

Already use Ansible?

Keep it. /setup-machine is the plain-shell version for teams that don't. The skill can also turn what it did into a playbook if you ask. The important bit for CodeSense is that test_machine_connection ends green and the machine is saved.
