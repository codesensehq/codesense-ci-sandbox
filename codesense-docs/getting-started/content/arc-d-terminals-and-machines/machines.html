What CodeSense means by a machine

A machine is somewhere a CodeSense terminal can run. Your Mac is one. A Linux build box over SSH is another. A machine shows up in the Machines list once you (or a teammate) have declared it. Everyone picks it from the same list; everyone signs in as themselves.

Load, memory and free disk

Each connected machine, including This Mac, reports a plain line in the Machines tab:

Load 38% of 8 cores · Memory 12.1 / 16 GB · 84 GB free of 460 GB · reported 14:32

Load is the one-minute load average divided by the logical core count (it can exceed 100%). Memory used is total minus available memory. Disk is the volume holding the terminal server's workspace directory. Hover over the line for the reporting machine, sample time and disk path. GB uses decimal bytes.

These figures are self-reported observations, not reserved capacity. CodeSense adds no thresholds or placement decisions. An operation that needs disk space still checks it again. Disconnected machines show no line. An older server says “Load, memory and disk unknown · update the terminal server”.

The server samples every 30 seconds only while a Machines view subscribes. Hiding or closing the view releases its subscription; returning catches up from a snapshot and live changes through the shared machineStats LiveHub topic. Samples stay in local runtime memory and never sync.

Agents use list_machines {orgSlug, team?}. Dashboard authors use await codesense.machines() for the same optional fields: load1, cpuCount, memUsedBytes, memTotalBytes, diskFreeBytes, diskTotalBytes, diskPath and sampledAt (Unix epoch milliseconds on the server). MCP reads reuse a sample under 30 seconds old or request one fresh sample; they do not leave a watcher running. machineStatsSupported: false identifies an old server.

const machines = await codesense.machines();
for (const machine of machines) {
  if (machine.diskFreeBytes !== undefined) {
    console.log(machine.label, machine.diskFreeBytes / 1e9, 'GB free', machine.diskPath);
  }
}

Two records per machine

CodeSense splits every machine into two records so a teammate can share "where it is" without ever handing out "how to log in":

  • Declaration — public: label, host, port, pinned host key, default base dir. Lives either in your personal layer (just you see it) or in a team's config/ (every teammate sees it after sync). Never carries a user name, key, or password.
  • Binding — personal: your Unix username on that box, your private key file, your keychain handle, whether you've hidden it. Lives in your own directory. Never syncs anywhere.

That split is the whole reason "my teammate shared the build box with me" doesn't mean "my teammate handed me their key". Each person binds the shared declaration to their own account on the machine.

Kinds

  1. This Mac — the machine CodeSense is running on. It owns your account directory and runs the host-agent. You never add it; it's always present.
  2. Remote — any other host reachable over SSH. You add it once, test it, and from then on it appears in the picker next to "this Mac". Linux is the common case; another Mac works too.

Two modes

Every remote machine runs in one of two modes:

  • Private-account recommended — you have your own Unix account on the box. Your files, your agent CLI logins, your terminal server identity. Teammates on the same box have theirs. This is the mode CodeSense is built around: parity with local comes from this mode. See Remote (private account).
  • Read-only (shared account) narrow use — multiple teammates work as the same Unix user. Everyone can see and change each other's files. Fine for a CI box or a classroom demo; not what you want for day-to-day work. CodeSense still works, but per-user state (agent logins, keychain handles) is a shared concern on that account.

The add-machine-user page walks the choice. The /add-machine-user skill recommends "own account" by default.

Where they live on disk

Short tour of the files, in case you're spelunking:

  • Personal declaration — ~/.codesense/users/<principal>/machines.d/<id>.yaml
  • Team declaration — <team-content>/config/machines.d/<id>.yaml (shared through the context repo's git like everything else in the team layer).
  • Your bindings — ~/.codesense/users/<principal>/machine-bindings.json. Never syncs; never leaves your Mac.
  • Private-account state (v1) — ~/.codesense/users/<principal>/machines-private-v1.d/<id>.yaml plus machine-private-bindings-v1.json for the per-account uid, canonical home, and enrollment id. Also never synced.

List every machine you (or your team) have declared, with mode and setup state.

How to do this via MCP 
// List
codesense.invoke('list_machines', {})

// Save a new remote machine (public declaration)
codesense.invoke('save_machine', {
  label: 'build-box-01',
  host: 'build-box-01.lab',
  port: 22,
  share: 'personal',          // or { team: 'ops' }
})
