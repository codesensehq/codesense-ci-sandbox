This Mac — the terminal you already know

Your Mac is where CodeSense starts. The app runs here, your local workspace and your ~/.codesense folder live here, and the fastest workflows happen here: terminals are native PTYs, files are watched with fsevents, and the keychain is right there. Everything you learn on the local machine translates to remote with one or two caveats — enumerated in the parity matrix.

Anatomy of a local terminal tab

  1. You open a tab — ⌘T or Workspace → New terminal, or open_terminal_tab over MCP. The tab is scoped to the current workspace: its cwd is the workspace's hydrated worktree.
  2. CodeSense forks a native PTY — your login shell, in that cwd, with the environment you'd expect (PATH, HOME, SHELL). No SSH involved.
  3. You type, run agents, read scrollback — plain shell. claude and codex work exactly as they would in Terminal.app, except CodeSense's MCP server is wired in so agents can see your context repo.
  4. Scrollback is captured — the emulator keeps a bounded scrollback so read_terminal_tab can snapshot it for an agent without re-running anything.

The host-agent

The host-agent is a background process that runs on the Mac you run CodeSense on. It brokers resources no other process can — notably, exposing CodeSense's MCP server to agent CLIs you launch yourself in your own Terminal.app, and holding the file watchers for your context repos.

Two things to know about it:

  • There is exactly one. It lives alongside your profile directory. It never runs on a remote machine — remote work gets its parity from the terminal server (next page), not from a second host-agent.
  • If it's wedged, quit CodeSense and relaunch it first. If that doesn't help, Restart terminal server (or restart_terminal_server) starts it fresh, and it ends every terminal and agent running on it.

What's special about the Mac you run CodeSense on

The Mac that runs CodeSense owns your profile directory (~/.codesense/users/<principal>/). It holds:

  • Your machine bindings (never synced).
  • Your issued passphrase handles (keychain-backed).
  • The worktrees CodeSense created for the context repos you've opened.
  • The sample source repo CodeSense ships with (one per profile).

If you move Macs, CodeSense's onboarding helps you re-create the profile and re-enroll your keys; your team's content syncs back down over the normal publish/pull path.

Try this now

Open a fresh terminal tab in your current workspace.

How to do this via MCP 
codesense.invoke('open_terminal_tab', {
  requestId: crypto.randomUUID(),
  workspaceId: '<current workspace>',
  launch: 'shell',   // or 'claude' / 'codex' / an agentKey
  headed: true,
})

Omit machineId and the tab opens on this Mac. Supply a machineId and it goes remote — same shape, different host.
