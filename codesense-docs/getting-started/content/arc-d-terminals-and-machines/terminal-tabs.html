Tabs: open, hidden, resumed

A terminal tab is a workspace-scoped shell with scrollback the UI can read. It's the surface agents live in, the surface you type into, and — because of how PTYs are owned — a surface that outlives the app itself. This page is the full lifecycle: creation, hiding, quitting, resume, closing.

Lifecycle

  1. Open — you ask for a new tab (⌘T, UI, or open_terminal_tab / open_remote_tab). CodeSense allocates a tab id, spawns the PTY in your login shell (zsh, bash or fish), and streams scrollback from frame 0. PTYs are children of the terminal server (codesense-session-server): on this Mac, a process separate from the app; on a remote machine, one in your account there.
  2. Active — the tab is in the workspace tab-strip. You type; agents type back. read_terminal_tab snapshots scrollback for agents without disturbing the live stream. run_in_terminal_tab types + submits a line (or sends a single key).
  3. Hidden — you can hide a tab from the strip without closing it. It keeps running and is listed under its tile's chip in the tray as Hidden tabs; one click restores it.
  4. Dormant (CodeSense quit) — the UI is gone but the PTYs keep running in the terminal server, so agents carry on working. A remote machine's tabs also keep running while your Mac sleeps.
  5. Resume — re-open CodeSense (or wake the Mac). CodeSense reconnects to each terminal server, and the UI shows each tab as it was, plus anything that scrolled by while you were gone.
  6. Close — ⌘W or the × on the pill hides the tab when a command is running in it and ends it when it's idle, asking first if background jobs would die with it. End terminates the PTY and its scrollback is gone. ⌘⇧T reopens the last closed tab: a hidden one on its live session, an ended one as a fresh shell in the same place.

Local vs remote tabs

The shape of a tab is identical. The owning process differs:

  • Local — PTY under the terminal server on this Mac. Survives CodeSense quit. Does not survive restarting your Mac or stopping the terminal server. If the terminal server can't start, new terminals run inside the app and close when you quit it.
  • Remote — PTY under the terminal server on the remote account. Survives CodeSense quit, your Mac sleeping, your Mac rebooting, and your Wi-Fi dropping out. Does not survive the remote machine rebooting or the terminal server being updated or restarted (after either, CodeSense reopens the machine's tabs as fresh shells, and relaunches Agents with resumeAfterRestart).

Scrollback contract

Scrollback is bounded by the emulator (Terminal scrollback in Settings → General: 5,000 lines by default). When an agent calls read_terminal_tab, CodeSense returns the current snapshot:

  • Normal shell — plain text lines, including scrollback up to the limit.
  • Full-screen TUI (Claude Code, Codex, top) — the emulator renders the alt-screen and returns the rendered frame rather than the raw overlapping redraws. The agent sees what you see.
  • Remote — every read returns the full text; there is no delta protocol. Reads are cheap enough to make this the honest shape.

Addressing tabs

Every MCP tool that touches a tab accepts two addressing modes:

  • {handle} — the opaque handle returned by open_terminal_tab / open_remote_tab / open_workspace / list_sessions. Preferred for automation.
  • {tab} — the tab's current name (editable in the UI, visible in list_sessions) with optional {machine} / {workspace} qualifiers to disambiguate. Ambiguous names return the candidate set instead of guessing.

Hidden tabs

Hiding a tab is a UX-only idea: the PTY keeps running, scrollback keeps accumulating, agents keep working, and the tile's chip in the tray lists them under Hidden tabs; one click restores a tab. Agents don't need the tab visible to drive it; hidden tabs still answer run_in_terminal_tab and read_terminal_tab.

Try this now

See the current tab inventory across every workspace and every machine.

How to do this via MCP 
// Inventory.
list_sessions {}

// Snapshot a tab's scrollback.
read_terminal_tab {
  tab: 'Machine setup',   // or { handle: '…' }
  view: 'scrollback',     // 'screen' for a live alt-screen frame
}

// Type into a tab.
run_in_terminal_tab {
  tab: 'Machine setup',
  command: '/setup-machine',
}
