Arc B · The model

Orgs, teams, and the team chain.

One org is one context repo. A repo holds teams, and a team can name one parent_team. A team's context is its own content plus the files its parents share (their config/sharing.yml), resolved per file: the closest team wins. Nothing copies itself anywhere. Content reaches a worktree only when the worktree is created, when an agent launches there (it gets what its context asks for), or when an agent explicitly asks for more. This arc teaches the model with pictures and a worked example, and leaves the schemas to the schema browser.

This is the shape; the live arc-b-model.excalidraw canvas has the editable version.

The model at a glance

When an agent launches in a worktree, every file it gets comes from one of these places. CodeSense checks them in this order for each file and takes the first one that has it. Folders are never owned by a team: the same folder can hold files from several places, and they are merged.

# Place Lives at Who sees it
1 Repo content <org>/<team>/repos/<host>/<owner>/<repo>/content/ The team itself (child teams don't inherit it), and only in that repo. Wins over everything below for a launch there.
2 Private ~/.codesense/users/<you>/scratch/orgs/<org>/, plus scratch/all-orgs/ for inert items Only you. Never pushed.
3 Team content <org>/<team>/content/ The team and every child team. Pushed and pulled with the org's git remote: the shared-truth layer.
4 Parent teams <org>/<parent>/content/, then its parent, up the chain Every team below them, for the files the parent shares in config/sharing.yml (for example share: ['content/**']; see Teams). With no file, a parent shares nothing. A child team inherits each shared file it doesn't hold itself.

Which paths a launch asks for is up to the agent. Its context list (or, without one, its runtime's default, such as CLAUDE.md and .claude/skills for Claude) names the folders and files; a per-repo override can add or remove some for one repo. At launch CodeSense works out the difference from what the worktree already has, copies the missing files (and newer versions of ones it copied before) in one batch, and adds them to the clone's .git/info/exclude so they stay out of your commits. It never overwrites a file the repo tracks or a copy you edited. An agent launched in a team workspace defaults to .claude/commands and .claude/skills; its files are staged into a separate worker folder that isn't a git repo, so it gets no git exclude. After that nothing moves on its own: an agent calls hydrate_worktree or hydrate_story to pull more in, and reverse_sync_worktree or route_file_to_context to send an edit back. If you want that as a routine, you write your own sync skill.

// → { activeOrg, activeTeam, orgs: [{ slug, displayName, teams: [{ name, parent?, … }] }], … }
