Arc B · Worked example

Three teams, one launch, one explanation.

Everything in this arc, concrete. We follow the shipped sample epic DEMO across a three-team chain, put one file in each place, launch one agent, and then edit an inherited file. For each file we spell out where it lives, who sees it, whether it gets pushed, and whether the launch copies it. If a page in this arc hasn't clicked yet, read this one.

The setup

Imagine your org is acme/codesense and teams.yml declares three teams in a chain: default is where you work day-to-day; platform holds skills shared across products; root is the top of the chain and holds the house style guide and the lint rules every team honors. 

# teams.yml, at the root of the org's context repo
teams:
  - name: default
    source_repos:
      - owner: acme
        repo: sample-source-repo
        provider: git
        host: example.invalid
    parent_team: platform
  - name: platform
    parent_team: root
  - name: root

The active team is default, so its chain is [default, platform, root]: default's context is its own content plus platform's plus root's, decided file by file. The source repo acme/sample-source-repo (the bundled sample) is bound to default.

One file in each place

Paths below are relative to the org's context repo (the folder you cloned or created and connected in CodeSense), unless they start with ~.

Repo content The dag-kill lint

default/repos/example.invalid/acme/sample-source-repo/content/.claude/skills/dag-kill-lint/SKILL.md

A lint skill that only makes sense inside sample-source-repo: it refuses a kill-switch PR that doesn't call the new host primitive. It lives in default's repo content for that repo.

Who sees it: default, and only for launches in acme/sample-source-repo. Pushed: yes, it's in the context repo.

Private Your DEMO prototype skill

~/.codesense/users/<you>/scratch/orgs/acme/codesense/content/.claude/skills/fake-killswitch-draft/SKILL.md

A prototype skill that drives the DEMO kill switch end to end. You're iterating on it before offering it to the team.

Who sees it: only you, only in the acme/codesense org. Pushed: never.

All-orgs Your “explain this diff” prompt

~/.codesense/users/<you>/scratch/all-orgs/prompts/explain-this-diff.md

A prompt you've honed and want in every org. It's an inert kind (a prompt), so All-orgs accepts it; an agent manifest here would be refused.

Who sees it: only you, in every org you open. Pushed: never.

Team content · default Default's review checklist

default/content/.claude/skills/review/SKILL.md

default's own review skill. platform has a skill at the same path; this one is closer, so it wins for default.

Who sees it: everyone on default and any team below it. Pushed: yes, via the org remote.

Parent team · platform Platform's deploy and review skills

platform/content/.claude/skills/deploy/SKILL.md
platform/content/.claude/skills/review/SKILL.md

Skills platform shares with every product team through its config/sharing.yml, which also shares the root's content/CLAUDE.md onward. default holds no deploy skill, so it inherits platform's. It does hold its own review, so platform's review is hidden for default only.

Who sees it: everyone on platform, and every child team for each shared file the child doesn't hold itself. Pushed: yes.

Parent team · root The house rules

root/content/CLAUDE.md

The top of the chain holds the instructions every team honors, and shares content/CLAUDE.md in its config/sharing.yml. Neither default nor platform has a CLAUDE.md, so both inherit this one.

Who sees it: every team in the org, as long as each team in between shares it onward. Pushed: yes.

One launch, file by file

Now launch a Claude agent called reviewer on default, in a worktree of acme/sample-source-repo. Its definition asks for two things: 

# default/config/agents/reviewer/agent.yaml (excerpt)
runtime: claude
context:
  - CLAUDE.md
  - .claude/skills

CodeSense resolves each file under those paths through the stack (repo content, private, all-orgs, default, platform, root) and takes the closest copy: 

CLAUDE.md                               ← root      (no closer team has one;
                                                     kept as is if the repo tracks its own)
.claude/skills/dag-kill-lint/SKILL.md   ← repo content for sample-source-repo
.claude/skills/fake-killswitch-draft/…  ← your private space
.claude/skills/review/SKILL.md          ← default   (platform's copy is shadowed)
.claude/skills/deploy/SKILL.md          ← platform  (inherited)

not copied: prompts/explain-this-diff.md
            (the agent's context doesn't ask for prompts/)

CodeSense compares that list with what the worktree already holds, copies the missing files (and newer versions of ones it copied before) in one batch, and adds them to the clone's .git/info/exclude. It never overwrites a file the repo tracks or a copy you edited: if sample-source-repo commits its own CLAUDE.md, that one stays and the launch report lists root's as skipped. The same agent launched in another repo would get everything except the dag-kill lint.

After the launch

  • A teammate improves platform's deploy skill. The running worktree keeps the copy it got. Nothing updates in the background; when the agent wants the new version it calls hydrate_worktree for .claude/skills.
  • The agent fixes a typo in its copy of the review skill. That edit stays in the worktree until the agent previews it with preview_reverse_sync_worktree and publishes it with reverse_sync_worktree, which writes it back to default's file.
  • You open default in the left nav and edit deploy/SKILL.md. It's marked as inherited from platform, and the viewer says: "This file comes from platform. Changes you make here update it for platform and every team that inherits from it." Save, and every product team sees the change.
  • You want a deploy skill for default only. Choose Copy into default on the file. The copy lands in default/content/.claude/skills/deploy/, it's now the closest, and the next launch (or hydrate) picks it up instead of platform's.

How to do this via MCP

To walk the chain shown above from an agent: 

// describe_setup {} → { data: { activeOrg, activeTeam, orgs: [...] } }
const { activeOrg, activeTeam, orgs } = setup.data
const org = orgs.find(o => o.slug === activeOrg)
const chain = []
let t = activeTeam
while (t) {
  chain.push(t)
  t = org.teams.find(x => x.name === t)?.parent
}
// chain === ['default', 'platform', 'root']

The seed data this page cites ships with CodeSense; the sample repo lands under ~/.codesense/users/<id>/sample-source-repo/ when CodeSense launches.
