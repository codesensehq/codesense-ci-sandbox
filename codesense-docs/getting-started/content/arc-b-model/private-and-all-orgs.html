Arc B · Private & All-orgs

Only you — scoped to one org or carried everywhere.

Two layers belong to you alone. The Private space is per-org: a place to try things, keep shortcuts, or stash notes for one org without shipping anything to teammates. The All-orgs folder is cross-org: the one place that resolves identically in every org you open, limited to inert items on purpose. Both are local-only and never pushed.

Side by side

Private · per org

~/.codesense/users/<you>/scratch/orgs/<org>/

Shaped exactly like a team dir — content/, config/, notes/, libraries/, panes/. Anything you file here appears when this org is active and vanishes when you switch orgs. The resolver overlays it at the head of this team's resolution chain, so a private file wins over the team's at the same logical path.

Who sees it: only you, only in this org.

Synced? Never. CodeSense initializes a local git repo under scratch/ for history but never adds a remote.

Accepts: any kind — agents, routines, skills, notes, panes, canvas libraries.

All-orgs · carry everywhere

~/.codesense/users/<you>/scratch/all-orgs/

A tiny folder that resolves in every org you open. Reserved for items that don't carry org-specific state: a skill you want in both your work and side-project orgs, a prompt you reuse everywhere, a snippet, a template.

Who sees it: only you, in every org you open.

Synced? Never — it's part of the same local scratch repo as Private.

Accepts: inert kinds only. CodeSense refuses to file an agent or routine here and points you at the per-org Private space instead: "cannot go in all-orgs: only skills, prompts, snippets and templates apply in every org."

How they overlay the team chain

When an agent launches, each file its context asks for is looked up in this order, and the closest copy wins:

  1. Your team's content for that repo (repos/<host>/<owner>/<repo>/content/), for a launch in that repo.
  2. Your Private content for this org.
  3. The All-orgs folder (next, but only for inert kinds).
  4. Your active team's own content.
  5. Each parent team in order, up to the chain depth cap.

The practical result: file a personal override for one org under Private and only you see it; file an inert skill under All-orgs and you carry it to every org on your machine. If a Private file and an All-orgs file name the same logical path, Private wins — "closer to home" is the whole rule.

Two exceptions let the team win. Switch off Use my private items in ‹Team› in the team switcher and that team takes no private or all-orgs files at all. Or, on a single private file that replaces a team file, choose Use team's and that one path comes from the team again.

Promoting a private file to the team

A common move: you prototyped a skill in your Private space, it earned its keep, now you want everyone on the team to pick it up on their next pull.

  1. Find the file in Private (the button in the title bar), or on its From private badge in a worktree's file tree.
  2. From its ⋯ menu (or right-click in the file tree), choose Share with ‹Team›…. CodeSense moves it to the same place in <team>/content/, asking first only if the team already has a file there. Nothing is committed.
  3. The file is now a change in the team's context repo. Commit and push it, or ask an agent to: CodeSense never commits, pushes or merges for you (see agent-driven git). Teammates get it on their next pull.

The same menu has Copy to another org…, Use in all orgs (inert kinds only), Only this org for an All-orgs item, and Remove…. For the inverse, a team file's ⋯ menu in the left nav offers Move to… and Copy to…, and Private is one of the places it can go.

How to do this via MCP

describe_setup reports your private space next to the orgs: 

describe_setup {}
// → data.scratch: {
//     orgs: [{ counts: { notes, overlayFiles, panes, routines, agents }, offTeams, … }],
//     allOrgs: { skills, prompts, snippets, templates, notApplied },
//   }

In an agent_preview result, files from these roots are tagged with the personal tier rather than a team.
