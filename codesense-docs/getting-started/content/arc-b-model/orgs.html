Arc B · Orgs

One org is one context repo.

Everything a team shares — teams, agents, routines, the list of source repos, the whole shared-truth tree — lives in a single git repo on disk, with a slug, a display name, and an org.yml at its root. One org is one context repo, every time.

Slug conventions

The slug is the org's identity. It is written in the context repo's org.yml and keys every team, agent and private file in the org. The folder's name doesn't matter: CodeSense reads the identity from org.yml.

  • Format: a bare name such as ledgerline, or <owner>/<repo>.
  • Allowed: one or two safe path segments, so no spaces, .. or empty parts. The bare names builtin, local and _personal are reserved.
  • Fixed: renaming the workspace changes its display_name, never the slug. Every agent, routine and private file keyed by the slug would have to move, so choose it once.
  • One per slug: connecting a second folder that claims an org you already have fails without replacing the first.

What org.yml declares

One org.yml sits at the root of every context repo. It declares the slug, display name and creation time, plus two optional blocks. Unknown keys are ignored, so an older file still loads.

slugrequired
The org's identity (see above).
display_namerequired
Human-readable label shown in the workspace switcher.
created_atrequired
ISO-8601. Set when the org is created.
config_flags.workspace_root_dir
Where clones that CodeSense manages for this org go. Defaults to ~/.codesense/users/<id>/sources/.
tag_schema
Team-defined tag registry. Leave it out for the unopinionated default.

Teams live in teams.yml and members in people.yml, beside org.yml.

What an org looks like on disk

An org is a plain git working tree: its context repo, in whatever folder you cloned or created it. CodeSense doesn't clone it for you; it records where the folder is in ~/.codesense/users/<you>/context-attachments.yml. It looks like this — the default team is the usual starter team, and each team's files live in a folder named after it. 

~/code/team-context/       ← wherever you cloned or created it
├── org.yml              ← slug, display_name, created_at, …
├── teams.yml            ← one entry per team; parent chain declared here
├── default/
│   ├── content/         ← team content (shared truth)
│   ├── config/agents/   ← the team's agents, each with its context list
│   └── repos/
│       └── github.com/acme/codesense/content/
│                        ← repo content: only for launches in that repo
├── platform/            ← a parent team, same shape
└── .git/

Your private files for this org live outside the repo entirely, in a folder under ~/.codesense/ on this Mac. They are never pushed. None of these folders is copied anywhere on its own: an agent's launch copies what its context asks for, and the content layers page has the order. The Private & All-orgs page spells out which kinds of items belong there.

How to do this via MCP

Agents walk the same shape:

list_orgs_teams (no arguments) returns one { org, team, synced } entry for each team synced on this Mac. Use that org and team as the optional arguments of any team-scoped tool. list_context_attachments lists the connected context repos and where each one is.
