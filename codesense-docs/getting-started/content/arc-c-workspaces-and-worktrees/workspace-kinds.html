Arc C · Workspace kinds

Four kinds, one open call

A workspace is anything you can open_workspace against. CodeSense ships four kinds. Three of them — story, epic, team — are tied to a context repo. The fourth is just a managed dir. Each one gets its own tab, its own name, and the same lifecycle (open · live · hidden · closed). What differs is what sits on disk when the tab lands.

The four kinds

Story

A worktree per story

The headline kind. Opens into a real git worktree bound to the story's branch, hydrated with the story's docs. One per story, forever (until merge-teardown).

handle story_id
on disk ../<repo>-wt/<slug>/ (beside the clone)
git real worktree, feature branch
source story's source_repo
Epic

Plan + integration view

A synthetic workspace holding the epic's docs plus the epic-wide integration worktree. One per epic. Not a git clone itself — the integration view mounts each epic repo's integration branch inside the workspace.

handle epic path
slug _epic/{epic_id}
on disk ~/CodeSense/<team>/_epic/<id>/
git synthetic — mounts integration branches
Team

The whole team view

The team's editable context repo opened as a workspace. Where you edit agents, routines, docs, panes. One per team per Mac. No per-session worktree — everything lives in the team's content root.

handle team key (org/team)
on disk ~/CodeSense/<team>/content/
git the context repo's own clone
agents run in _worker/ under the user dir
Generic

A managed dir

You picked a path and gave it a name. CodeSense tracks the handle so your terminal tabs and agent sessions bind to it; no git, no hydration. Useful for ad-hoc work and sprint-triage tabs.

handle whatever you named it
on disk wherever you pointed it
git none (CodeSense doesn't touch it)
typical `sprint-triage`, `notes`

How to tell them apart

In the UI

  • Story workspaces show the story id in the tab title and a branch pill underneath (feat/demo-1).
  • Epic workspaces show the epic name plus a small plan glyph. No branch pill — there's no single branch.
  • Team workspaces show the team name and a tiny content-repo dot. Opening agents from a team workspace routes them to the user's _worker/ dir under the team.
  • Generic workspaces show the handle you gave it and no context-repo badge.

In the slug

Every synthetic workspace is encoded as a reserved slug that can never collide with a real GitHub owner (GitHub owners can't contain _): 

# A real source repo
acme/sample-source-repo

# An epic workspace — synthetic
_epic/per-agent-kill-switch

The leading _ is the tell. Story and team workspaces reuse the underlying context repo's slug and story / team id; generic workspaces use the handle you supplied.

Which kind do you want?

  1. Writing code against a story? Open the story workspace. It creates the worktree; the agent you launch there gets its declared context, and story docs arrive when an agent calls hydrate_story.
  2. Planning or triaging an epic? Open the epic workspace. All five sibling stories are visible; the integration view mounts their shared branches.
  3. Editing team instructions, agents, routines, docs? Open the team workspace. Edits land directly in your team's content repo.
  4. Working on something that isn't tracked by CodeSense yet? Open a generic workspace for the dir. Add terminal tabs; promote to a story workspace later when the work gets a story id.

How to do this via MCP

One tool, four kinds of target

open_workspace opens a story workspace from a story_id; with a target it launches an agent in a story or a team workspace. Agent launches settle with a typed status (opened · alreadyLive · busy · invalid). 

// Story — creates the worktree if it doesn't exist yet
codesense.invoke('open_workspace', { story_id: 'DEMO-1' })
// → { handle, mode, headed, reconciled }

// Launch an agent in that story's worktree, in a new tab
codesense.invoke('open_workspace', { target: 'story', story_id: 'DEMO-1', name: 'review', agent: 'reviewer' })

// Launch an agent in a team workspace
codesense.invoke('open_workspace', { target: 'team-workspace', name: 'sprint-triage' })
