Workspace and tab lifecycle tools

Reference for the tools that open, read, drive, rename and close terminal tabs, close and rename workspaces, update a machine workspace's base, and manage custom workspace groups.

How to read this page

A tab is addressed by its opaque handle (from the open call or list_sessions), never by a raw session id. Several tools also accept the tab's current name as tab, narrowed by machine and workspace; a name that more than one tab has, or that no tab has, is refused with the tabs it could mean.

Workspace ids are viewer ids such as story:DEMO-13, root:... or generic:.... Team keys are written org:team.

Sessions and tabs

Tool calls that change a tab (open, type, close) are gated by the trusted-side Interactive tier.

list_sessions

Lists every session CodeSense is running, local and remote, as {sessions:[{handle, displayName, state, sessionId, effectiveStatus, launchedBy, unread, ...}]}. state is running, idle, needs-you, exited, offline or unknown. handle is how other tools address a session, and launchedBy is the launcher handle or null for a human launch. Optional launched_by filters to sessions that launcher started. Listing marks nothing read. The served description has the full row, including progress, launch telemetry and inbox fields.

{
  "tool": "list_sessions",
  "arguments": {
    "launched_by": "<launcher handle>"
  }
}

open_terminal_tab

Opens a normal terminal tab in an already-open workspace and returns {handle, headed, kind}. workspaceId is required and must be an open workspace. headed (default true) focuses the tab; false opens it quietly. name labels the tab (default Terminal <n>). The caller never learns the raw session id. For a tab on a machine use open_remote_tab.

{
  "tool": "open_terminal_tab",
  "arguments": {
    "workspaceId": "story:DEMO-13",
    "name": "build watch",
    "headed": false
  }
}

open_remote_tab

Creates or attaches a native remote terminal tab in an already-open workspace. Create needs operation: "create", a UUID requestId, a configured machineId, teamKey (org:team), workspaceId and an absolute existing host cwd; launch is shell (default), claude or codex. A saved Agent starts with agentKey plus preparedWorkspaceHandle from a verified prepared worktree. permissionMode: "bypass" applies only to raw claude/codex launches and needs an updated terminal server (otherwise terminalServerOutdated). Attach needs operation: "attach" with exactly one of handle or requestId; retry an unknown Create only with Attach, never with a new requestId. Opening the CLI does not prove authenticated inference.

{
  "tool": "open_remote_tab",
  "arguments": {
    "operation": "create",
    "requestId": "6f1c2e0a-8f55-4a3e-9d57-0b6a1b0f6c11",
    "machineId": "<machineId from list_machines>",
    "teamKey": "acme:engineering",
    "workspaceId": "story:DEMO-13",
    "cwd": "/home/dev/worktrees/app-example",
    "launch": "shell"
  }
}

read_terminal_tab

Reads a tab's current scrollback as a one-shot snapshot, not a live subscription. Address it by handle, or by tab plus optional machine and workspace. Local tabs return {output, altScreen}; remote tabs return {status:"ok", output, head, reset, altScreen} and every remote read returns the full text (reset is always true). view is scrollback (default) or screen, the current frame of a redraw-in-place program.

{
  "tool": "read_terminal_tab",
  "arguments": {
    "handle": "<handle from open_terminal_tab or list_sessions>",
    "view": "scrollback"
  }
}

run_in_terminal_tab

Types input into a tab and submits it, or presses one key. Give exactly one of command or key. At a shell prompt a command runs as a shell command; when Claude or Codex is running in the tab it is sent as a prompt, then Enter as a separate keystroke. key is one of enter, escape, tab, shift-tab, backspace, ctrl-c, ctrl-d, up, down, left, right. A local tab returns {submitted, input?}; a remote tab returns {status: submitted|notSent|unknown|refused, ...}, where unknown means the input may have been submitted: check with read_terminal_tab and never resend automatically.

{
  "tool": "run_in_terminal_tab",
  "arguments": {
    "handle": "<handle from open_terminal_tab or list_sessions>",
    "command": "pnpm test"
  }
}

send_to_session

Sends a prompt to a running Claude or Codex session by handle. A raw session id, or a handle with no running session, is refused and nothing is written. text is non-empty and may be a slash command; it is typed into the input box and Enter is sent separately. Local returns {submitted} (false: the agent may not have started, so check read_terminal_tab). Remote returns a status of submitted, notSent, unknown or refused; never automatically resend after unknown. The text is also recorded in the target's inbox conversation as typed into the terminal and already read.

{
  "tool": "send_to_session",
  "arguments": {
    "handle": "<handle from open_terminal_tab or list_sessions>",
    "text": "Summarize your progress so far"
  }
}

rename_terminal_tab

Renames a tab as a person would from its tab bar; the new name shows at once and in list_sessions. Address it by handle, or by current name tab narrowed by machine (its label, This Mac for this one) and workspace. name must be non-empty. A tab on a remote machine is renamed in that machine's layout. Returns {renamed:true, name, machine, workspace, handle?}.

{
  "tool": "rename_terminal_tab",
  "arguments": {
    "handle": "<handle from open_terminal_tab or list_sessions>",
    "name": "claude: triage"
  }
}

close_terminal_tab

Closes a tab opened with open_terminal_tab or open_remote_tab; local and remote alike. Takes the opaque handle only (a raw session id is refused). It ends the CLI if one runs, closes the tab and drops it from list_sessions, and never removes the worktree or its files, even for the last tab. Idempotent: a session already gone returns {closed:true, alreadyClosed:true}; an unknown handle returns {closed:false, reason:"unknownHandle"}; a session closing its own tab is refused with reason:"selfClose".

{
  "tool": "close_terminal_tab",
  "arguments": {
    "handle": "<handle from open_terminal_tab or list_sessions>"
  }
}

Workspaces

close_workspace

Ends every live terminal session in a workspace, on every machine that holds it, and removes its pill from the workspace tray. Address it by story_id or by the raw viewer workspace_id. It keeps files: the worktree, its files and git registration are never removed. discardUnsaved is always refused (discardUnsavedRefused) and machine_id is accepted but ignored. Other refusals: selfClose, ambiguousWorkspace (a bare story_id live in more than one team), unknownWorkspace and tabsNotClosed. Idempotent. It does not archive the agent definition (agent_delete does) or touch chat history or documents.

{
  "tool": "close_workspace",
  "arguments": {
    "story_id": "DEMO-13"
  }
}

rename_workspace

Sets the org's display name, the same edit as the UI's workspace rename. Pass org (owner/repo; the slug does not change) and name. An empty name returns {status:"validation", message}; success returns {status:"ok", data:{orgSlug, edit:"RenameWorkspace"}}.

{
  "tool": "rename_workspace",
  "arguments": {
    "org": "acme/context",
    "name": "Acme context"
  }
}

update_workspace_base

Moves a machine workspace to the newest commit of its base, where newest means what baseRef names in your attached local clone now (fetch or pull there first for the provider's latest). Name it by machineId + workspaceHandle, or by storyId / workspaceId of an open workspace (add teamKey if several teams match). Only commits the machine lacks are sent. The worktree fast-forwards only when it is clean and its branch has no commits of its own; otherwise it is refused (refusedDirty, refusedDiverged, or refusedManagedOverlap when the new base tracks files that already exist there). removeManagedCopies: true deletes the unedited CodeSense copies in the overlap and replaces them with the repo's versions; edited copies and other files are never removed. Returns status, previousCommit, commit and bundleBytes. Reopening a workspace never updates its base.

{
  "tool": "update_workspace_base",
  "arguments": {
    "machineId": "<machineId from list_machines>",
    "workspaceHandle": "<workspaceHandle from the workspace record>"
  }
}

list_move_intents

Lists open move_workspace intents for the active principal: [{teamKey, workspaceId, from, to, step, dirtyAllowed, startedAtMs, lastProgressAtMs}], empty when no move is in flight. The app calls it on load so a restart mid-move keeps the moving state. Read-only. To start a move, see move_workspace.

{
  "tool": "list_move_intents",
  "arguments": {}
}

Custom workspace groups

Personal groups of workspaces. teamKey (org:team) defaults to the active team on every group tool, and every group tool returns {status:"ok", ...} with the resulting groups, or {status:"validation", message}. A workspace is named by workspaceId or storyId; the plural forms take lists.

workspace_group_list

Lists the personal custom workspace groups, including empty groups.

{
  "tool": "workspace_group_list",
  "arguments": {
    "teamKey": "acme:engineering"
  }
}

workspace_group_create

Creates a named custom group. Names must be unique within the team, are trimmed, and are at most 80 characters. workspaceIds or storyIds optionally seed its members.

{
  "tool": "workspace_group_create",
  "arguments": {
    "teamKey": "acme:engineering",
    "name": "Docs",
    "storyIds": [
      "DEMO-13"
    ]
  }
}

workspace_group_rename

Renames a custom group by groupId.

{
  "tool": "workspace_group_rename",
  "arguments": {
    "teamKey": "acme:engineering",
    "groupId": "<groupId from workspace_group_list>",
    "name": "Docs wave"
  }
}

workspace_group_delete

Deletes a custom group by groupId. Its workspaces stay open and return to their epic groups.

{
  "tool": "workspace_group_delete",
  "arguments": {
    "teamKey": "acme:engineering",
    "groupId": "<groupId from workspace_group_list>"
  }
}

workspace_group_add

Adds a workspace to a group by groupId. It applies to current membership atomically, moves the workspace out of any other custom group, and preserves the other members.

{
  "tool": "workspace_group_add",
  "arguments": {
    "teamKey": "acme:engineering",
    "groupId": "<groupId from workspace_group_list>",
    "storyId": "DEMO-13"
  }
}

workspace_group_remove

Removes a workspace from a group by groupId. Other members, including closed workspaces, and the group itself remain, even if it is now empty.

{
  "tool": "workspace_group_remove",
  "arguments": {
    "teamKey": "acme:engineering",
    "groupId": "<groupId from workspace_group_list>",
    "storyId": "DEMO-13"
  }
}

workspace_group_set_members

Replaces a group's membership with the given workspaceIds or storyIds. Membership moves from other custom groups, empty groups remain, and roots cannot join.

{
  "tool": "workspace_group_set_members",
  "arguments": {
    "teamKey": "acme:engineering",
    "groupId": "<groupId from workspace_group_list>",
    "storyIds": [
      "DEMO-13",
      "DEMO-12"
    ]
  }
}
