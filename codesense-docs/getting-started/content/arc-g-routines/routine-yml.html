Arc G · Routines

routine.yml — every model field

A routine saves either an agent task or an argv command. An agent routine lives at config/agents/<agent-id>/routines/<id>/routine.yml; the path supplies its agent. Command routines live under config/agents/_command/routines/<id>/routine.yml.

The table below is generated from RoutineDef and its nested serde models. Open the standalone JSON Schema or schema browser. The schema describes accepted wire shapes; save-time validation also checks schedules, agents, placement, limits and combinations. Flattened fields are preserved. Some are supported runner extensions, including policy.max_wait; other unknown fields have no guaranteed behavior.

Also available: Agent schema and role configuration schema.

Author a definition

Give every routine a unique team-wide id, nonblank name and owner, where.kind and policy.max_runtime (1m–24h). Start revision at 1; saves increment it. A field default in the wire schema does not imply the resulting definition passes semantic validation.

  • action: agent is the default. Give it a nonblank task. Usually omit agent because its directory supplies it. Legacy and unassigned files can carry a bare or scoped agent reference.
  • mode: wake delivers into a matching idle saved agent's session and starts one only if none matches. On this Mac, the session must carry this routine's launch identity. fresh starts a new session. A blank mode is resolved at fire time; read effective_mode in the tool reply. Built-in starters are fresh only. Bypass agents need allowWake: true.
  • action: command needs command as argv, and no agent, task or mode. Commands run on this Mac, without a model. See command routines.
  • where.kind is team_workspace or repo:owner/repo. where.machine is local, any, or a machine id for agent routines. runs_on defaults to one_mac; each_mac is a per-Mac opt-in recipe. Metadata triggers refuse each_mac.
  • triggers contains singleton schedule or event maps. Empty means manual. after: {routine: review-command, on: succeeded} adds a same-space dependency; finished continues after succeeded, failed, timed_out, needs_you or ended; cancelled does not fire a chain. See the six trigger recipes.
  • policy.overlap is coalesce, skip or queue (MCP command creation defaults to queue). policy.missed is skip or run_once. policy.visible opens a fresh agent in a tab; wakes are visible.
  • policy.max_wakes, max_wakes_per_day and min_gap limit deliveries into live sessions. Positive counts only; min_gap is 1m–7d. Reaching the total pauses the routine; daily limits recover automatically. Fresh runs ignore wake limits with a warning.
  • policy.max_wait is a supported wake-runner extension stored in the policy’s extra fields. It bounds how long a wake waits for an idle session: 30 minutes by default; use a positive duration such as 30m or 2h.
  • variables declares typed defaults (text, number, boolean); defaults are required for scheduled tasks. Scalar defaults accept strings, numbers and booleans and are retained as text. Use {{name}} in a task.
  • result_schema is a bounded inline JSON Schema for a structured private dashboard result. It is not a command exit-code schema. Use routine_publish_result in an agent run; dashboards can read the cached result.

armed_host, armed_machine, arm_epoch and handover_from track placement and disarm acknowledgements. Use routine_arm_on to move placement safely rather than editing those fields. archived_at, archived_with_agent and migrated record lifecycle/history. Keep them intact when editing.

Enabled state is a local Mac switch, outside routine.yml and git: saving or syncing a definition does not enable it on a teammate’s Mac. Use routine_set_enabled for pause/resume. Preserve placement when patching an MCP-created draft. A hand-installed one_mac definition without armed_host needs routine_arm_on {id, machine:"this_mac"} before enabling.

Role queue filters

Use {kind:"role_pending"} when a dispatcher needs every role queue in reach. Use {kind:"role_pending",role:"reviewer"} when this routine should run only for reviewer mail.

triggers:
  - event:
      kind: role_pending
      role: reviewer

Omit role for the wildcard. A team routine reaches only its team; a private routine reaches teams in its org. Empty or whitespace-only role values fail validation, and role is valid only on role_pending. Role names need no registry entry. agent_done alone accepts from_agent (id or full key, no existence check). MCP uses the same spelling inside events. Updating with null or omitted events preserves; [] clears these three event kinds; a nonempty list replaces them and keeps schedules/metadata triggers. Only creation supports dryRun, which reports resolved triggers and writes no definition.

Validate before enabling

routine_create {..., dryRun:true} runs the real create validation without saving. Read the envelope status; only ok is success. Then read data.warnings, effective_mode, next_fires and the selected agent. Create with enabled:false until ready. Read the saved definition with routine_get; use routine_update with its latest baseRevision.

The schema browser’s validateYaml page bridge is currently unavailable; its local shape check does not establish semantic validity. Use routine_create with events and dryRun:true for shared event validation; see the cookbook.

Policy: spend cap

A fresh agent routine may set policy.budget_usd, for example {per_day: 10, per_week: 40}. Both fields are optional positive finite USD. Its runs aggregate by routine handle across sessions and machines, and also count toward the agent's own cap. Either scope can refuse a fire with budget_reached.

A wake routine must cap its agent instead. Command routines cannot have a cap. Capped routines cannot be armed on a machine, and machine-armed routines cannot add a cap. Read Spend caps before changing a limit.

Context in a fresh team run

On this Mac, an agent routine targeting team_workspace starts in its own scratch directory for that routine and saved agent, outside shared team content. Before each new session, CodeSense clears that pair's scratch files and prepares the saved agent's current context and startup, including merge-marked workspace files such as team hooks in .claude/settings.json. Both visible and headless sessions receive these files. Save outputs you need to keep through the appropriate content or Notes tools; files left in the routine's working directory are temporary. Reassigning a routine to a different saved agent selects a different directory, preserving the previous agent's live files. Old per-agent directories remain; they are not automatically removed on reassignment. 

# In the saved agent's agent.yaml:
context:
  - path: skills/evaluate
    dest: .claude/skills/evaluate

# In its routine.yml:
mode: fresh
task: Run /evaluate, save the result, then call signal_done.
where:
  kind: team_workspace

Preview with agent_preview {agent: "org/repo/team/agent", teamWorkspace: true}: its context.files destinations are the context paths prepared in the run's cwd. Changes to skills or the agent's context apply on the next spawn, without restarting the app. Projected files are never written into shared team content.

each_mac prepares the directory on each firing Mac; one_mac prepares it only on the armed host. Explicit remote-machine launches continue using their prepared remote repo workspace. On this Mac, a wake delivers only to a live session tagged at launch with that routine's identity. It never adopts another routine's session or an untagged agent started from the Agents tab, even when the agent and cwd match; it launches its own session instead. Remote wakes retain their existing per-agent/workspace matching and admission for now. Delivery leaves the live session's files untouched; an absent agent gets the waking routine's prepared directory before launch. A later fresh spawn for the same routine and saved agent clears that pair's scratch files. Overlap policies are coalesce, skip and queue. Command routines retain their existing target directory.

Tool reference

Reference for the routine tools that read a routine, run-side tools used from inside a routine run, move where a routine fires, and the session wakeup timers. Where a tool takes sessionId, identity comes from the verified MCP connection; a supplied sessionId must name the caller itself, and an unbound caller is refused.

Reading routines and results

routine_get

Reads one routine in full. id comes from routine_list; optional agent refuses (validation) unless the routine belongs to that agent. Returns {status:"ok", data:{id, scope, agent_key, mode, effective_mode, owner, enabled, revision, schedule_in_words, routine, runs}} with this Mac's last 5 runs, plus budgetUsd, budgetPending and spend (ok, warn, reached or unpriced). A routine with content_stale was armed on a machine and not refreshed since its agent changed.

{
  "tool": "routine_get",
  "arguments": {
    "id": "<id from routine_list>"
  }
}

routine_result

Reads the last successful private structured result and the latest attempt for a routine. It is a cached read: it never launches an agent, and it reports schema_compatible and the success timestamp explicitly. Returns the snapshot, latest_attempt status, revision and schema_compatible.

{
  "tool": "routine_result",
  "arguments": {
    "id": "<id from routine_list>"
  }
}

routine_delete

Archives any routine you can see: it stops firing and leaves routine_list, and its run history stays readable. Any visible routine is yours to change, a teammate's included; the change is a local edit to the context repo, and sharing it is a git push your agent makes. Notifies no one. Returns {status:"ok", data:{id, archived:true, revision}}.

{
  "tool": "routine_delete",
  "arguments": {
    "id": "<id from routine_list>"
  }
}

Inside a routine run

routine_context

When a routine launched you, tells you what you are running and why. sessionId is required and answers for the routine run that session is running; optional runId selects the run named in a wake header. Returns data:{run_id, routine_id, routine_name, revision, routine, source, scheduled_at, fired_at, variables, trigger_payload, last_run_summary, last_run_id, agent, content_dir}, or validation ("not a routine run"). trigger_payload carries the document change and coalesced_payloads every merged change; wake text stays static, so call this to read changes.

{
  "tool": "routine_context",
  "arguments": {
    "sessionId": "<your $CODESENSE_TAB_SESSION_ID>"
  }
}

routine_done

Finishes one routine run with your verdict without ending your session; use it when a routine woke you inside a session that keeps working (signal_done ends the session's whole task). Required: sessionId (checked against the terminal you call from), runId (from routine_context or the run line in your task) and outcome (success, failed or needs-attention). Optional summary; a successful run's summary becomes the next run's {{last_run_summary}}. Other runs your session holds are untouched. Returns data:{run_id, routine_id, phase}.

{
  "tool": "routine_done",
  "arguments": {
    "sessionId": "<your $CODESENSE_TAB_SESSION_ID>",
    "runId": "<run_id from routine_context>",
    "outcome": "success",
    "summary": "Checked 3 reviewers"
  }
}

routine_publish_result

Publishes a structured routine result candidate: your JSON payload. The recorded running session chooses the run and the pinned schema; no runId is accepted. Call signal_done with success afterwards to promote the private snapshot. Returns {published:true}; a failed status is an MCP error.

{
  "tool": "routine_publish_result",
  "arguments": {
    "payload": {
      "open": 3,
      "closed": 12
    }
  }
}

Where a routine fires

routine_arm_on

Moves where a routine fires: machine: "this_mac" or a machine id from list_machines, whose terminal server then fires it on its own clock, in the routine's zone, whether or not any Mac is open. This Mac manages it: it prepares the agent there now and on every edit, pushes the definition on reconnect and records the runs. A routine armed on a machine runs on its schedule only (no agent_done, inbox_idle or role_pending triggers), once for the team. Each move is a new revision under a new arm epoch, and moving it off a machine waits for that machine to acknowledge (handover_pending). It counts against the 25 enabled-routine cap. Returns data:{id, armed_machine, arm_epoch, revision, handover_pending, machine_warning?}.

{
  "tool": "routine_arm_on",
  "arguments": {
    "id": "<id from routine_list>",
    "machine": "<machineId from list_machines>"
  }
}

routine_refresh_on_machine

Prepares a machine-armed routine from what it and its agent are now, and pushes it there. The machine workspace is prepared only when you arm, edit, resume or restore the routine, or call this: later changes to the agent's files or team content do not reach the machine on their own. routine_list and routine_get show content_stale until this is called. The machine must be connected and this Mac must manage the routine. Returns data:{id, machine, content_stale:false}, or validation with why it could not.

{
  "tool": "routine_refresh_on_machine",
  "arguments": {
    "id": "<id from routine_list>"
  }
}

routine_handover_release

Stops waiting for a machine that is gone to confirm it stopped firing a routine moved off it. Until a machine confirms, nothing else fires the routine, so a move never doubles a fire. Required: id, machine (the one it waits on, as routine_get shows) and machineGone: true, confirming the machine is gone: one that still runs may fire the routine once more. Returns data:{id, machine, machine_warning?}.

{
  "tool": "routine_handover_release",
  "arguments": {
    "id": "<id from routine_list>",
    "machine": "<machineId from routine_get>",
    "machineGone": true
  }
}

Session wakeups

Timers on your own session, held by the terminal server that runs it (schedule_wakeup sets them).

list_wakeups

Lists the active timers on your own session, soonest first: {timers:[{timerId, name, prompt, nextAt, every?, until?, count?, remaining?, fires, createdBy, machineId, sessionId}]}. sessionId is required and must be your own; another session's id is refused. On a machine whose desktop is away, the machine answers.

{
  "tool": "list_wakeups",
  "arguments": {
    "sessionId": "<your $CODESENSE_TAB_SESSION_ID>"
  }
}

cancel_wakeup

Stops one timer on your own session; a fire it already queued is dropped and nothing is typed. Required: sessionId (your own) and timerId (from schedule_wakeup or list_wakeups). Returns {cancelled}, false when your session has no such active timer.

{
  "tool": "cancel_wakeup",
  "arguments": {
    "sessionId": "<your $CODESENSE_TAB_SESSION_ID>",
    "timerId": "<timerId from list_wakeups>"
  }
}
