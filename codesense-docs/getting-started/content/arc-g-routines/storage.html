Arc G · Routines

Routines live with their agent.

Every routine starts or wakes an agent, so a routine belongs to that agent. Its file sits under the agent's folder, config/agents/<agent>/routines/<id>/routine.yml, and the path names the agent: the YAML has no agent: key. In the app the agent's Routines section in the Agents tab lists them, and Agents | Schedule shows every agent's upcoming fires. Archiving an agent archives its routines (after a confirm that lists them); unarchiving it offers to bring them back.

A timer is the other kind: a temporary routine owned by one running session. It is never a file. It lives with the machine running that session and ends when the session ends.

On-disk layout

<team>/config/agents/ ├── manager/ │ ├── agent.yaml │ └── routines/ │ ├── manager-wake/ │ │ ├── routine.yml # the current definition │ │ └── revisions/1.yml # its own history, separate from the agent's │ └── manager-ensure/ │ └── routine.yml ├── _builtin/ │ └── claude/routines/ # routines on a built-in starter (fresh only) └── _unassigned/routines/ # a routine whose agent is missing: "Pick an agent" _personal/<account>/<org>/_scratch/agents/<org>~<team>~<agent>/routines/<id>/ # your Only me routine on a team agent

Ids, starters and the old folder

Ids are team-unique

A routine id is unique across the whole team, whichever agent holds it, so <org>/<team>/<id> always names one routine and its run history. Moving a routine to another agent keeps its id and its runs.

  • The folder name is the id.
  • Agent folders starting with _ are never agents.
  • agent_get lists an agent's routines; routine_list takes an agent filter.

The old config/routines/

Routines used to live in config/routines/<id>/ and name their agent. CodeSense copies each one forward under its agent the first time it loads the team, with mode: fresh written so it behaves as before, and leaves the old file as a pointer for one release. Nothing new is written there.

  • Copy, never move: an old client's edit is carried forward.
  • An id clash is renamed, with a visible note.
  • The read-only CodeSense docs ship in the new layout already.

Files next to a routine

A routine's folder holds its routine.yml and its revisions/. Keep anything else the task needs (a prompt partial, a checklist) under content/, where the agent reads it like any other file and it versions with the team. State a run produces belongs in the run's result (signal_done, routine_done or routine_publish_result), which the next run reads back.

How CodeSense finds them

  1. For each team you can see, it reads every config/agents/*/routines/*/routine.yml (starters and _unassigned included), plus any old config/routines/ entry not yet carried forward.
  2. A file that doesn't parse, or whose id doesn't match its folder, is skipped (logged, never fires) and doesn't show up. A routine you write by hand is only fully checked when it is saved through CodeSense, so check it first with routine_create dryRun: true.
  3. Enabled routines are armed on the Mac that runs them (armed_here). A routine that runs on each Mac is armed on every Mac whose user turned it on.

Try this now

List the Manager's routines in your editable context repo.

How to do this via MCP 
// Every routine you can see, or one agent's
routine_list {}
routine_list { agent: 'manager' }

// An agent and its routines in one read
agent_get { id: 'manager' }

// Create one under its agent (checks and writes nothing with dryRun)
routine_create {
  name: 'Morning triage', agent: 'barb', mode: 'wake',
  when: 'weekdays 09:00', task: '…', dryRun: true,
}
