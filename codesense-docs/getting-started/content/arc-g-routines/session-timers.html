Arc G · Routines

Remind yourself.

A timer is a temporary routine for the session you're in. Tell an agent "add a routine for your session to check the build in 20 minutes", and it sets a timer on its own session: later, once it is idle, the timer's prompt arrives in the same conversation, so the agent still knows what it was doing. A timer never starts anything, never reaches another session, is never written to git, and ends when the session ends.

Tell it "make a routine for Barb to do X every weekday" instead, and that is a routine: saved under Barb, shared with the team, and firing for as long as it exists, whether or not today's Barb session is still open.

Which one?

You say to the agent It makes With
"Add a routine for your session to check the build in 20 minutes" a timer on its session schedule_wakeup in: "20m"
"Remind yourself at 3pm to post the summary" a timer schedule_wakeup at
"Check the deploy every 10 minutes until it's green" a repeating timer schedule_wakeup every: "10m"
"Make a routine for Barb to triage issues every weekday" a routine on Barb, wake routine_create mode: "wake"
"Every night, start a new agent that writes the changelog" a routine, start a new routine_create mode: "fresh"

Setting one

  • sessionId is the caller's own session. Another session's id is refused: a timer can only wake the session that set it.
  • Exactly one of in (90s, 20m, 2h, 1h30m, 1d) or at (RFC 3339 with its offset, in the future). every repeats (at least 1m), with at most one of until or count.
  • list_wakeups lists the session's timers, soonest first; cancel_wakeup stops one.
  • minGap (optional, 30m, 2h; 1m to 7d) is the least time between two of its deliveries: a fire inside it folds into the last one. Set it when each fire starts heavy work; a light check needs none.
  • Limits: 10 active timers per session, 200 per machine. No lifetime cap: a session can take hundreds of small wakes over a week. A fixed safety backstop (120 wakes an hour per session, every source together) refuses the rest as rate_limited, posts one inbox note naming the top source, and resumes on its own.

When it fires

  1. It waits for idle. The prompt is typed only when the agent is idle at its prompt, nobody has typed in the tab for 3 seconds, and no permission prompt is waiting. Fires due while one still waits fold into it.
  2. It arrives as a new message, headed [timer: Check the build | fire 1]. The tab's caption says "Woken by Check the build" and the scrollback gets a marker.
  3. It ends with the session. Exit, close or crash, and its timers are gone. On a connected machine the machine keeps and fires them, so they keep firing while the desktop is closed; setting, listing and cancelling need the desktop connected.

Timers work in any interactive CodeSense session, a saved agent or an unnamed one, on this Mac or a connected machine. They don't work for headless runs or Codex sessions.

In the app

  • Remind this agent… in a terminal tab's menu sets a timer as you: in 20 minutes, at a time, or every N minutes, with a message.
  • A tab with timers shows a clock in its tab pill and a countdown chip in its caption. The chip's popover lists each timer with Cancel, plus the tab's wake history.
  • Keep this… on a timer turns it into a routine on the tab's agent, with the timer's prompt and schedule filled in. For an unnamed session it saves the session as an agent first.

Try this now

Ask the agent in any CodeSense tab:

Add a routine for your session to tell me the time in 2 minutes.

It calls schedule_wakeup with in: "2m". Watch the caption chip count down, then the message arrive.

How to do this via MCP 
// Set, list, cancel (always your own session)
schedule_wakeup { sessionId, in: '20m', name: 'Check the build', prompt: '…' }
list_wakeups { sessionId }
cancel_wakeup { sessionId, timerId }
