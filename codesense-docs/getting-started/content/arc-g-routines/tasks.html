Tasks.

The task: block is the prompt the agent session receives on each fire. It's a short, well-structured instruction — not a program. The engine substitutes {{trigger.*}} placeholders, hands the resulting text to the agent as its opening message, and watches for the agent to call signal_done. There are no return values and no RPC — the agent's observable effects are the MCP calls it makes and the files it writes.

Task shape

  1. Template body — a markdown block (YAML's | literal) that reads like a short memo. State the trigger, enumerate the steps, name the signal_done payload. Keep it under ~40 lines; longer tasks drift.
  2. Trigger-context placeholders — anywhere the body says {{trigger.X}}, a fresh run substitutes the matching field on the trigger event (table below). Unknown keys stay literal — the agent will mention them in its reply and you'll notice. A wake fills in only {{date}} and {{timestamp}}: the text is typed into a live session, so it carries no run-specific data.
  3. MCP calls — the agent works via its allowlisted MCP servers (declared in its agent.yaml). The seeded tasks lean on read_messages, claim_role_messages, role_state and routine_done. A task never wakes another agent with send_to_session: give that agent its own wake routine.
  4. Scope — the task body never names the context repo path explicitly; the engine spawns the session with the right where and the agent uses its MCP tools against that scope. Portable across workspaces for free.

Trigger context, by trigger shape

Trigger Available placeholders
inbox_idle {{trigger.sessions}} (JSON list of {handle, name, unread, oldest_unread_at}), {{trigger.count}}
agent_done {{trigger.session_id}}, {{trigger.status}}, {{trigger.summary}}, {{trigger.agent}}
cron / manual none beyond the always-on ones
always (fresh) {{date}}, {{timestamp}}, {{last_run_at}}, {{last_run_summary}}, declared {{variables}}
always (wake) {{date}}, {{timestamp}} only

Exit contract

routine_done (wake)
A woken session gets the task headed [routine: <name> | run <id>]. It calls routine_done with that run id, an outcome and a summary: the run ends, the session keeps working. Without it the run is recorded delivered. Never signal_done for a wake: that ends the session's whole task.
signal_done (start a new)
The agent calls signal_done with a one-line summary. The engine logs the run as ok and tears the session down. The routines console shows the summary; the next trigger fires on its own timeline.
no-op
"Nothing to do" is a valid outcome. The agent still calls signal_done with a short rationale ("manager queue empty"). A tick that fires and signals no-op is cheap and leaves a scannable breadcrumb in run history.
timeout
If the agent exceeds policy.max_runtime, the engine kills the session and logs the run as timeout. The routines console shows the partial transcript. Fix: shorten the task, tighten the MCP calls, or raise max_runtime.
overlap: skip
With policy.overlap: skip, a tick that fires while the previous run is still in flight is logged as skipped and does nothing. Use this for idempotent cron routines where overlap would mean duplicate work.
fail
An unhandled error inside the agent's runtime (crash, bridge rejection) is logged as fail with a short reason. The next scheduled tick fires normally; CodeSense doesn't back off automatically.

Worked example — a wake task with a no-op branch

The seeded manager-ensure routine wakes the Manager every hour. Its task is written to the Manager itself — it is typed into the Manager's session — and every branch ends quietly. If no Manager is running, the same text starts one. 

mode: wake
task: |
  Check the manager queue. Call role_state with role "manager".
  If anything is pending, claim it with claim_role_messages and carry on
  with /manage-team. If nothing is pending, say "manager queue empty" in
  one line and wait.

Try this now

Check a routine without saving it: routine_create with dryRun: true validates the schedule, the agent and the mode, and reports warnings such as a /command the agent doesn't start with.

How to do this via MCP 
// Check without writing
codesense.invoke('routine_create', { name: '…', agent: 'manager', mode: 'wake', task: '…', dryRun: true })

// Live fire
codesense.invoke('routine_run_now', { id: 'manager-wake' })

// Inside a woken session: finish this run, keep the session
codesense.invoke('routine_done', { sessionId, runId, outcome: 'success', summary: '…' })

// Tail the run (routines-console does this live)
codesense.subscribeContext({ topic: 'routines.runs', id: 'manager-wake' }, (ev) => { … })
