Wake the Manager.

Every routine has a mode. wake types the routine's task into a matching running session once it is idle, so the agent keeps everything it already knows. On this Mac, the session must carry this routine's launch tag: another routine's session or an untagged Agents-tab session is never adopted. Each local routine starts its own session when none matches. Remote wakes retain per-agent/workspace matching and admission for now. start a new (mode: fresh in the file) starts a new session of the agent on every fire, with the task as its whole prompt. A Manager, a triage desk or a long-lived Builder you keep open and talk to wants wake. A nightly report or a digest that wants a clean slate wants start a new.

A wake with no running session doesn't fail: it starts one, with the task as its first prompt. So one routine both keeps a live agent busy and brings it back when it is gone.

The two files

The routine lives under the agent it wakes, so it names no agent:. Both files ship in these docs under examples/agents/manager/.

What happens, step by step

  1. Mail arrives. A message lands in the Manager session's inbox — a worker's report, a question for it. The Manager is idle at its prompt. Its inbox waiter tells it at once, but if it leaves the mail unread (or runs without a waiter), nothing tells it again.
  2. The event fires. One of the Manager's own sessions sits idle with unread mail, so inbox_idle fires manager-wake (at most once every 30 seconds). Mail waiting for another agent — a worker, an ad-hoc tab — never fires a Manager's wake routine; give that agent its own.
  3. CodeSense finds the Manager. It looks for the Manager's live session on the routine's machine, preferring the one with the mail, then an idle one. Local sessions must be tagged as launched for this routine.
  4. It waits for a quiet moment. It types only when the agent is idle, no one has typed in that tab for 3 seconds, and no permission prompt is waiting. Then it pastes the task once, headed [routine: Wake the manager | run <id>], and submits it.
  5. You can see it. The tab's caption says "Woken by Wake the manager" and the scrollback gets a marker. The run is recorded delivered.
  6. The Manager works. It reads and claims, then may call routine_done with the run id to record a result for that run, while its session carries on.

Busy, absent, on another machine

  • Busy: the run is queued ("Waiting for Manager to be idle") and delivered at its next idle point, up to the routine's max wait (30 minutes by default), else undelivered (busy_timeout). Fires that come meanwhile fold into it (coalesced).
  • Not running: it starts the Manager with the task as its first prompt. On this Mac, only one start is in flight per routine, so repeated fires of that routine never start two Managers. Separate local routines get separate sessions. Remote starts keep their existing per-agent/workspace admission.
  • On a connected machine: set machine to its id, or any to wake the agent wherever it runs (starting it on this Mac when none does). The machine itself delivers, so a wake lands even if the desktop drops while it waits. A machine that is offline gives undelivered (machine_offline), never a second Manager.
  • Unknown: when CodeSense can't confirm the text went in, the run says "May have been delivered. Check the terminal before re-sending." It is never re-sent automatically, and it posts once to your inbox.
  • Ignored: after 3 wakes that leave the same mail unread, the routine stops waking for that mail and raises "needs you".

Who can be woken

A saved agent with launch: foreground. The built-in starters (builtin/claude, builtin/codex) start a new session only, so a tab someone opened by hand is never typed into. A headless run is never woken. An agent that auto-approves every tool needs allowWake: true in its definition. Codex idle detection isn't qualified yet, so wakes into Codex sessions may come back undelivered (unobservable).

The wake text is the task with only {{date}} and {{timestamp}} filled in; {{last_run_summary}} and {{trigger.*}} are for start-a-new runs.

No middleman

Before routines could wake, the pattern was a second, short-lived agent whose task called list_sessions and send_to_session to nudge the real one. Don't write that any more: mode: wake delivers into the agent the routine belongs to, waits for it to be idle, never collides with your typing, and records an honest result. send_to_session is still the tool for an agent nudging another agent by hand.

For "check back on this in 20 minutes" from inside a session, don't write a routine at all: set a timer on that session.

Try this now

With the Manager copied into your editable context repo, fire its wake routine once by hand. If the Manager is running, the task goes into its tab; if not, a Manager starts.

How to do this via MCP 
// A wake routine on a saved agent, every weekday at 9
codesense.invoke('routine_create', {
  name: 'Morning triage', agent: 'barb', mode: 'wake',
  when: 'weekdays 09:00',
  task: 'Triage new issues, then call routine_done with a one-line summary.',
})

// Fire it once, then read how it went (delivered / queued / undelivered / unknown)
codesense.invoke('routine_run_now', { id: 'morning-triage' })
codesense.invoke('routine_runs', { id: 'morning-triage', limit: 5 })

// Inside the woken session: finish just this run, keep working
codesense.invoke('routine_done', { sessionId, runId, outcome: 'success', summary: '4 triaged' })
