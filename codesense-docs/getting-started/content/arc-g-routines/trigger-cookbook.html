Trigger cookbook: schedule, metadata trigger, events and chaining

Choose one trigger, preview it, then enable it deliberately. Each card has the actual routine_create arguments and the equivalent complete YAML. These examples share machine-readable inputs with the routine-create seam tests.

First save an agent whose id is default, or substitute your saved agent id in the MCP form and YAML path. Agent routines go under config/agents/default/routines/<id>/routine.yml. A command routine goes under config/agents/_command/routines/<id>/routine.yml. Examples start disabled. A dry run reports a plan; it never fires the trigger.

For each MCP block call routine_create with that JSON. Require status: ok and data.dry_run: true; inspect warnings, effective mode, selected agent and next fires. A refusal explains the invalid field. To save, change dryRun to false. Use routine_get to read back the definition. Trigger a controlled test before enabling unattended operation.

Create or update event triggers

routine_create and routine_update accept events for inbox_idle, agent_done and role_pending, with the same validation as handwritten YAML. Each item becomes triggers: [{event: ...}]; use metadataTriggers for metadata changes. from_agent is valid only for agent_done; omit it for all agents in reach. It is an agent id or full key, without an existence check.

On update, omitted or null events preserves existing event triggers; [] clears these three kinds; a nonempty list replaces only them. Schedules and metadata triggers remain. A refusal returns status: validation with an indexed field such as events[1].role and a hint; nothing is saved. Creation alone supports dryRun:true: inspect the resolved data.triggers, then save and enable deliberately. There is no update dry run. These three event kinds support each_mac; metadata triggers still require one_mac. Local event triggers cannot be armed on a remote machine.

The complete YAML blocks omit machine-owned placement. If installing by hand, keep the routine disabled, open the app editor, make a harmless edit (such as the name), then choose Save changes to validate it. Use routine_arm_on {id, machine:"this_mac"} before enabling a one_mac routine. The schema browser’s local shape check does not establish semantic validity.

Weekday review · schedule

Runs weekdays at 09:00 UTC. The disabled draft has an empty data.next_fires; check its schedule wording, then enable and verify the next three weekday fires in that zone. Schedules use five-field cron and may not fire more often than every five minutes. After saving and enabling, wait for the next listed fire, then inspect its run.

MCP: routine_create dry run

{
  "agent": "default",
  "mode": "fresh",
  "maxRuntime": "5m",
  "enabled": false,
  "dryRun": true,
  "id": "morning-review",
  "name": "Weekday review",
  "task": "Review the relevant stories and report the result.",
  "when": "weekdays 09:00",
  "tz": "UTC"
}

Complete routine.yml

id: "morning-review"
name: "Weekday review"
owner: "codesense"
where:
  kind: "team_workspace"
policy:
  max_runtime: "5m"
revision: 1
agent: "default"
mode: "fresh"
task: "Review the relevant stories and report the result."
triggers:
  -
    schedule:
      cron: "0 9 * * 1-5"
      tz: "UTC"

Story moves to review · metadata_change

A metadata trigger watches story status entering review from in-progress. Selection uses the same query model as query_context; target and previous currently use op: eq. Omit previous for any transition into the target value. First discovery and app restart baseline existing matches; they do not replay them. Enable before making a new transition, keep runs_on: one_mac, then inspect the run trigger to identify the document. The dry run validates the condition, not an observed transition.

MCP: routine_create dry run

{
  "agent": "default",
  "mode": "fresh",
  "maxRuntime": "5m",
  "enabled": false,
  "dryRun": true,
  "id": "story-review",
  "name": "Story moves to review",
  "task": "Review the relevant stories and report the result.",
  "metadataTriggers": [
    {
      "selection": {
        "where": {
          "kinds": [
            "story"
          ]
        }
      },
      "target": {
        "key": "status",
        "op": "eq",
        "value": "review"
      },
      "previous": {
        "key": "status",
        "op": "eq",
        "value": "in-progress"
      }
    }
  ]
}

Complete routine.yml

id: "story-review"
name: "Story moves to review"
owner: "codesense"
where:
  kind: "team_workspace"
policy:
  max_runtime: "5m"
revision: 1
agent: "default"
mode: "fresh"
task: "Review the relevant stories and report the result."
triggers:
  -
    event:
      kind: "metadata_change"
      metadata:
        selection:
          where:
            kinds:
              - "story"
        target:
          key: "status"
          op: "eq"
          value: "review"
        previous:
          key: "status"
          op: "eq"
          value: "in-progress"

Unread mail at an idle prompt · inbox_idle

With this fresh-mode example, idle sessions with unread mail in reach of the team fire it; {{trigger.sessions}} identifies them. For a wake routine, only the owning agent’s own session with unread mail fires and receives it. To test, send ordinary inbox mail to an idle disposable agent session, then inspect the run. After three wakes that leave the same mail unread, the runner stops repeating that mail and records the reason in routine run history. Use routine_runs then routine_run to inspect it; write the task to read the mail.

MCP: routine_create dry run

{
  "agent": "default",
  "mode": "fresh",
  "maxRuntime": "5m",
  "enabled": false,
  "dryRun": true,
  "id": "inbox-idle",
  "name": "Unread mail at an idle prompt",
  "task": "Inspect the idle sessions {{trigger.sessions}} and read their pending inbox messages. Report any work needing attention.",
  "events": [
    {
      "kind": "inbox_idle"
    }
  ]
}

Complete routine.yml

id: "inbox-idle"
name: "Unread mail at an idle prompt"
owner: "codesense"
where:
  kind: "team_workspace"
policy:
  max_runtime: "5m"
revision: 1
agent: "default"
mode: "fresh"
task: "Inspect the idle sessions {{trigger.sessions}} and read their pending inbox messages. Report any work needing attention."
triggers:
  -
    event:
      kind: "inbox_idle"

Agent finishes · agent_done

from_agent filters to the saved agent named default; omit it to watch all agents in reach. After enabling, finish a disposable run of that agent and inspect the trigger’s agent, status and summary. This observes an agent completion; use after to watch a specific routine outcome.

MCP: routine_create dry run

{
  "agent": "default",
  "mode": "fresh",
  "maxRuntime": "5m",
  "enabled": false,
  "dryRun": true,
  "id": "agent-done",
  "name": "Agent finishes",
  "task": "Inspect the completion of {{trigger.agent}}: {{trigger.status}} / {{trigger.summary}}. Review the result and report findings.",
  "events": [
    {
      "kind": "agent_done",
      "from_agent": "default"
    }
  ]
}

Complete routine.yml

id: "agent-done"
name: "Agent finishes"
owner: "codesense"
where:
  kind: "team_workspace"
policy:
  max_runtime: "5m"
revision: 1
agent: "default"
mode: "fresh"
task: "Inspect the completion of {{trigger.agent}}: {{trigger.status}} / {{trigger.summary}}. Review the result and report findings."
triggers:
  -
    event:
      kind: "agent_done"
      from_agent: "default"

Role mail arrives · role_pending

Use {kind:"role_pending"} when a dispatcher needs every role queue in reach. Use {kind:"role_pending",role:"reviewer"} when this routine should run only for reviewer mail. The example below uses that filter; omit role for the wildcard. A team routine watches its own team; a private routine watches teams in its org. Empty or whitespace-only role names fail validation; role names need no registry entry. The run receives {{trigger.role}}, {{trigger.message_id}}, {{trigger.org}} and {{trigger.team}}. Notification does not claim mail: use register_role, claim_role_messages, accept_role_message before work and ack_role_message after work. After enabling, enqueue a disposable message with send_role_message, then inspect both role_state and the routine run. A defaultHandler is configuration only and does not automatically launch an agent.

MCP: routine_create dry run

{
  "agent": "default",
  "mode": "fresh",
  "maxRuntime": "5m",
  "enabled": false,
  "dryRun": true,
  "id": "role-pending",
  "name": "Role mail arrives",
  "task": "Call role_state for the reviewer queue. If it has pending work, register_role for reviewer, then claim_role_messages. Before doing the work, call accept_role_message with disposition kind work; after finishing, call ack_role_message with its receiptId and the claim details. If an existingReceipt is returned, finish that accepted work and acknowledge its receipt instead of accepting again. Ignore other queues.",
  "events": [
    {
      "kind": "role_pending",
      "role": "reviewer"
    }
  ]
}

Complete routine.yml

id: "role-pending"
name: "Role mail arrives"
owner: "codesense"
where:
  kind: "team_workspace"
policy:
  max_runtime: "5m"
revision: 1
agent: "default"
mode: "fresh"
task: "Call role_state for the reviewer queue. If it has pending work, register_role for reviewer, then claim_role_messages. Before doing the work, call accept_role_message with disposition kind work; after finishing, call ack_role_message with its receiptId and the claim details. If an existingReceipt is returned, finish that accepted work and acknowledge its receipt instead of accepting again. Ignore other queues."
triggers:
  -
    event:
      kind: "role_pending"
      role: "reviewer"

Agent follows the command · after

Create the predecessor review-command from the command chain before this dry run. A successful predecessor run fires this agent routine with {{trigger.result_text}}. on: finished continues after succeeded, failed, timed_out, needs_you or ended; cancelled does not fire a chain. Trigger the upstream command after enabling both; compare the downstream trigger run_id to the upstream run. Dry-run success establishes the saved dependency, not a completed chain.

MCP: routine_create dry run

{
  "agent": "default",
  "mode": "fresh",
  "maxRuntime": "5m",
  "enabled": false,
  "dryRun": true,
  "id": "review-agent",
  "name": "Agent follows the command",
  "task": "The upstream result names the changed story: {{trigger.result_text}}. Open that path, review the story and report your findings.",
  "after": {
    "routine": "review-command",
    "on": "succeeded"
  }
}

Complete routine.yml

id: "review-agent"
name: "Agent follows the command"
owner: "codesense"
where:
  kind: "team_workspace"
policy:
  max_runtime: "5m"
revision: 1
agent: "default"
mode: "fresh"
task: "The upstream result names the changed story: {{trigger.result_text}}. Open that path, review the story and report your findings."
after:
  routine: "review-command"
  on: "succeeded"

Read a controlled run

After enabling, induce the real event in a disposable story or message thread. Use routine_runs {id} and routine_run {runId} to inspect the outcome, trigger and summary. Agent fresh runs finish through signal_done or process exit; wake runs use routine_done. Commands succeed on exit 0 and fail on a nonzero exit. A dry run proves authoring validation; it does not prove your external command, clock or agent instructions work live.
