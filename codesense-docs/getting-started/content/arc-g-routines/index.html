Routines.

A routine is a saved agent's standing task: a tiny bit of YAML, stored under that agent, that pairs a trigger with a task. The trigger is "when" (a schedule, an idle inbox, mail queued for a role, another agent finishing, a human clicking Run). The mode is "how": wake types the task into the agent's running session when it is idle (starting one only if none runs), and start a new (mode: fresh) starts a new session every time. No daemon, no polling — CodeSense owns the clock. In the app, routines live in the Agents tab: each agent's Routines section, and the Agents | Schedule view.

For "do this later" inside one conversation there is a lighter tool: a session timer, a temporary routine that comes back to that same session and ends with it.

Cancel one run

An agent calls routine_cancel {runId} to cancel one queued or running run. Read routine_runs first and use the returned run_id: 

routine_runs {"id":"acme/api/backend/digest","limit":20}
// Choose a queued or running row and copy its run_id.
routine_cancel {"runId":"<run_id from routine_runs>"}
routine_run {"runId":"<the same run_id>"}

Success returns {status:"ok", data:{routine_id, routine_name, run_id, phase, created_at, started_at, ended_at, ...}}, the same row shape as routine_run, with RFC3339 times. Cancelling a fresh run stops its agent or command. Cancelling a wake run keeps the session it woke alive; queued wake text is withdrawn from its host first. If the host already delivered it, the response reports that it could not be withdrawn and gives its actual phase. An unreachable host or a remote launch still starting returns an error; the run stays queued.

An unknown run, a run outside your visible routines, or an already finished run returns validation with a message; finished runs are unchanged. Shared team runs can be cancelled regardless of who created the routine. MCP identity comes from the verified connection; omit sessionId, or supply only your own. An unbound connection or another caller's id is refused.

This cancels one run and leaves future fires enabled. Other queued runs may start when this one ends. To pause future starts, use routine_set_enabled {id, enabled:false}. The pane method codesense.routineCancel({key}) is a different operation: it batch-cancels this principal's live structured-result attempts for that routine and returns a count, retaining last-good data. See troubleshooting.

Trigger shapes

A trigger is a schedule (a cron and a time zone) or an event. The event kinds are inbox_idle, role_pending and agent_done. No triggers means manual only.

inbox_idle

Fires when a session sits idle at its prompt with unread mail. With mode: wake it wakes the routine's own agent. Zero cost when nothing waits; immediate when work lands. The glue of the inbox-driven factory.

schedule

A standard 5-field cron in a time zone (an agent can also pass a preset such as daily 09:00 as when). Fires on wall-clock cadence. Great for liveness backstops, synthesis passes, or a nightly sweep.

manual

Fires only when a human clicks Run now, a dashboard's Refresh calls routineRefresh, or an agent calls routine_run_now. The docs' own update-codesense-docs routine is one: the Update button runs it.

agent_done

Fires when an agent finishes (signal_done), optionally only one agent (from_agent). The routine shows under the agent it runs, with an "after ‹agent›" note.

role_pending

Fires once for each message queued for a role inbox. A controller routine uses it to start an agent for the role, which then claims the message. The run gets {{trigger.role}} and {{trigger.message_id}}.

each_mac

Not a trigger by itself — a runs_on scope that pairs with any of the above. The routine fires once per trusted Mac on each tick, so remote fleets stay independent.

Try this now

Open the routines console dashboard. It lists every routine the active team is wired to run, their next-fire times, and the last-N runs with status chips.

How to do this via MCP 
// Every routine you can see, or one agent's
codesense.invoke('routine_list', {})
codesense.invoke('routine_list', { agent: 'manager' })

// Make one for Barb: wake her running session every weekday at 9
codesense.invoke('routine_create', {
  name: 'Morning triage', agent: 'barb', mode: 'wake', when: 'weekdays 09:00', task: '…',
})

// Or, for your own session only, a timer
codesense.invoke('schedule_wakeup', { sessionId, in: '20m', prompt: '…' })

// Fire a routine once by hand
codesense.invoke('routine_run_now', { id: 'manager-wake' })
