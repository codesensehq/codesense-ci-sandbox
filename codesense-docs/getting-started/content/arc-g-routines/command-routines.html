Command routines: argv commands and an agent chain

Use a command routine for deterministic work: validate a file, run a script, collect a small report. Use an agent routine when the work needs judgment, tools selected by the agent, or a conversation. A command routine launches no agent and makes no model call.

Set action: command and an argv array: the program is the first element, each argument is its own element. Omit agent, task and mode. Commands have no wake mode and run on this Mac. They live under config/agents/_command/routines/<id>/routine.yml.

command: [python3, scripts/check-review.py, --format, json]

The program may be a name found on PATH or a path inside the team's files; absolute program paths, parent traversal and whitespace in the program name are refused. Prefer python3 scripts/check-review.py or node scripts/check-review.mjs as separate argv entries because sync does not preserve executable permission. Pipes, redirects and shell expansion are not interpreted. The working directory follows where.kind: team_workspace uses the team content root, while repo:owner/repo uses that managed repository clone. Relative program paths in argv[0] still resolve under the team content root. Each template expands within one argv element; it is never split into shell words.

Outputs and outcomes

Exit 0 records succeeded; a nonzero code records failed. Cancellation and a runtime deadline record cancelled and timed_out. Use routine_runs then routine_run for the exit code, stdout/stderr tails, argv and working directory. Captured output is bounded (4096-byte tails), so save large artifacts to a file.

The child receives CODESENSE_ROUTINE_ID and CODESENSE_RUN_ID. Stdout becomes the run's result_text. A chained routine reads it as {{trigger.result_text}}; also available are {{trigger.run_id}}, {{trigger.routine}}, {{trigger.phase}} and {{trigger.detail}}. result_text is what the command produced; detail is CodeSense's explanation of why the run ended (a command that did not start, such as unresolved:itemId). Wake, machine and admission runs still explain themselves in result_text. Command stdout is plain result text; result_schema does not parse or validate it as a structured published payload.

Metadata → command → agent

A story changing from in-progress to review fires the command. On its successful completion, an agent gets the stdout as its task input. Save the command first, then the agent routine; the predecessor must exist in the same space. after.routine is its bare routine id. Chains reject cycles. on: succeeded continues only after success; on: finished continues after succeeded, failed, timed_out, needs_you or ended; cancelled does not fire a chain. An independent schedule or event may coexist with an after trigger.

Choose a saved agent id for the final step (the example uses default). Dry-run both blocks, save them with dryRun:false, inspect with routine_get, then enable both. If installing the YAML by hand, arm each one_mac definition with routine_arm_on {id, machine:"this_mac"} before enabling; preserve the placement of MCP-created drafts. Existing metadata matches are baselined, so make a new controlled transition after enabling. The command receives {{trigger.path}} as a separate argv element and prints that original document path. Its stdout reaches the agent as {{trigger.result_text}}, so the agent can open the exact changed story. Replace the print step with your validator while preserving that identity in its output.

Metadata review command

MCP: routine_create dry run

{
  "maxRuntime": "5m",
  "enabled": false,
  "dryRun": true,
  "id": "review-command",
  "name": "Metadata review command",
  "action": "command",
  "command": [
    "python3",
    "-c",
    "import sys; print(sys.argv[1])",
    "{{trigger.path}}"
  ],
  "metadataTriggers": [
    {
      "selection": {
        "where": {
          "kinds": [
            "story"
          ]
        }
      },
      "target": {
        "key": "status",
        "op": "eq",
        "value": "review"
      },
      "previous": {
        "key": "status",
        "op": "eq",
        "value": "in-progress"
      }
    }
  ]
}

Complete routine.yml

id: "review-command"
name: "Metadata review command"
owner: "codesense"
where:
  kind: "team_workspace"
policy:
  max_runtime: "5m"
  overlap: "queue"
revision: 1
action: "command"
command:
  - "python3"
  - "-c"
  - "import sys; print(sys.argv[1])"
  - "{{trigger.path}}"
triggers:
  -
    event:
      kind: "metadata_change"
      metadata:
        selection:
          where:
            kinds:
              - "story"
        target:
          key: "status"
          op: "eq"
          value: "review"
        previous:
          key: "status"
          op: "eq"
          value: "in-progress"

Agent follows the command

MCP: routine_create dry run

{
  "agent": "default",
  "mode": "fresh",
  "maxRuntime": "5m",
  "enabled": false,
  "dryRun": true,
  "id": "review-agent",
  "name": "Agent follows the command",
  "task": "The upstream result names the changed story: {{trigger.result_text}}. Open that path, review the story and report your findings.",
  "after": {
    "routine": "review-command",
    "on": "succeeded"
  }
}

Complete routine.yml

id: "review-agent"
name: "Agent follows the command"
owner: "codesense"
where:
  kind: "team_workspace"
policy:
  max_runtime: "5m"
revision: 1
agent: "default"
mode: "fresh"
task: "The upstream result names the changed story: {{trigger.result_text}}. Open that path, review the story and report your findings."
after:
  routine: "review-command"
  on: "succeeded"
