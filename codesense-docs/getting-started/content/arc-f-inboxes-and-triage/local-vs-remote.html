Any role. Any machine.

A role lives in the team workspace, not on a machine. When an agent calls register_role {role: "manager"}, the inbox queue is addressed by the role name — not by the hostname or the session id. That means you can run the same flow with every role on one Mac, with half of them on a beefy remote, or with the whole thing roaming between two Macs that take turns being awake. Three shapes below; the agent.yaml is identical across them. Only the machineId on open_workspace and the runs_on field on the routine change.

Shape A · All local

Everything on your Mac

Simplest shape. Every role's holder session runs on the same machine the user is on. Fast, deterministic, and the only shape that works with no network. The inbox-flows dashboard and factory-playbook render this when the Local↔Remote toggle is set to Local. 

// Launch every worker on this Mac
open_workspace {
  target: 'story', story_id: 'DEMO-1', name: 'builder-DEMO-1',
  agent: 'builder',
  // machine_id omitted → defaults to the local machine
}

Shape B · Local triager, remote workers

Keep the human-facing roles close; farm out the heavy lifting

The manager and resolver stay on your Mac so you can see and interrupt them. The builder-* shards run on remote machines in private-account mode — more cores, more RAM, no interruption to your dev loop. Replies arrive in your inbox like any other message; the dashboards show a machine badge next to each session. 

// Local manager — default
open_workspace { target: 'team-workspace', name: 'manager', agent: 'manager' }

// Remote builders — one per story shard
open_workspace {
  target: 'story', story_id: storyId, name: `builder-${storyId}`,
  agent: 'builder',
  machine_id: pickRemote(storyId),   // picks a remote by id from list_machines
}

Shape C · Roaming between Macs

Follow the awake Mac

Two Macs that take turns. The role names are the same on both; whichever Mac wakes up first, the manager-ensure routine on it registers the manager role and starts work. The queue persisted while nobody was holding it, so the overnight escalation that arrived at 2am is waiting intact. This is what makes "my laptop closed, nothing is lost" a true statement. 

# routine.yml — one wake routine, turned on with Run on my Mac on each Mac
runs_on: each_mac
triggers:
  - schedule: { cron: "*/5 * * * *", tz: UTC }  # health check
  - event:    { kind: role_pending }
# the task does role_state first; if nobody holds the role AND work is pending,
# this Mac takes it.

Parity gaps

⚠ Parity gap. The app itself runs only on the Mac you run CodeSense on. Everything else — launching sessions, inbox state, role queues — is machine-agnostic; inbox_idle routines fire from the app on a Mac. If a flow depends on tools that work only on this Mac (e.g. deep OS automation), those shards must stay on the Mac you run CodeSense on. The factory-playbook marks these with a per-phase callout.
