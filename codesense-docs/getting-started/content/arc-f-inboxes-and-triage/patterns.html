Same kit, four shapes.

You've got the kit: messages, roles, queues, inbox_idle. The flexibility story is that these four primitives recompose into a surprising range of shapes. Below are the four we ship with — a closed dispatch factory, a human-in-the-loop pipe, a linear SDLC flow with an escalation hop, and a one-shot notify. Each has a sibling .excalidraw source under ./diagrams/inbox-flows/, a seed routine + agent, and lives on the inbox-flows dashboard so you can pop open the full detail sheet.

01 · Dispatch factory

closed loop no humans in hot path

A triager role fans incoming work out to typed worker queues — builder, reviewer, scout — and the workers return results to the triager. Replies loop back; a human only sees the roll-up. This is the shape the Manager Agent + manager-wake routine ship as the default. 

# config/agents/manager/routines/manager-wake/routine.yml (seed)
id: manager-wake
mode: wake          # typed into the Manager's own idle session
triggers: [{event: {kind: inbox_idle}}]
task: You have unread mail. Call read_messages, then claim_role_messages …

02 · Human-in-the-loop queue

one pair of hands nudge on stale

Every incoming message funnels through a single resolver role held by a human. They reply, or they hand off to another role. A routine that starts a new digest agent on a schedule posts the stale items to the human's Inbox. Shape is identical to dispatch — only the holder changed from an agent to a human. 

# config/agents/digest/routines/stale-digest/routine.yml
mode: fresh
triggers: [{schedule: {cron: "0 */2 * * *", tz: UTC}}]
task: Post a one-line digest of stale resolver items with inbox_post.

03 · SDLC pipeline

linear escalation hop

Scout → builder → reviewer in sequence. Each step is a role; each handoff is a reply with replyTo: "role:next". When either the builder or the reviewer hits an ambiguous spec, they escalate to a resolver; the verdict comes back and the pipeline resumes. This is the exact shape the decision-escalation seed thread traces (more →). 

# agent.yaml (seed · examples/agents/manager)
id: manager          # the triager at the head of the pipeline
runtime: claude
default_prompt: /manage-team

04 · One-shot notify

smallest shape no queue

A single routine polls an external signal — CI, a webhook, a watched file — and sends one message when the condition flips. No role; no queue; no second actor. The routine's cron is the trigger. The shape exists to prove you don't have to adopt the full kit for a trivial need. 

# routine.yml
id: ci-green-ping
triggers: [{schedule: {cron: "* * * * *", tz: UTC}}]
task: |
  1. Poll CI status for the current PR.
  2. If status is green and we have not pinged yet, send_message
     {to: "human", text: "CI green on PR #42."}
policy: { max_runtime: 2m, overlap: skip }

How to do this via MCP

Each pattern reduces to a routine wake-up and the shared role-queue loop:

// 1. A routine on inbox_idle fires on the right role.
// 2. In mode: wake, CodeSense types the routine's task into that agent's idle session.
// 3. The holder's loop: claim_role_messages → accept_role_message → do work
//    → reply/send_message → ack_role_message.
// Changing the shape = changing the roles + the edges between them.
