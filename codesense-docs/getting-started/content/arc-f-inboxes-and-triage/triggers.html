Wake on idle.

You don't want workers polling. You don't want a central scheduler. You want a sleeping agent to wake exactly when there's work on its queue — nothing before, nothing after. inbox_idle is the trigger that does that: a routine declares event.kind: inbox_idle, and CodeSense fires it when a session sits idle at its prompt with unread mail. With mode: wake only the routine's own agent's sessions fire it, and CodeSense types its task into the one with the mail — the Manager, say — and the loop in manage-team picks the work up. No second agent does the waking, and a worker's mail never wakes the Manager.

Worked example — manager-wake

The seed examples/agents/manager/routines/manager-wake/routine.yml lives under the Manager agent and wakes it when mail waits. Short, declarative, no polling. 

id: manager-wake
name: Wake the manager
owner: codesense
mode: wake
task: |
  You have unread mail. Call read_messages with your session id, then
  claim_role_messages for the manager role, and carry on with /manage-team.
  If there is nothing for you, say so in one line and wait.
where:
  kind: team_workspace
  machine: local
triggers:
  - event:
      kind: inbox_idle
policy:
  max_runtime: 5m
runs_on: each_mac
revision: 1

Two shapes of trigger

  1. event-driven — triggers: [{event: {kind: inbox_idle}}] fires as a reaction. Zero cost when the queue is quiet; immediate when work lands. Use this for anything the inbox can notify.
  2. cron-driven — triggers: [{schedule: {cron: "0 * * * *"}}] fires on a wall-clock cadence. Pair with event-driven when you need a liveness backstop. The seed manager-ensure wakes the Manager every hour to check its queue (starting one if none runs); manager-wake uses the event to wake it when mail waits.

Both routines consult the same queue state via the same MCP tools; one is reactive, one is a safety net. You get a system that's quiet when nothing's happening, instant when something is, and self-healing when a machine was asleep.

How to do this via MCP 
// Enumerate one agent's routines
codesense.invoke('routine_list', { agent: 'manager' })

// Watch for firings in real time (routines console dashboard uses this)
codesense.subscribeContext({ topic: 'routines.runs' }, (run) => { … })

// Fire one manually, through its own overlap rule
codesense.invoke('routine_run_now', { id: 'manager-wake' })
