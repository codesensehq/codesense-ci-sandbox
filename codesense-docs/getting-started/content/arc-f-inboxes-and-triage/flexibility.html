Compose any shape.

The four shapes we ship are the common ones, not the only ones. The claim is stronger: anything that fits "something sends a thing, somebody holds a role, something fires when a queue goes quiet" fits in CodeSense's kit. On this page we'll sketch three shapes we don't ship, show the routine.yml + agent.yaml each one takes, and point you at the composer in inbox-flows that will emit the same config for whatever you build.

Shape A · Fan-in triage

Three scouts, one analyst

Separate scouts collect user-voice, metrics, and errors; all three send into one analyst role queue. The analyst drains once a day and files a digest. Any time a scout wants to escalate individually, it bypasses the queue and sends to human directly. 

# routine.yml — the daily analyst wake
id: analyst-daily-digest
triggers:
  - schedule: { cron: "0 9 * * *", tz: UTC }
  - event: { kind: inbox_idle }   # also wake on urgent-looking spikes
task: |
  claim_role_messages {role: "analyst", limit: 50}
  Group by scout, summarize, send_message to "human".

Shape B · Round-robin worker pool

Dispatcher + idempotent workers

A dispatcher holds a dispatch role queue. Four workers share a single worker-pool role (non-exclusive). Each incoming job gets handed to the first idle worker — role_state tells the dispatcher who's free. When a job's done it posts back to role:dispatch, closing the loop. 

# agent.yaml — non-exclusive pool holder
id: worker
runtime: claude
default_prompt: /work-one
# worker's /work-one skill ends with:
#   release_role {team, role: "worker-pool", instanceId, generation}
# so a sibling can claim the next job.

Shape C · Review-then-ship

SDLC + a deploy valve

Same bones as the SDLC pipeline, with a deploy role on the end that only fires on reviewer green. On red, the reviewer bounces the thread back to the builder; the deploy role never sees the delivery. The valve is a disposition check inside the deploy agent's accept_role_message — not a scheduler, not a new primitive. 

# deploy's /ship skill, in two lines of pseudo
if (parentReviewVerdict !== "green") {
  accept_role_message { disposition: {kind: "no_work", noteOrReason: "not green"} }
  return
}

How to build your own

  1. Name the roles. One name per seat. Exclusive if it holds state, non-exclusive if it's a pool.
  2. Draw the edges. Who sends to whom. An edge is a send_role_message {team, role: "X", text}, or a reply {message_id, text} to a message whose replyTo is "role:X".
  3. Pick the triggers. One inbox_idle wake routine per role that has sleeping holders. One cron routine for anything that needs liveness without a queue (e.g. CI polls).
  4. Open the composer. inbox-flows's Build-your-own card has a visual palette for roles and edges, and exports matching routine.yml + agent.yaml you drop into your editable context repo.

How to do this via MCP

There is no "shape" primitive. A shape is agent.yaml files (agent_create), routine.yml files (routine_create), and the sessions that register_role. Compose by writing those three. 

agent_create { name: 'worker', runtime: 'claude' }
routine_create { name: 'Wake the worker', agent: 'worker', mode: 'wake', task: '…' }
open_workspace { target: 'team-workspace', name: 'worker', agent: 'worker' }
