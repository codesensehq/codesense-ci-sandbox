Running overnight · hands-off loop

Set the loop at 22:00. Wake up at 07:00 to a morning summary and five open PRs. The factory ran six wake cycles while you slept, each triggered by inbox_idle, each isolated to its own worktree, each one honest about what it couldn't resolve.

This is the shape; the live factory/overnight.excalidraw canvas has the editable version — click the diagram to open it.

What makes overnight safe

  1. Routines don't need a human. inbox_idle triggers wake agents from the running daemon; no interactive host-agent needed for the build + review loop.
  2. Escalations don't block the loop. If a Builder hits a frozen-spec contradiction, it posts to resolver and claims the next story. The escalation waits for you in the morning.
  3. Lease-based claims. If a Builder dies mid-story, the claim times out and the next wake reclaims it.
  4. Caps. Every routine honors a maxConcurrent and a per-hour quota — the loop can't melt the Mac even if the inbox is deep.

Step-by-step: the 22:00 ritual

  1. Fill the inbox. Make sure the builder inbox has 5–20 claimable stories. Nothing is more disappointing than waking up to an empty DAG because every builder claim resolved into "waiting on upstream."

  2. Open the agent-dag. Confirm current Builders show green or amber, not red. A red session before you go to sleep stays red all night.

  3. Flip the overnight-wake routines on — enable the Builder wake + the Reviewer wake. Each fires when its agent sits idle with unread mail, so they cost nothing while the queues are empty.

  4. Set a scheduled morning summary. One routine at 07:00 drops a summary message in the analyst inbox: live sessions, PRs opened, escalations queued, red sessions. 

    # config/agents/mary-analyst/routines/morning-summary/routine.yml
id: morning-summary
name: Morning summary
mode: fresh
task: |
  Summarise the night: live sessions (list_sessions), PRs opened,
  escalations queued, red sessions. Send it to the analyst role
  with send_role_message, then call signal_done.
where:
  kind: team_workspace
triggers:
  - schedule:
      cron: "0 7 * * *"
      tz: UTC  # use your own IANA time zone, e.g. Europe/Berlin
policy:
  max_runtime: 30m
revision: 1

  5. Plug in. Close the lid gently (if you need to). If the factory shape is solo + remote, the mini carries on.

The morning check-in

Coffee first. Then, in order:

  1. Open the analyst inbox. Read the morning summary.
  2. Open the agent-dag. Scan for red (crashes) or amber (stalls).
  3. Open the resolver inbox. Answer the two or three escalations.
  4. Open the pipeline-graph. See which stories moved into Review.
  5. Review the first PR. The loop was never a replacement for your eyes on the merge.
How to do this via MCP 
routine_set_enabled { id: 'builder-wake', enabled: true }
routine_set_enabled { id: 'reviewer-wake', enabled: true }
routine_set_enabled { id: 'morning-summary', enabled: true }
