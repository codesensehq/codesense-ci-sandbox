Solo + remote · one Mac plus one or two remote machines

You've got a laptop. You've got an always-on Linux box in the closet (call it mini). Add it as a machine over SSH and you can send heavy work to it while your laptop keeps its fans quiet. Its sessions keep running when the laptop sleeps or you quit CodeSense.

This is the shape; the live factory/solo-with-remote.excalidraw canvas has the editable version — click the diagram to open it.

When to reach for solo + remote

  • You want to run overnight on something other than your laptop battery.
  • Your laptop needs to be portable and quiet; the mini can roar.
  • You want a build / review split: fast dev loop locally, long reviews on the mini.
  • You want a staging-shaped environment without any cloud dependency.

Private-account mode in one paragraph

CodeSense reaches the machine with ordinary OpenSSH and your own SSH setup (your SSH agent or a key file); it never asks for a key, password or token. It installs a small terminal server in your account there, which owns the machine's terminals, so they outlive your SSH connection. A private-account machine is yours alone: its agents use the same MCP tools, Inbox and team context as local ones once you turn on remote MCP control for it. Linux is the verified remote; another Mac over SSH may work but hasn't been checked. Full detail: Terminals & machines → Remote (private account).

Step-by-step: turn the mini into a Builder farm

  1. Add the machine. Open Machines (⌘⌥C) or run Add machine… from ⌘K. The first connection test shows the machine's host key fingerprint; confirm it and CodeSense pins it.

  2. Define your Builder agent once. It lives in the context repo, so the same definition launches on either machine. 

    # config/agents/amelia-builder/agent.yaml
id: amelia-builder
name: Amelia (builder)
runtime: claude
startup:
  - .claude/skills/bmad-build/
revision: 1

  3. Send its sessions to the mini with a routine whose where.machine is the machine's id (from list_machines): 

    # config/agents/amelia-builder/routines/builder-claim-remote/routine.yml
id: builder-claim-remote
name: Start a builder on the mini
mode: fresh
task: |
  Join the builder role with register_role, claim the waiting
  message with claim_role_messages and build the story it names
  with /bmad-build.
where:
  kind: team_workspace
  machine: <machine id>
triggers:
  - event:
      kind: role_pending
policy:
  max_runtime: 2h
revision: 1

  4. The agent-dag now shows sessions on both machines. Builder sessions light up on the mini while your laptop stays quiet.

⚠ Parity gap — event triggers need the laptop

Sessions already running on the mini keep going when the laptop sleeps or CodeSense quits. New ones don't start: a role_pending, inbox_idle or agent_done trigger is fired by the CodeSense app on your Mac. A routine moved onto the machine with routine_arm_on fires on the machine's own clock whether or not any Mac is open, but only on a schedule.

How to do this via MCP 
list_machines { orgSlug: '<owner/repo>' }
// → This Mac (machineId 'local') first, then shared and private machines

test_machine_connection { … }      // before the first connect
set_machine_remote_mcp_control { … }   // let its agents reach CodeSense

// A schedule that fires on the mini's own clock:
routine_arm_on { id: 'nightly-sweep', machine: '<machine id>' }
