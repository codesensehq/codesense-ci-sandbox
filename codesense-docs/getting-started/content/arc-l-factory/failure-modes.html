Failure modes

Running a factory means things fail. The question is whether the factory notices, recovers, and keeps going. This page is the honest inventory: what breaks, how CodeSense handles it, what you have to do.

The failure matrix

What breaks How CodeSense notices Automatic recovery What you do
Agent crashes mid-story
Rust panic, LLM 500, OOM 		Session marked failed; worktree write-lease released Next inbox_idle wake reclaims the story to another Builder Open the session log; patch the skill if the error is deterministic
Agent stalls (loops)
Infinite retry on a tool call 		agent-dag shades amber after 10 min with no worktree write None by default — stalls aren't crashes Close its tab with close_terminal_tab, then relaunch the agent
Machine goes offline
Mini unplugged; lid closed; wifi drops 		Host-agent heartbeat stops; sessions on that Mac marked offline None: the work waits until the Mac is back or you relaunch it elsewhere Bring the Mac back. Its worktrees are still on disk, so relaunch the agents there
Escalation stuck
Resolver inbox growing, nobody at keyboard 		Resolver inbox count climbs on home dashboard None — a human has to answer Open the resolver inbox; answer in batch
Routine fails to fire
cron expression typo; agent archived 		routines-console shows last-fire time > expected interval None Check routines-console; fix the expression; the next tick re-fires
Worktree lock contention
Two Builders racing on the same git lock 		agent-dag shows one Builder spinning on git worktree add Git's lock usually clears once the first operation finishes If it stays stuck, close the older agent's tab with close_terminal_tab
Context repo diverges
Two Macs committed to main concurrently 		Push rejected; the agent doing the sync rebases and retries (CodeSense never pushes) The agent reports report_context_sync {state: 'retrying'}; the status button shows it A file both sides changed opens a conflict card: Use mine, Use theirs, Keep both or Hand to ‹agent›
Loop sweep finds everything stuck
Deferred-work ledger growing unbounded 		bmad-loop-sweep output flags CRITICAL None — this is a planning signal, not an execution one Pause the loop; run bmad-correct-course; carry forward intentionally

The one failure mode CodeSense can't help with

A silently-wrong agent. The agent didn't crash. The DAG is green. The PR looks fine. The code is wrong. CodeSense can't catch this — only review can. Keep a human-reviewed PR as the merge gate, especially for anything that touches runtime behavior or stored state.
