10 composition recipes

Ten production shapes. Each one is an agent.yaml plus the routine.yml that lives under it — copy both into your context repo under config/agents/<agent>/, turn the routine on, done. Treat these as starting points: edit the schedule, swap the skill, add more Builder clones, tune to taste.

Validator notes

Every routine.yml below uses the real routine shape: it lives under its agent (no agent: key), writes its mode — wake for long-lived agents woken when mail waits (inbox_idle), start a new (fresh) for scheduled one-shot jobs — and carries its triggers and policy.max_runtime. Compare with the routine.yml schema. agent.yaml files follow the schema: id, name, runtime and revision are always present, and none lists the codesense MCP server, which every agent always has.

01 Overnight story-graph drain

N Builders 1 Scout 1 Resolver inbox_idle

Pre-fill the builder inbox at 22:00 with 10–20 claimable stories. The Builder fleet drains the queue overnight; the Scout watches for upstream drift; the Resolver inbox fills with escalations you answer with coffee.

02 Review-only farm (3 remote macs)

1 Triager 3 Reviewers (remote) inbox_idle

Your laptop is the Triager. Three remote Macs (minis, old laptops) host identical Reviewer clones. Review-only workloads parallelize cleanly: there's no shared mutable state and the LLM calls dominate the wall-clock time.

03 Spec-driven incremental

1 Analyst 1 Builder retro each cycle cron · 1h

An Analyst runs bmad-spec to distill the next slice; the Builder picks it up and ships it; a retrospective runs at the end of each cycle to update the spec. Great for research-flavored product work where you don't know the full plan yet.

04 Fire-and-forget feature

1 Builder 1 Reviewer cron · 10m single epic

The smallest recipe. One epic. One Builder. One Reviewer. No Triager, no Resolver — if the Builder escalates, it waits in the resolver inbox for you. The point of this recipe is low ceremony: a day's work in a couple of files.

05 Research sprint

N Scouts (fan-out) 1 Analyst (synthesis) cron · hourly

Many Scouts fan out over sources (release notes, upstream repos, support threads, telemetry) and write findings into the context repo. One Analyst wakes hourly and distills the pile into a brief. The output is a document, not a PR.

06 Bug-triage loop

1 Triager N Builders role-queue backpressure inbox_idle

The Triager reads incoming bug reports and routes them to builder — but with a cap. If the Builder queue is already at depth 10, the Triager holds new reports in a staging inbox. Backpressure keeps the fleet from overcommitting.

07 Hot-fix

1 Builder 1 Reviewer no sprint plan manual trigger

Production is on fire. You bypass the sprint plan: open a story, assign it priority: hot-fix, hand it to a dedicated Builder. The Reviewer gates the merge but doesn't block for lenses — just the verification lens. Reset to normal cadence after the fix lands.

08 Dogfood loop

1 Scout (runs the app) 1 Builder cron · 30m

The Scout boots the CodeSense dev build in a disposable workspace, runs a scripted "typical day" smoke test, and files any failure as a bug report in the builder inbox. The Builder loop drains those bugs against the running codebase.

09 Multi-repo epic

1 epic across 3 repos 3 Builders per repo cross-repo depends_on

One epic has repos: [A, B, C]. Each repo gets a dedicated Builder cohort. The epic's depends_on graph crosses repos, so a Builder in repo B waits on a story in repo A — the agent-dag shows the cross-repo chain.

10 Open-source contributor

1 Analyst (reads issues) 1 Builder (drafts PR) 1 Reviewer (gates) cron · 6h

Point this recipe at an open-source repo you want to contribute to. The Analyst reads community issues on a 6-hour cadence, picks a feasible one, files it as a story. The Builder drafts a PR. The Reviewer gates. Human approval before pushing to the upstream fork.

How to drop a recipe into your context repo

  1. Copy the agent.yaml block into config/agents/<agent>/agent.yaml. Create the directory if it doesn't exist.
  2. Copy the routine.yml block into config/agents/<agent>/routines/<id>/routine.yml — the path in its caption.
  3. Validate both: open the schema browser, paste, hit Validate.
  4. Open the agent in the Agents tab and turn the routine on in its Routines section (or routine_set_enabled).
How to do this via MCP 
// The agent block from any recipe above, as agent_create arguments
agent_create { id: 'amelia-builder', name: 'Amelia (builder)', runtime: 'claude', … }

// The routine block: write it to config/agents/amelia-builder/routines/builder-wake/routine.yml
// (routine_create takes a schedule as `when`; event triggers live in the file)

// Turn it on for this Mac
routine_set_enabled { id: 'builder-wake', enabled: true }
