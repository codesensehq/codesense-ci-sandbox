Local-only · all on one Mac

No network. No remote accounts. Just your Mac, N worktrees, and N agents happily working the same context repo. The simplest factory that ships, and the one you'll start with. When battery and fans aren't a concern — plugged in, on your desk — this shape beats anything fancier.

This is the shape; the live factory/local-only.excalidraw canvas has the editable version.

When to use local-only

  • You're on your main dev Mac and plugged in.
  • You want the lowest latency: inbox → agent wake is < 1s.
  • You haven't set up a private-account on any remote Mac yet.
  • You want to try a factory shape before deciding whether to invest in remote.

Switch to solo + remote the night you want the fans off while five Builders keep going.

What runs where

Every piece of the factory lives on disk under the standard CodeSense home. One Mac, four familiar directories: 

~/code/<org-context-repo>/               ← the context repo: agents, routines, team content
~/.codesense/users/<you>/                  ← app state: connected repos, private files, inboxes
~/code/<repo>-wt/<story-slug>/              ← per-story worktrees, beside each source clone
~/.codesense/logs/                          ← agent + session logs

Scale ceilings on one Mac

You'll hit three ceilings. In rough order:

  1. CPU under build. Three Builders running Rust compiles in parallel will warm the fans fast. Mitigation: cap Builder count at cores/2 while builds are hot.
  2. Memory per Claude session. ~800 MB resident per active agent. Six Builders + a Reviewer + a Resolver eats ~7 GB.
  3. Disk bandwidth on worktree creation. N parallel git worktree add on a cold repo serializes under the lock. Mitigation: create worktrees eagerly during sprint planning, not at claim time.
How to do this via MCP

Nothing special — the local-only shape IS the default. The MCP calls look like the massively-parallel page: agent_create, write a config/agents/<id>/routines/<routine>/routine.yml, open the agent-dag. No remote-account setup, no private-account dance.
