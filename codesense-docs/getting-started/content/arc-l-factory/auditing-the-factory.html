Auditing the factory

Two dashboards tell you the state of a running factory: agent-dag shows who's doing what right now, pipeline-graph shows what moved. Everything else — routines-console, agent-inbox-console — is a detail view off those two. Together they are the factory's control surface.

The two dashboards

agent-dag

Question it answers: what is every agent doing right now, and is any one of them stuck?

  • One row per agent session.
  • Columns: agent · Mac · story · worktree · last-check-in · status.
  • Statuses: running (green), stalling (amber, > 10m no write), escalated (purple), failed (red), done (grey).
  • One-click stop — the dashboard calls the page bridge's stopSession. (kill_agent is the sample epic's story, not a shipped tool.)

pipeline-graph

Question it answers: which stories moved through which phases, and where are the piles?

  • One node per story. Edges follow depends_on.
  • Status fill: todo / in-progress / review / done / blocked.
  • Click a story to see its full phase history (claim → build → PR → review → merge).
  • Hover a column to see the active sprint's backlog by phase.

What good looks like

  • agent-dag: most sessions green; a steady 1–2 amber in the mix; no red for > 10 minutes; worktree names consistent with story IDs.
  • pipeline-graph: stories moving right over time; the "review" column is not an endless pile; blocked stories have an escalation message in the resolver inbox.
  • Loop sweep output is a bounded number of carry-forwards per sprint; the ledger isn't growing.

What trouble looks like

  • agent-dag: every Builder stuck on the same story. You cloned agents without clearing the inbox — multiple Builders claimed before dedupe caught up. Fix: kill all but one, reset claims, re-wake.
  • agent-dag: red session, same stack trace, every wake. A deterministic crash in the skill. Fix: open the session logs, patch the skill, re-wake.
  • pipeline-graph: review column growing. Not enough Reviewers. Fix: clone a Reviewer, or temporarily have a Builder run bmad-review.
  • pipeline-graph: a blocked story with no escalation message. The agent exited without posting its blocker. Fix: read the session log, post the escalation manually, carry on.
How to do this via MCP

An agent reads the same state the dashboards draw:

list_sessions {}        // every running session, local and remote, with its story and unread mail
query_context { where: { kinds: ['story'] } }   // story status for the pipeline graph

A dashboard stops a session through its page bridge: codesense.invoke('stopSession', { … }).
