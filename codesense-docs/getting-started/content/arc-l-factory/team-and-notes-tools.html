Team, source repo and notes tools

Reference for the tools that create and organise teams, bind source repos and local clones, read the publish set, and read and write private notes.

How to read this page

org is an org slug written owner/repo. Team and source-repo admin tools make the same edit as the matching action in the app, and most return {status:"ok", data:{...}} or {status:"validation", message}; an unknown or archived team returns {status:"unauthorizedTeam"} on the source-repo tools.

Teams

create_team

Creates a team in an org, the same edit as the UI's New team. Pass org and name (a lowercase slug); optional parent nests it under an existing team (checked first, so a bad parent creates nothing) and activate: true then switches the app to it as set_active_team does. You are recorded as the creator. If the switch fails the team stays created with activated:false and an activationError. An invalid, reserved or duplicate name returns validation and writes nothing.

{
  "tool": "create_team",
  "arguments": {
    "org": "acme/context",
    "name": "engineering",
    "parent": "platform",
    "activate": false
  }
}

rename_team

Renames a team: its registry entry, content and installs move to the new name, and the UI carries its tabs and state over. Pass org, team (current name) and newName (a lowercase slug). An unknown team or an invalid, reserved or taken name returns validation and changes nothing.

{
  "tool": "rename_team",
  "arguments": {
    "org": "acme/context",
    "team": "engineering",
    "newName": "platform-eng"
  }
}

archive_team

Archives (archived: true) or unarchives (archived: false) a team: an org-wide, reversible retirement, the same edit as the UI's Archive. An archived active team is switched off in the UI. To remove the registry entry instead, see delete_team.

{
  "tool": "archive_team",
  "arguments": {
    "org": "acme/context",
    "team": "engineering",
    "archived": true
  }
}

delete_team

Deletes a team from the org's registry, the same edit as the UI's Delete team. Only the registry entry is removed; the team's content stays on disk and is git-recoverable. If it was the active team the UI falls back to another team.

{
  "tool": "delete_team",
  "arguments": {
    "org": "acme/context",
    "team": "engineering"
  }
}

set_team_parent

Sets or clears a team's parent (team nesting). Omit parent, or pass null, to make the team a root. An unknown team or parent, the team itself, or one of its descendants (a cycle) returns validation and changes nothing.

{
  "tool": "set_team_parent",
  "arguments": {
    "org": "acme/context",
    "team": "engineering",
    "parent": "platform"
  }
}

set_team_starter_page

Sets or clears the file CodeSense opens when the team has nothing open (landing_page: in teams.yml). path is required: pass a path relative to the team's content folder (guide/start.md) or an absolute path inside it, which must be an existing file, not hidden and not outside the folder; pass null to clear it (the team then falls back to README.md, README.html, then index.html). Leaving path out is refused. org and team name the team; omit both for the active team. The edit is a local working-tree change of the context repo; publish it to share it. The read-only CodeSense Docs is refused.

{
  "tool": "set_team_starter_page",
  "arguments": {
    "org": "acme/context",
    "team": "engineering",
    "path": "guide/start.md"
  }
}

set_private_items_use

Sets "Use my private items" for a team, the same per-team switch as the Private tab. Pass org, team and use. It changes which private files, agents and routines apply to that team, not what the user is browsing. An unknown or archived team is refused.

{
  "tool": "set_private_items_use",
  "arguments": {
    "org": "acme/context",
    "team": "engineering",
    "use": true
  }
}

Source repos

CodeSense never clones. Clone with git yourself, then bind the folder.

add_source_repo

Adds a source repo to a team. Pass org, team and exactly one of url (https, git@, host/owner/repo or GitHub shorthand owner/repo, tracked on the team) or path (an absolute folder on this machine, bound as the repo's local clone). A folder is tracked as the repo its upstream remote names, else origin, else local/<folder>; remoteName in the result says which. A folder inside a git repository must be that repository's root. Add by url and bind the clone later with attach_source_repo_path. A bad URL or folder, a duplicate or an invalid identity returns validation.

{
  "tool": "add_source_repo",
  "arguments": {
    "org": "acme/context",
    "team": "engineering",
    "url": "acme/app"
  }
}

attach_source_repo_path

Binds, or rebinds, a local clone to one of a team's source repos so worktrees, terminals and editor actions find its code. Pass org, team, repo (owner/repo, or host/owner/repo when the same owner/repo is on two forges) and path: the absolute path of a git working tree's root with a remote that names that repo. Remotes are tried origin, upstream, then the rest. A folder that is not a working-tree root (the error names the root to pick), has no remote, or has no remote naming the repo is refused. Rebinding replaces the previous clone.

{
  "tool": "attach_source_repo_path",
  "arguments": {
    "org": "acme/context",
    "team": "engineering",
    "repo": "acme/app",
    "path": "/Users/me/code/app"
  }
}

Publish set

get_publish_set

Reads the structured changes for the active context repo as a {buckets, general} publish set. It is read-only: nothing is committed, pushed or merged. Optional worktree (a registered id or name) uses that worktree's working tree against the merge-base of its branch and the clone's local main, including committed and uncommitted edits. Omit it, or pass clone, for the usual clone against GitHub.

{
  "tool": "get_publish_set",
  "arguments": {
    "worktree": "clone"
  }
}

Private notes

Notes are Markdown kept on this Mac only, never pushed or shared, each with local history. One org's notes are never visible from another. org (owner/repo) is optional on every notes tool: omit it for the org your session works in. Every reply names the org it used, so pass it back to stay on it. Replies are {status:"ok", data:{...}} or validation.

notes_list

Lists the person's private notes for one org, pinned first then most recently touched: notes:[{id, title, pinned, lastOpenedAt, updatedAt?, updatedBy?}]. Bodies are not included; use notes_read.

{
  "tool": "notes_list",
  "arguments": {
    "org": "acme/context"
  }
}

notes_search

Finds notes whose title or body contains query (case-insensitive). Optional limit (default 20). Returns hits:[{id, title, matched, snippet?}] with matched of title, text or both: title matches first, then body matches, most recently touched first.

{
  "tool": "notes_search",
  "arguments": {
    "query": "release plan",
    "limit": 10
  }
}

notes_read

Reads one note with its Markdown body. id comes from notes_list or notes_search. A missing note returns validation.

{
  "tool": "notes_read",
  "arguments": {
    "id": "<id from notes_list>"
  }
}

notes_create

Adds a private note. title is required; content (Markdown body), pinned, org and sessionId are optional. sessionId (your $CODESENSE_TAB_SESSION_ID) credits the note to your session; a remote session is always credited to its own tab, and a supplied sessionId must name the caller itself. The note is committed to local history and the Notes pane shows it at once. An unbound caller is refused.

{
  "tool": "notes_create",
  "arguments": {
    "title": "Release plan",
    "content": "# Release plan\n",
    "pinned": false
  }
}

notes_write

Changes a note. id is required, plus exactly one of content (the whole new body), append (text added on a new line at the end) or patch ({find, replace}, where find must occur exactly once in the body; read the note first), and/or title to rename. More than one of content/append/patch, no edit, or a patch matching zero or several times returns validation. Each change is committed with you as author, and anything the person typed before your write is committed first under their name, so notes_restore can undo you. A write that changes nothing reports changed:false.

{
  "tool": "notes_write",
  "arguments": {
    "id": "<id from notes_list>",
    "patch": {
      "find": "draft",
      "replace": "final"
    }
  }
}

notes_history

Lists who changed a note and when, newest first: revisions:[{commit, at, actor:{kind, name, ...}, change, summary, added, removed}] where change is create, write, restore, meta or delete. Optional limit (default 50). Asking for history first commits the person's pending typing. Read an old version with notes_read_at; bring it back with notes_restore.

{
  "tool": "notes_history",
  "arguments": {
    "id": "<id from notes_list>",
    "limit": 20
  }
}

notes_read_at

Reads a note's text as it was at one revision. commit comes from notes_history (at least its first 4 characters). Returns {org, id, commit, title?, content}, or validation for an unknown commit or a note that did not exist then.

{
  "tool": "notes_read_at",
  "arguments": {
    "id": "<id from notes_list>",
    "commit": "a1b2c3d4"
  }
}

notes_restore

Brings a note's body back to its text at one revision as a new change: the current text is committed first, so the restore can be undone the same way. id and commit are required; the title is left as it is. Returns changed:false when the text was already that. An unbound caller is refused, and a supplied sessionId must name the caller itself.

{
  "tool": "notes_restore",
  "arguments": {
    "id": "<id from notes_list>",
    "commit": "a1b2c3d4"
  }
}
