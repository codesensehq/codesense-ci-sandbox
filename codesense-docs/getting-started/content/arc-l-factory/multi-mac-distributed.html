Multi-mac distributed · several developers' Macs cooperating

Three developers. Three Macs. One team context repo. One triager keeps the whole thing in sync; each developer runs the roles that matter for the hour. Nobody has to know what the others are doing — the inbox does the choreography.

This is the shape; the live factory/multi-mac.excalidraw canvas has the editable version.

When to reach for multi-mac

  • You've got more than one developer on the same codebase.
  • You want to use each developer's spare cycles without a cloud build farm.
  • You want a shared triager so nobody duplicates work and nobody has to ask "what are you working on?"
  • You want to split roles by comfort: Alice loves reviews, Bob loves plumbing, Carol owns the dogfood sweep.

The shared triager rule

In a multi-mac shape, exactly one Triager agent is active at a time. The team context repo stores a triager-lease.yml; the triager routine checks the lease before claiming any dispatch message. If Alice's laptop goes offline, the lease expires in 5 minutes and Bob's Mac picks it up.

This is the only piece of state the team shares beyond git. Everything else — role queues, worktrees, agent-dag — is per-Mac, synced via the team repo.

Step-by-step: stand up a three-Mac factory

  1. Each developer joins the team. One clicks Create a team repo; the other two Connect existing team repo. The team repo lives in git — anywhere all three can push.

  2. Each developer trusts the others' Macs under the same private account. The Macs dashboard lists all six (two per developer if they each have a laptop + mini).

  3. One developer authors the team-wide routines under the team context. One Triager routine; one builder-wake; one reviewer-wake; one scout-wake. Every developer's CodeSense picks them up on git pull.

  4. Each developer picks which role to host. Alice runs Triager + Resolver + a Builder. Bob runs two Builders + a Reviewer. Carol runs a Scout + a Builder + a Reviewer. The agent-dag now has three columns.

  5. Human-in-the-loop moves between developers. A Resolver escalation lands in resolver; whoever is at the keyboard answers. The next escalation might go to someone else.

Expected drama and how CodeSense handles it

  • Carol's Mac goes offline mid-review. The reviewer inbox message's claim times out in 10 minutes; Bob's Reviewer picks it up on the next inbox_idle wake.
  • Alice and Bob both pull at the same instant. Git rebase on push; the second pusher re-pulls and tries again. CodeSense never writes to the team repo without a rebase-and-retry wrapper.
  • Someone edits a routine while a routine is firing. The daemon reads routines fresh at each tick; the change takes effect on the next wake.
