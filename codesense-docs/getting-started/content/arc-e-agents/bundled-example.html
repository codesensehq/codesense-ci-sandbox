A small agent with the tools it needs.

docs-helper is the bundled headless agent for reading CodeSense docs and running the manual offline update routine. Its agent file has no startup entries. The routine task names the update skill explicitly; the helper does not edit pages or add skills to the read-only docs.

The routine supplies the task

The bundled agent.yaml has no startup entries. Its manual routine lives at config/agents/docs-helper/routines/update-codesense-docs/routine.yml. There is no schedule. The each_mac routine starts disabled on each Mac; explicitly enable it before running it, as shown on the update page. With where.kind: team_workspace, a fresh run starts in the placed docs team's content directory. The task names the update-codesense-docs skill; no CLAUDE.md or requires: chain is needed to explain this behavior.

Check, update, report

The skill calls codesense_overview to check docs versions and state, then update_codesense_docs for the requested offline refresh. The tool resolves the canonical profile docs root independently of cwd. Before selecting the bundled HEAD and index it preserves local history, staged content, working edits and nonignored untracked files on a named local branch. Ignored machine state stays in place; collisions block the update.

The helper reports versions, state, preservation branch and changed paths, then calls signal_done. Codex agents pass their own sessionId to send_message and signal_done. If docs disagree with a live tool description, trust the tool and check docs.state.

Use the file as an example

Creating a context repo with “Start from the CodeSense example” deliberately leaves out docs-helper, its routine and the docs-update skill. They manage the canonical docs rather than an editable copy. To create an agent for your own team, use agent_preview and agent_create with a task and startup context appropriate to that team.

Try this now

Use agent_preview to check the shipped agent's launch fields, including its explicit Claude permissions. The agent-side call returns the resolved launch manifest without writing a definition; the example below shows the call to make.

How to do this via MCP 
// Get the shipped definition as the viewer sees it.
agent_get { id: 'docs-helper' }

// Preview these launch fields, including the shipped permission rules.
agent_preview {
  "name": "Docs helper",
  "id": "docs-helper",
  "description": "Keeps the CodeSense docs up to date and answers questions about CodeSense.",
  "runtime": "claude",
  "launch": "headless",
  "permissions": {
    "claude": {
      "allow": [
        "Read",
        "Skill(update-codesense-docs)",
        "mcp__codesense__codesense_overview",
        "mcp__codesense__update_codesense_docs"
      ]
    }
  }
}

// Start the helper in a team workspace.
open_workspace { target: 'team-workspace', name: 'docs', agent: 'docs-helper' }
