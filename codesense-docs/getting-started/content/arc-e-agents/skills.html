A skill is a directory.

A skill is a directory on disk. Its SKILL.md is the entry point; everything else next to it (helpers, examples, more markdown) comes along for the ride. Put it in your team's content/ and an agent gets it at launch when its context includes the path. The default context already does: a Claude agent gets all of .claude/skills/, a Codex agent all of .agents/skills/. List the directory in startup: as well when the agent can't work without it. From then on either the CLI picks it up by its description (auto-trigger) or you invoke it by name (/triage). Same file either way.

Four moves

1

Write SKILL.md

YAML frontmatter + prose. name is the slash command. description is the trigger line the CLI reads to auto-invoke the skill when the user's intent matches — write it as "Use when the user says …". Keep the body as the step-by-step the agent will follow once it's inside. 

---
name: triage
description: Sweep the inbox and file actionable issues. Use when the user says
             "triage the inbox", "clear mail", or asks for an inbox digest.
---

# Triage

You hold the triager seat. Pull a batch…
2

List the directory in startup:

Optional when the default context already carries the folder, but it makes the skill required: a startup entry that can't be found blocks the launch, and it counts toward what the agent provides. Trailing slash, content-relative, no globs. Everything inside comes with it — your helpers/, your examples/, whatever markdown you have for the agent to read mid-run. 

startup:
  - CLAUDE.md
  - .claude/skills/triage/        # claude agents
  - .agents/skills/triage/        # codex agents (same shape, different root)
3

Carry prerequisites with requires:

A skill's SKILL.md (or any file in startup) can declare paths it needs. Those come along automatically whenever the file does. Content paths only — no globs, no absolute paths. 

---
name: triage
description: …
requires: [.claude/commands/bmad-help.md, .claude/skills/mcp-primer/]
---
4

Invoke it, or let the description do it

Two ways in; same skill: 

# User-invocable — exactly matches the SKILL.md `name`.
default_prompt: /triage

# Auto-triggered — nothing in agent.yaml needed; the CLI matches the
# user's chat message against the SKILL.md `description` and invokes it.

A prompt starting with /name fails if the agent doesn't carry the skill. agent_preview lists what the agent's startup provides and warns (it never refuses) when the default prompt names something outside it.

User-invocable vs auto-triggered

User-invocable Auto-triggered
How it fires A prompt (chat, default_prompt, routine task) that starts with /name. The CLI reads the description and matches the user's intent — no explicit command.
What name is for The slash. Must match the frontmatter name: exactly. Still useful: the agent can refer to the skill by name in its plan.
What description is for Human-readable; shown in agent_preview's provides. The whole trigger. Write it so the CLI knows exactly when to reach for it.
Must the agent carry it? Yes — through its context or startup, or /name is "command not found". Yes — the CLI only matches against skills the agent carries.
Good shape "Do this specific thing when asked" — e.g. /triage, /manage-team. "Advisory posture the agent should slip into for a kind of work" — e.g. bmad-build.

Commands vs skills

A command is a single file — .claude/commands/<name>.md, for Claude only: Codex reads no project command folder. It can only be invoked by /name; it never auto-triggers. Use a command when the prompt body is short and self-contained. Everything bigger — multiple files, examples, a stepped procedure — is a skill. 

startup:
  - .claude/commands/bmad-help.md      # file  → command
  - .claude/skills/bmad-build/         # dir   → skill
