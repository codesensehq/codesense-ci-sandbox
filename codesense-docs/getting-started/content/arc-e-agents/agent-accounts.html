Run agents on the login you chose.

An account is one Claude Code or Codex login that CodeSense keeps in a private folder it creates. CodeSense never reads or sends the credentials; the CLI signs in and uses them itself. A launch uses a pinned account, else the Active account, else your own CLI login. A selected account that can't be used refuses the launch. It never falls back to your own login.

Which account a launch uses

  1. The launcher's account. A launch that names an account (override_account_id) must name the generation it saw. A change since then refuses it.
  2. The agent's pin. An account you bound one agent to.
  3. Active. One account per CLI that unpinned launches use. Active follows its account through a rename or a new sign-in. Only people change it; agents pin per launch.
  4. Your own login. Used only when no Active account is set for that CLI.

To learn which account agent X will use, call agent_get and read resolved.account. resolve_agent_account without an override ignores pins.

While an account is injected, CodeSense drops the credential variables the CLI would rank above its login (for Claude: ANTHROPIC_AUTH_TOKEN, CLAUDE_CODE_OAUTH_TOKEN, the Bedrock, Vertex and Foundry switches, and ANTHROPIC_PROFILE; for Codex: CODEX_API_KEY). A launch on your own login keeps them.

Refusal reasons and their fixes

ReasonMeaningFix
detachedThe account was disconnected.Reattach it, or pick another.
auth-requiredThe login is not signed in (it expired, or sign-in was not finished).Sign in to the account again.
provider-mismatchThe account is for the other CLI.Pick a Claude account for Claude, a Codex one for Codex.
account-missingThe account no longer exists.Pick another account, or clear the selection.
generation-mismatchThe account changed after this launch was prepared.List the accounts and retry with the current generation.
required-missingNo account is set up for this CLI.Add one and sign in.

A signed-in account whose login has gone is noticed when accounts are listed (at most once every ten minutes per account) and after a failed Codex usage poll, and then shows as needing sign-in. An account that was in error and now verifies goes back to ready.

The MCP tools

  • list_agent_accounts lists attached accounts. {"includeDetached": true} adds detached ones, marked by detachedAt.
  • get_active_agent_account reads the Active selection for one CLI.
  • resolve_agent_account previews what a launch would use. A refusal carries the reason and, when you passed an override, requestedAccountId. It never returns a home or credentials.
  • set_active_agent_account is for people only; it needs the interactive account-management capability.

Spend caps for accounts' agents are in Spend caps.
