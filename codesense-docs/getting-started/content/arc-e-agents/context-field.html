From a path to a seated session.

You wrote a startup: list. The context resolver is the code that turns that list into a real set of files on disk a claude or codex run can open. It walks your team chain once per entry (your team, then its parent, then the root), takes the first hit, and records which team gave it to you. If every team misses, the agent_preview reply names the entry as a resolve error and nothing is written for that launch. There's no partial-success mode: every path in startup either resolves or the launch refuses.

Five jobs

1

Build the team chain

team_chain starts at your active team and climbs the parent pointer until it reaches a team with no parent — the root. Short list, in order: [<team>, <parent>, …, <root>]. A cycle in parents is caught by the validator long before the resolver sees it.

2

Resolve each entry, first hit wins

For every path in startup, the resolver asks each team in the chain, in order: do you have this file or directory under your content/? The first one that does supplies it. Teams never merge — a skill in the parent and a same-named skill in your team don't blend; the child wins and the parent's copy is ignored.

3

Pull in requires:

If a resolved entry's frontmatter declares requires:, each required path goes through the same team-chain walk. Required paths that themselves require things recurse, with a fixed depth cap and dedup on the way. A required path that no team has is a resolve error naming the parent that asked for it.

4

Dedup & copy in

Same path showing up twice (once from startup, once as a requires:) is kept once; identity is the final content-relative path. Then launch preparation copies the resolved files into the workspace for the CLI to open normally: one diff against what is already there and one batched copy. It never overwrites a file the repo tracks or a copy someone edited there (those are reported as kept). In a source-repo worktree the copied paths go into the clone's .git/info/exclude, shared by all its worktrees, so they stay out of your commits; a team-workspace launch adds no exclude. Nothing updates them afterward. An agent that needs more calls hydrate_worktree or hydrate_story.

5

Return a trace

Every call to agent_preview returns a manifest that lists each resolved entry, which team supplied it, its size, and which requires: edges it pulled in. The agent-preview dashboard renders this trace as a table (same data as the one below).

Worked example: docs-helper

The shipped helper has no explicit startup entries. Its native CLI permissions allow the tools needed for the manual offline update task:

id: docs-helper
name: Docs helper
description: Keeps the CodeSense docs up to date and answers questions about CodeSense.
created_by: codesense
runtime: claude
launch: headless
permissions:
  claude:
    allow:
      - Read
      - Skill(update-codesense-docs)
      - mcp__codesense__codesense_overview
      - mcp__codesense__update_codesense_docs
revision: 2

The CodeSense MCP bridge and the launcher's CLI login are supplied by the runtime. The manual routine's task explicitly names the update-codesense-docs skill; it does not depend on a CLAUDE.md or requires: chain. A local team_workspace routine prepares the agent's resolved context in its own scratch directory, including the default .claude/skills/ when no explicit context is declared. Shared team content stays unchanged. See fresh routine context and scratch files for the lifecycle and a projection example.

How the resolver fails

Every failure mode is deliberate — the resolver never silently drops an entry.

  • No team has the path. agent_preview returns a resolve error naming the missing entry and the chain it walked. Nothing is copied.
  • Path escapes content/. An entry with .. or an absolute path never reaches the resolver — the validator rejects it on save. If you push one in by editing the file on disk, startup fails with invalid startup entry.
  • Overlap with an earlier entry. .claude/skills/ followed by .claude/skills/docs/ is also rejected on save — overlap would make the trace ambiguous. Pick one.
  • MCP server missing from the team's .mcp.json. mcp.servers: [slack] with no slack in the team's config is a warning in agent_preview (so you can still save the agent) but the launch refuses the server with unknown MCP server.
