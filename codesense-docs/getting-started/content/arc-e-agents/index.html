An agent is a small file.

You've got a job you want a Claude or Codex to do over and over — triage inbound, build the next story, review a PR, keep a dashboard fresh. CodeSense has no agent library and nothing to install. An agent is a small file in your team's context repo at config/agents/<id>/agent.yaml that says which runtime, what it starts with, which MCP servers it can reach, and what it may do. Launch it from a story, a routine or an agent's open_workspace call, on This Mac or a remote machine, in a terminal tab or headless. Every launch starts a session with the same posture; a routine in wake mode hands its task to a live session instead.

The starters

CodeSense ships read-only agents everyone has: builtin/claude (Claude) and builtin/codex (Codex), plus their unattended twins builtin/claude-unattended and builtin/codex-unattended, which run without asking for permission and are what a headless launch that names no agent runs. They live in the app, not in your context repo. Each one runs its CLI with its defaults and your own login — no extra args, no MCP server beyond the bridge, the CLI's own permission config, no default prompt. Each starts with what CodeSense needs plus the team's root CLAUDE.md or AGENTS.md when the team has one. You can't edit them ("built-in agent — Copy to Mine to customize"); to customize one, copy it and change the copy.

Four moving parts, one file

Runtime

claude or codex. The CLI that runs when you launch. Each user runs the agent with their own CLI login; nothing in agent.yaml binds an account.

Startup

An ordered list of content paths. The team's CLAUDE.md, the skills the agent needs, the slash commands its default prompt uses. Each is a file or a directory; there are no skill: or command: keys.

MCP servers

Which servers from the team's MCP config the agent gets. The CodeSense bridge is always there — never list it. Default: none beyond the bridge.

Permissions

The runtime's own permission config, enforced by the CLI and passed through verbatim. Claude takes {allow, ask, deny, …}; Codex takes {approvalPolicy, sandboxMode}.

The same file also takes args (appended to the CLI's argv), launch (foreground or headless), context (the content sets a workspace gets), default_prompt, avatar, allowWake and resumeAfterRestart. See agent.yaml for every field.

How to do this via MCP

Every lifecycle action on an agent has a matching MCP tool. The four you'll reach for most: 

// List agents the team can see — starters, team agents, your Only-me ones.
codesense.invoke('agent_list', { scope: 'all' })

// Preview a definition. Returns manifest.errors + warnings + resolved paths.
codesense.invoke('agent_preview', { name, runtime, startup, mcpServers, permissions })

// Create it, team-scoped by default. Pass scope: "personal" + org for Only me.
codesense.invoke('agent_create', { name, runtime, startup, dryRun: false })

// Update it. Pass the revision you last read as baseRevision; a conflict
// reply means something else changed it since you read it.
codesense.invoke('agent_update', { id, baseRevision, startup, permissions })

See mcp-explorer for the full tool catalog and schema-browser → agent.yaml for every field.
