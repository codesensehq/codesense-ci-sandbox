Instructions ride the team chain.

CodeSense ships no "system prompt" of its own. The agent's posture comes from your team's root instructions file: CLAUDE.md for Claude agents, AGENTS.md for Codex. One place to put "we review every PR before merging", "never force-push", "the house style is Rust 2024 edition" — and every agent you launch picks it up. You never list it on each agent; agent.yaml names it once in startup: and the resolver finds it.

How it gets in

1

List it first in startup:

Just the bare name. The resolver treats CLAUDE.md and AGENTS.md as team-chain paths — never a file in your working directory, never an absolute path. Listing it first keeps the posture ahead of per-skill rules. 

startup:
  - CLAUDE.md          # claude agents
  - .claude/skills/triage/
2

Team-chain walk

Teams can have a parent_team:. At preview and launch time CodeSense builds the chain [self, parent, grandparent, …, root] (up to 64 levels, no cycles) and the resolver reads the first match it finds. A sub-team can add its own CLAUDE.md to shadow the parent's — first hit wins, no merge. Rewriting parent_team at the sub-team level is how you specialize. 

# teams.yml
- name: Backend
  parent_team: null         # root instructions live here
- name: Auth
  parent_team: Backend      # inherits it if Backend shares it, unless Auth adds its own
3

Codex twin

Codex agents follow the exact same walk for AGENTS.md. The two files are twins, not synonyms — startup: for a claude agent should list CLAUDE.md; a codex agent should list AGENTS.md. agent_preview warns when the pair is crossed.

4

Missing is fine

A path no content layer has is normally a manifest error, but CLAUDE.md and AGENTS.md are the one exception: if no team on the chain has one, the agent simply starts without it — same posture as the shipped starters. You get a warning the first time, not a refusal.

What goes in it

Think "team norms", not "task instructions":

  • House style. "Rust 2024 edition. Prefer ? over .unwrap()."
  • Review posture. "Every PR gets a human reviewer role before merge."
  • Hard rules. "Never force-push to main. Rebase feature branches with --force-with-lease."
  • Where things live. "Story files live in _bmad-output/<epic>/stories/."
  • Who to ask. "Decisions and escalations go to the resolver role via bmad-loop-resolve."

Keep per-task knowledge in the skills (SKILL.md) the agent picks up for that job. The team root is the thing you want every session to know.

How much is too much

CodeSense doesn't cap CLAUDE.md, but agent_preview and agent_create return a manifest.totals with the byte count the agent will load. A 50 KB CLAUDE.md gets a warning, not a refusal; the user decides. Rule of thumb: team norms fit comfortably in 5–10 KB. Everything project-specific goes in skills.

Try this now

Resolve CLAUDE.md against the active team's chain. The dry-run shows which team the file came from — or that no team on the chain has one. Read-only.

How to do this via MCP 
// Which team on the chain has CLAUDE.md? Preview is the honest answer —
// it runs the same resolver as a real launch.
agent_preview {
  name: 'probe', runtime: 'claude', startup: ['CLAUDE.md'],
}
// → { manifest: { entries: [{ path: 'CLAUDE.md', source: 'teams/backend/...', bytes: 4821 }] } }

// The chain itself (which teams, in order): describe_setup lists each team and its parent.
describe_setup {}
