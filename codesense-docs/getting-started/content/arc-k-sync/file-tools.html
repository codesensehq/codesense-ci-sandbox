Content file tools

Reference for the tools that create, read, move, delete, list and search context content files, and refresh the frontmatter cache.

How to read this page

Paths are absolute context-layer paths. Edits here change team content only; copies already in worktrees are not touched, because nothing syncs a worktree on its own. Use hydrate_worktree to update a worktree.

Create, read, move and delete

create_content_file

Creates a content file at an absolute own-team content path; content defaults to empty. onCollision is fail (the default) or keep-both, which picks the first available numbered sibling. Returns {path}, the path actually created. It is the MCP twin of files.create.

{
  "tool": "create_content_file",
  "arguments": {
    "path": "/abs/context/_team/engineering/content/notes/plan.md",
    "content": "# Plan\n",
    "onCollision": "fail"
  }
}

read_content_file

Reads a content file by path. Reads use the calling session's team, so an ancestor file must be shared with that child. Returns {text?, bytesUrl?, size, truncated, sha256}; maxBytes is capped at 1.5 MB, and bytesUrl streams large or binary files through /viewer. The MCP twin of files.read.

{
  "tool": "read_content_file",
  "arguments": {
    "path": "/abs/context/_team/engineering/content/notes/plan.md"
  }
}

move_content_file

Renames or moves a context-layer content file or directory in team content, keeping content and frontmatter (including story_id). It is one explicit two-path call, not a delete plus create. Returns {fromPath, toPath}.

{
  "tool": "move_content_file",
  "arguments": {
    "fromPath": "/abs/context/_team/engineering/content/notes/plan.md",
    "toPath": "/abs/context/_team/engineering/content/notes/roadmap.md"
  }
}

delete_content_file

Deletes a context-layer content file or directory in team content. It is git-backed, so deleting a committed file can be undone with git. Returns {deletedPath}. To remove an item from a named context by logicalName, see remove_from_context.

{
  "tool": "delete_content_file",
  "arguments": {
    "path": "/abs/context/_team/engineering/content/notes/old-plan.md"
  }
}

List and search

list_context_content

Lists the content items in one context by its stable id (personal:<org>, all-orgs, team:<org>:<team> or team-repo:<org>:<team>:<owner>/<repo>), scoped to the active org. Each item has a logicalName, which feeds move_between_contexts, copy_between_contexts and remove_from_context, and a path. An empty context returns an empty list. Without context it navigates files by scope, team, storyId, agentId and dir, like files.list.

{
  "tool": "list_context_content",
  "arguments": {
    "context": "team:acme:engineering"
  }
}

query_context

Finds context files by metadata across synced orgs: where, filters, match, relationships, text, sort, select, groupBy, limit and cursor, all optional. Returns rows with id, path, org, team, layer, kind, title and fields. Private items come back only for the one org you name. Text results rank by title, then heading, then body coverage. The full filter and ranking rules are in the served description. For listing one context's items by logicalName, use list_context_content.

{
  "tool": "query_context",
  "arguments": {
    "where": {
      "orgs": [
        "codesense/docs"
      ]
    },
    "text": "refresh_frontmatter_cache",
    "limit": 5
  }
}

refresh_frontmatter_cache

Refreshes the frontmatter cache for a context-layer file after a non-CodeSense writer (such as an agent's own filesystem write) changed it; otherwise open_workspace can miss a story that is physically present. It is not needed when writing through CodeSense's own file APIs. Returns {path, team, refreshed, storyId, previousStoryId?}.

{
  "tool": "refresh_frontmatter_cache",
  "arguments": {
    "path": "/abs/context/_team/engineering/content/stories/DEMO-1.md"
  }
}
