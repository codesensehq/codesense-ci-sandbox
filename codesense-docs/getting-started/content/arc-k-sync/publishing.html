Publishing — getting context to GitHub

Publishing has two halves. A workspace edit goes to team content on this Mac (Publish, or reverse_sync_worktree). Team content goes to GitHub when an agent commits and pushes the context repo. CodeSense does the first and shows you the second; it never commits or pushes itself.

What publishing means

  1. Workspace → team content. An agent's edit in its worktree reaches the team's content on this Mac with preview_reverse_sync_worktree then reverse_sync_worktree. Edits waiting in workspaces show as the scope row's N unsaved counter, with Publish and Discard for each. Nothing is committed.
  2. Team content → GitHub. You ask an agent ("commit and push the team context"). It reads the publish set with get_publish_set, runs git itself, and calls report_context_sync so the status button shows how it went.

The agent decides the commit message, the branch and whether to open a pull request, the same way it would for source code. You can tell it how you want that done, or write your own skill under .claude/skills/.

The publish set vs workspace edits

These two lists look similar; they aren't the same thing. Reading them side by side is often the fastest way to see where you are:

List Baseline Scope What clears it
Workspace edits (preview_reverse_sync_worktree, N unsaved) Team content Worktree reverse_sync_worktree, Publish or Discard
Publish set (get_publish_set, the status button's ↑ count) origin/main Context repo An agent commits and pushes

An empty preview_reverse_sync_worktree means your worktree's edits are in team content. An empty publish set means the context repo matches GitHub. You're fully in step only when both are empty.

A worked moment

You finished DEMO-1. preview_reverse_sync_worktree comes back empty; the status button shows ↑4.

1
Look first. Click the status button. The Changes view lists the four files, each opening as a redline against the last pushed version.
2
Ask an agent. "Commit and push the team context, one commit for DEMO-1." The agent calls get_publish_set, writes the commit and pushes.
3
It reports. The agent calls report_context_sync with state: 'ok'. The ↑ count goes back to zero and the button reads synced.

Local vs remote

The push runs wherever the context repo's clone is, usually your Mac. An agent on a remote machine sends its workspace's edits back with reverse_sync_worktree, which writes team content on this Mac; an agent here then commits and pushes. See also Arc H · 13 Ship.

How to do this via MCP

Agent-side equivalent 
// What GitHub doesn't have yet. Read-only.
get_publish_set {}
// Then run git yourself: git add, git commit, git push.
// Tell the status button how it went.
report_context_sync { state: 'ok' }
