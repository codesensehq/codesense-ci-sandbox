Arc K · Sync & agent-driven git

Your context repo moves. CodeSense never pushes, pulls or merges.

Every planning doc, agent, routine, story, and dashboard lives in your context repo — an ordinary git tree you own. CodeSense reads and writes files there and reads its git status and history; the commit, push, pull and merge are done by an agent you ask, with the same git and gh you use. One flow in, one flow out, one card per conflict. No hidden commits. No surprise pushes.

What this arc teaches

CodeSense is a context editor, not a git client. It copies context into a worktree when an agent starts there and when an agent asks, and nothing moves in between. The sync direction you want determines which call you reach for, or what you ask an agent:

  • Context → worktree (hydrate) — an agent gets what its definition declares when it starts, and calls hydrate_worktree or hydrate_story for more. You never run git pull.
  • Worktree → context (reverse-sync) — you edit a file in a worktree, then an agent previews and publishes it with reverse_sync_worktree. You never run git add.
  • Context ⇄ remote (push / pull) — you ask an agent to commit and push, or to pull. It runs git and reports with report_context_sync. A conflict opens a card per file: Use mine, Use theirs, Keep both, Hand to ‹agent›, Compare.
  • Reorientation — the status button (⎇ branch | ↑N ↓M) is the "where am I?" entry point. A click opens the Changes view.

Every direction has one call or request, one place in the app, one worked example. The pages below walk each one in order; after that, search finds the one you want.
