Hydration — context into worktree

Hydration is the direction in: team content is copied into a workspace. It happens at two moments only: when an agent starts there (it gets what its Agent definition's context declares), and when an agent calls hydrate_worktree or hydrate_story for more. Nothing copies files into a workspace in the background.

What hydration does

A worktree is a focused place to work on one story. It doesn't want every spec, retro and routine your team has written. So a workspace gets only what its agent needs:

  • At launch. The agent's definition declares its context (for example CLAUDE.md and .claude/skills/). CodeSense compares the workspace with that list once and copies what is missing or out of date in one batch.
  • On request. An agent calls hydrate_worktree with paths or sets, or hydrate_story with a storyId to bring a story's epic.

Every copy is hidden from git through .git/info/exclude and recorded as managed. A file you edited, or one CodeSense didn't write, is kept and reported, never overwritten. A later change to team content does not reach the workspace until the next launch or the next call.

What hydration doesn't do: it never takes the workspace's edits back (that is reverse sync), never writes a file the repo tracks, and never removes a file unless the call passes prune: true, and then only unedited copies under that call's paths.

A worked moment

You asked a Builder to pick up DEMO-1.

1
Worktree created. CodeSense makes feat/DEMO-1 as a git worktree against the source repo. It carries only the source tree.
2
Agent starts. The Builder's definition declares CLAUDE.md and .claude/skills/. CodeSense copies those in, and the agent's startup note says how many files it got and which it kept because you had edited them.
3
Agent asks for more. The Builder needs the epic's spec, so it calls hydrate_story with storyId: "DEMO-1". The epic dir lands in the worktree.
4
Team content changes. A teammate updates the spec. The Builder's copy stays as it is until the Builder calls hydrate_story again.

Local vs remote

The same calls work for a workspace on a machine: pass target: {kind: "remote", machineId, workspaceHandle}. CodeSense compares in one manifest call and sends the files in one batch. Neither workspace needs to be a clone of the context repo; only the source repo is a clone.

How to do this via MCP

Agent-side equivalent 
const target = { kind: 'local', codeRepoPath: '<worktree>', sessionId: '<session>' }

// Bring named files or folders in.
hydrate_worktree { target, sets: ['.claude/skills'] }

// Bring a story's epic in.
hydrate_story { target, storyId: 'DEMO-1' }

// What is here, and where did it come from?
list_hydrated { target }
