Write your own sync skill

CodeSense never syncs on its own. A workspace gets context when it is created and when an agent starts in it; anything more is an MCP call an agent makes. CodeSense doesn't install a sync skill. If you want /sync-style shortcuts, write a short skill on top of the calls below. Start from the example and make it yours.

Hydrate or publish?

You want to Direction Call
Bring named team files or folders into the workspace in hydrate_worktree with paths or sets
Bring a story's epic into the workspace in hydrate_story with storyId
See what a publish would write out · read-only preview_reverse_sync_worktree
Publish the workspace's edits to team content out reverse_sync_worktree
Add one new file to team content and hide it from git out route_file_to_context (undo with unroute_file_from_context)
Check or stop a long operation — context_operation_status, cancel_context_operation
See what CodeSense copied into the workspace read-only list_hydrated

Hydrate when the agent needs something the team has and the workspace doesn't. Publish when the workspace has something the team should have. A hydrate never publishes. A publish never changes the workspace's files: it only records what it published as managed and hides newly published files from git with a .git/info/exclude entry.

Safety defaults

  • Preview first. Call preview_reverse_sync_worktree with the same inputs, show the user the result, and publish only after they agree.
  • No deletes by default. A publish never removes a team file unless you pass includeDeletes: true. Without it, the removals come back in withheldRemovals.
  • Prune is scoped. prune: true on a hydrate removes only unedited copies under that call's paths or sets, never anything outside them. With neither, the scope is the runtime defaults (CLAUDE.md, .claude/{commands,hooks,agents,skills}, AGENTS.md, .agents/skills).
  • Edits are kept. A hydrate keeps a file you edited and reports it. Pass overwriteModified: true only when the user asks to discard their edits, and always with paths naming exactly those files.
  • Conflicts are never written. When a team file changed since it was copied, the publish skips it and returns it in conflicts. To resolve one, follow the example's recovery steps: save your edit aside, take the team's version with a hydrate_worktree scoped by paths with overwriteModified: true, re-apply, and preview again.

A minimal skill

A skill is a markdown file the agent reads. This one is enough to publish safely:

---
name: context-sync
description: Pull team context into this workspace, or publish its edits back after a preview.
---

Target: {"kind": "local", "codeRepoPath": "$PWD", "sessionId": "$CODESENSE_TAB_SESSION_ID"}

- To pull: call hydrate_worktree with the paths or sets the user named.
- To publish: call preview_reverse_sync_worktree, show the result, ask,
  then call reverse_sync_worktree with the same inputs.
- Never pass includeDeletes, prune or overwriteModified unless the user asked,
  and pass overwriteModified only with paths naming the files.

The full example covers stories, routing one file and long operations: examples/skills/context-sync/SKILL.md.

Use the example

1

Copy it into your context repo

Copy examples/skills/context-sync/ into your context repo's .claude/skills/. The copy in these docs is read-only and is never installed.

2

Adapt it

Delete the "Example from the CodeSense docs" sentence from its description, then change the name, the trigger phrases and the folders your team pulls most. Keep the preview step.

3

Give it to your agents

Add .claude/skills/context-sync/ to an agent's context, so it arrives when that agent starts.
