Conflicts — one card per file

A conflict is what happens when both sides moved: you (or an agent) edited a file in team content, and a teammate pushed a different edit to the same file. The agent doing the pull stops on it, and the status button shows a third count. Each conflicted file gets a card: you pick a side, hand it to an agent, or compare first. CodeSense writes the side you chose; the agent finishes the merge or rebase.

What the card offers

Click the status button when it shows a conflict and a card opens for each file, saying who changed each side and when. The choices:

  • Use mine — keep your version of the file.
  • Use theirs — take the version from GitHub.
  • Keep both — keep yours, and save GitHub's beside it as ‹name› (GitHub).‹ext› so you can merge them by hand later.
  • Hand to ‹agent› — ask one of the team's agents, through its inbox, to merge the two edits. Use this when both sides matter, for example two people tuning the same agent's prompt.
  • Compare — open the file's changes before you decide.

Settling a file writes the side you chose and stages it. The agent doing the sync finishes the merge or rebase, then reports with report_context_sync.

A worked round-trip

You've been tuning config/agents/reviewer/agent.yaml to speak less. Your teammate was tuning the same file to speak more, and pushed first. When an agent pulls the context repo for you, git stops on that file.

1
See it. The status button shows a conflict count. Click it; the card for agent.yaml names your edit and your teammate's.
2
Compare. The two sides differ in one place:

MINE

defaultPrompt: |
  Be concise. Keep responses
  under three lines unless
  the user asks for depth.

THEIRS

defaultPrompt: |
  Be expansive. Teach from
  first principles; show
  your work at every step.
3
Decide. Your tuning wins this round: Use mine. If you wanted parts of both, Hand to ‹agent› would ask an agent to write the merged file instead.
4
The agent finishes. The file is written and staged. The agent completes the merge or rebase, pushes, and calls report_context_sync. The conflict count goes away.

What CodeSense never does

  • Never picks a side for you.
  • Never commits, continues the merge or pushes. Settling a file is a file write and a stage; the agent doing the sync does the rest.
  • Never hides a stalled merge. A merge or rebase left untouched for 10 minutes shows as failed on the status button.

Local vs remote

The conflict lives in the context repo's clone, usually on your Mac, so the card is on this Mac's status button. Workspaces on remote machines don't hold a git copy of team content; their edits come back with reverse_sync_worktree, which shows a preview first. See reverse sync and publishing.

How to do this via MCP

Agent-side equivalent

An agent reads the same conflicts the card shows, and reports while it works: 

// Branch, ahead/behind, and conflicts: [{path, mine, theirs, lastWriter}]. Read-only.
context_repo_status {}
// While the merge is open, and when it's done.
report_context_sync { state: 'syncing', progress: 'Merging 1 conflict' }
report_context_sync { state: 'ok' }
