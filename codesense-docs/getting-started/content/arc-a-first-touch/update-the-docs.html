Update the docs

These pages ship inside the app. An explicit update selects the running app's bundled docs offline, preserving local work first. Untouched older copies also refresh automatically at startup when a newer app bundle arrives.

Check the version first

Ask an agent to call codesense_overview. Its docs section reports bundledCommit, placedCommit, appVersion, state and an action. The state is current, behind, modified, behind-and-modified or missing; unreadable docs report an error. Behind means the placed commit differs from this app's bundle. It does not promise a newer online release.

Run the manual helper

The update-codesense-docs routine belongs to docs-helper in the docs team. It is manual by design, with no schedule. As an each_mac routine it starts disabled on this Mac. When you choose to use it, explicitly enable it here, then fire it with routine_run_now. Enabling it does not add a schedule. Each run starts a fresh helper in the team's content directory. The task loads the update skill, checks the overview, calls update_codesense_docs, and reports the result with signal_done.

This works from another active project. routine_list {} lists all synced teams' routines; it has no org/team filter. Choose the returned row with org: codesense/docs, team: getting-started, and name: Update CodeSense docs. Copy that row's qualified id into the following calls:

routine_list {}
routine_set_enabled {"id":"<returned id>","enabled":true}
routine_run_now {"id":"<returned id>"}
routine_runs {"id":"<returned id>"}

When CodeSense launched you, you may also pass your own sessionId to the enable and run-now calls. routine_run reads an existing run by runId; it does not launch a routine.

The update tool always targets the canonical docs checkout for the active profile, independently of the helper's working directory. Any agent can call the tool directly when the user requests a refresh.

What happens to local work

A current clean copy is a no-op. For a replacement, the tool creates a named local preservation branch containing HEAD history, a staged-content snapshot when needed, and a working snapshot including tracked deletions and nonignored untracked files. It then selects the bundle's HEAD and index. The result reports preservationBranch and changedPaths.

Ignored machine state stays available. An update that would overwrite or delete unsaved local content is refused. If a later step fails, keep and report the preservation branch before resolving the error. No network, private remote or credentials are used.

From an agent

codesense_overview {}
update_codesense_docs {}

Report the versions, state, canonical root, preservation branch and changed paths. Trust live tool descriptions if a doc disagrees, and check docs.state. Codex agents pass their own session_id to send_message and sessionId to signal_done.
