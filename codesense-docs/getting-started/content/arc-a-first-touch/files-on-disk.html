Files on disk

CodeSense owns two spots on your Mac: ~/.codesense/ for its own runtime state and ~/CodeSense/ for the editable context repos you create. Your source repos stay wherever you clone them. Here's the full tree, with every path labelled by who writes it and what for.

The split is deliberate: ~/.codesense/ is CodeSense's — delete it and the app rebuilds it from scratch on next launch. ~/CodeSense/ and anywhere else you choose to Connect from is yours — delete it and you lose your work. CodeSense never writes into one of your source repos, and it never puts a user-facing file under ~/.codesense/ except these docs.

Path reference

Under ~/.codesense/ (CodeSense owns these)

Path What it is
~/.codesense/bin/ Managed binaries CodeSense drops in a known spot — git, the codesense-bridge, occasional helpers. Nothing of yours ever lands here.
~/.codesense/cache/frontmatter-cache.json Warm-start cache for the viewer's frontmatter index. Safe to delete; CodeSense regenerates it on the next watch pass.
~/.codesense/runtime/heartbeat.json Liveness file refreshed on an interval. Other processes read it to tell if CodeSense is up.
~/.codesense/mcp.sock The Unix socket agents connect to for MCP. 0700 so only your user can speak.
~/.codesense/http.port Chosen port for the local HTTP sidecar. Not a secret, just a lockfile.
~/.codesense/servers.json Registry of local MCP servers CodeSense exposes.
~/.codesense/users/<id>/codesense-docs/ The read-only docs org you're reading right now, placed by the installer.
~/.codesense/users/<id>/org_bindings.yml This Mac's bindings: which org names map to which folder paths.
~/.codesense/users/<id>/context-attachments.yml Where each context repo you connected lives. The repos themselves stay in the folders you cloned or created them in; CodeSense doesn't clone or move them.
~/.codesense/users/<id>/sample-source-repo/ The committed sample source tree the doc examples point at. CodeSense places it at launch, next to these docs.

Under your home (your editable context repos)

Path What it is
~/CodeSense/<org>/ The default parent folder the Create sheet suggests. You can point it anywhere — this is just the macOS folder picker's starting dir.
~/CodeSense/<org>/org.yml Marks the folder as a CodeSense context repo and holds its id and name. Next to it, people.yml and teams.yml. See the org.yml schema.
~/CodeSense/<org>/<team>/content/ A team's files: stories, notes, dashboards, and its agents and routines under config/.
~/CodeSense/<org>/.git/ You own this. Push to any remote you like; CodeSense never commits or pushes — you or an agent does.

Macos picker vs auto-created defaults

When you Create, the sheet prefills ~/CodeSense/<name> but you can navigate to any folder in the picker. When you Connect, you pick an existing folder — the parent doesn't matter, only that it holds an org.yml. Either way, CodeSense records the folder in context-attachments.yml so the next launch finds it.

How to do this via MCP

Agent-side equivalent

Agents don't hand-roll these paths; describe_setup reports each org's folder and each source repo's clone: 

describe_setup {}
// → orgs[].orgRoot, orgs[].teams[].sourceRepos[].localPath

Rust-side constants live in src-tauri/src/context_repo/path.rs (USERS_DIR, ORGS_DIR, …).
