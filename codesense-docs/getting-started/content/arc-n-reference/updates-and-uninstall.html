Updates, network calls and removing CodeSense

How the app from codesense.ai/download updates itself, what it sends on its own, and how to remove it and the files it keeps.

Updates

You don't need to do anything to stay up to date. The app checks at launch, then about once a day, and once after your Mac wakes. While a check is failing, or while a newer build is waiting to be installed, it checks about once an hour instead. A newer build downloads in the background and is checked against the release signing key before it's kept.

Open Settings → General. The Updates section, below About, shows where things stand:

  • With nothing waiting, it says CodeSense checks for a new version daily and installs it when you quit. Check now runs a check straight away; a newer build then downloads in the background.
  • When a build has downloaded, it says Update ready (<version>) — it installs when you quit CodeSense, with Release notes and Restart to update.
  • Quit CodeSense (⌘Q) whenever suits you and the update installs as the app closes, or choose Restart to update to install it now. If agent runs without a terminal are going, CodeSense says how many will stop and asks before it restarts (Restart anyway). Your terminal sessions run in a separate process, so they keep running through the restart.
  • If CodeSense is force-quit or crashes before you quit it, nothing is installed. The next launch finds the update again.

CodeSense installs an update only where it can replace itself without an administrator password. If it can't, or downloads keep failing, the Updates section says so, with Download the latest CodeSense from codesense.ai. To install by hand, quit CodeSense, open the new .dmg and drag CodeSense into Applications, replacing the old copy.

Update checks are automatic; there is no setting to turn them off. A build you make from source has no update source by default: Settings → General shows Check for Updates in About instead of the Updates section.

What leaves your Mac

CodeSense has no analytics, telemetry or crash reporting and makes no AI calls of its own. PRIVACY.md, at the root of the CodeSense source, lists every network call the app makes, with what it sends, how to turn it off and where it is in the code. In short:

  • On its own (PRIVACY.md §1–§5): the update check, a GET of one static file on dl.codesense.ai that sends no account, key, install id or clock; the update download when there is a newer build; inbox pictures on *.giphy.com or static.klipy.com that an agent in one of this app's tabs posts (other pictures wait for your click, and media: {remote: off} or remote: ask in a team's config/inbox.yml stops or holds them); and git fetch from a repository's origin for change history, with your own git credentials.
  • Because you set something up (§6–§11): your remote machines over SSH, which receive your terminal sessions, the files you open there and a git bundle of the branch you prepare a workspace from; git fetch when a workspace is checked; git-ai notes; MCP servers you configure; agent accounts you add; and dashboards you publish to share.codesense.ai, which sends the files those dashboards list.
  • Content you open (§12): dashboards, documents and stories load what they reference when you open them in the viewer.

The agent CLIs you run talk to their own providers under your accounts with them.

A shared dashboard draws no CodeSense bar over itself unless its dashboard.yml sets chrome: full, so a page can look like any screen, including CodeSense's own. Never type a password, a sign-in code or a payment detail into a dashboard. What a live dashboard shares with its viewers is set out field by field in get_live_data_contract.

Removing CodeSense

Your own repos stay where they are. To remove CodeSense and what it keeps on your Mac:

  1. Quit CodeSense (⌘Q).
  2. Stop the terminal server. Your terminal sessions run in a separate process, codesense-session-server, which keeps running after you quit. This ends every terminal session and agent still running in it: 
    pkill -f '/codesense-session-server[^ ]* --(resources|emulator|root) '
    To check nothing is left, run pgrep -fl codesense. If you connected remote machines, run the same command on each of them. On a Linux machine set up with a private account, stop it under that account with pkill -f '/codesense-session-server[^ ]* private-serve '.
  3. Drag CodeSense from /Applications to the Bin.
  4. Push or copy your work, then delete the folders CodeSense keeps (its bundle id is ai.codesense). Repos CodeSense cloned for you live in ~/.codesense/users/<id>/sources/, with their worktrees beside each clone in a folder named <repo>-wt, unless you chose your own folder for them. Deleting ~/.codesense deletes any branch, commit or change in them you haven't pushed. 
    rm -rf ~/.codesense \
  ~/Library/Application\ Support/ai.codesense \
  ~/Library/Caches/ai.codesense \
  ~/Library/WebKit/ai.codesense \
  ~/Library/Logs/ai.codesense \
  ~/Library/Preferences/ai.codesense.plist
    Repos you cloned yourself are not touched. CodeSense makes their worktrees next to each repo by default, in a folder named <repo>-wt; push what you want to keep, then remove them with git worktree remove. On remote machines, CodeSense keeps its files in ~/.codesense/ in your account there.
  5. Remove the Keychain items. Open Keychain Access and delete the items under these services, or run security delete-generic-password -s <service> for each until it reports that no item was found. You may not have all of them:
    • codesense-ssh: passphrases you saved for remote machines.
    • ai.codesense.dashboards: your dashboard publisher key.
    • codesense-auth: a sign-in record from older versions of CodeSense.

CodeSense also marks the worktrees it opens as trusted in Claude Code's own settings (~/.claude.json). Those entries do nothing without the folders; Claude Code manages them.
