YAML schemas: what CodeSense parses, and how to look them up.

CodeSense parses nine file types: an agent, a routine, a role, an org, its teams, a worktree, a bundle, and the frontmatter inside every story and epic markdown file. All nine live side-by-side in the schema browser with local shape checks — paste YAML to inspect supported fields and basic constraints. This page teaches you how to read it.

How to read the schema browser

  1. Pick a schema from the left list

    Eight rows: agent.yaml, routine.yml, org.yml, teams.yml, worktree.yaml, bundle.json, plus story frontmatter and epic frontmatter. Clicking a row deep-links the page: schema-browser.html#schema/story-frontmatter. Share that URL and the recipient lands exactly where you did.

  2. Read the field table top-down

    Required fields come first, then optional ones with defaults, then validation rules, then an example. Field names appear in the exact snake_case or camelCase the parser accepts — both are shown when the schema recognises an alias (e.g. default_mode ↔ defaultMode on permissions.claude).

  3. Paste YAML into the validator

    The validator debounces at ~120 ms. Its validateYaml bridge is currently unavailable, including when CodeSense is connected, so the browser uses a local subset parser and shape checks. A green bar does not establish Rust model validity or event semantics. Use the model’s save path for semantic validation; errors shown here cover only checks implemented by the browser.

  4. Copy the example and modify it

    Every schema row ships an example. Where a validator is available, paste it there, mutate one field at a time, and watch the status bar. Learning by breakage is the fastest way to internalise which fields are required vs. optional, and which have enum constraints.

Full field tables live in the explorer. This matrix is for orientation — which file holds what, where it lives on disk, and which arc teaches it.

Try this now

Open the story-frontmatter row, copy the example, paste it into the validator pane, change status: in-progress to status: wat, and watch the status bar flip red. The error cites the enum rule verbatim. Flip it back and the bar goes green. That round trip is the entire schema-browser idiom.

Validate a definition

validateYaml is a page bridge verb, not an MCP tool. The bridge is currently unavailable; the schema browser uses local shape checks even when connected. Those checks do not replace Rust semantic validation. An agent can use agent_create {dryRun:true, ...} or routine_create {dryRun:true, ...} for end-to-end create validation. For event triggers, pass events to routine creation as shown in the event cookbook. Role settings use role_save; the role schema has no bridge validator.
