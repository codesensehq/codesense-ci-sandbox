Arc N · Glossary

Every term the docs org uses, one place to look it up.

CodeSense names things precisely because the shapes matter — an org holds teams, a team hosts a context repo, a worktree is a prepared checkout of a source repo, and so on. Click a definition to jump to the arc that teaches it in context. Filter the box below to jump straight to a term, or use the alphabet rail to skim.

A

Agent taught by Arc E
An agent is a saved definition of a worker: which runtime (claude, codex or opencode), what it starts with, which MCP servers it can reach and what it may do. Each launch is a session, in a terminal tab or headless, on This Mac or a machine. A session works in a workspace, calls CodeSense MCP tools and sends inbox messages. CodeSense ships starters for Claude, Codex and OpenCode.
Lives on disk as config/agents/<id>/agent.yaml. See the schema row in the schema browser.
AGENTS.md taught by Arc E
A conventional instruction file at the root of a source repo (or team workspace), read by agents at startup. Hosts repo-wide rules, pitfalls, and preferred commands. Paired with CLAUDE.md for Claude-specific guidance.
Arc taught by home
A thematic grouping of pages in the docs org. Arcs A–N cover first touch, the model, workspaces, terminals, agents, inboxes, routines, pipelines, sync, the factory, and this reference catalog. Arcs are a navigational idiom, not a runtime concept.

B

Branch taught by Arc C
The branch a story's worktree is on: the story's branch field when it has one, otherwise the repo's branch prefix plus the story id (feat/LL-214 by default).

C

CLAUDE.md taught by Arc E
Claude-specific instructions file read at agent startup. Private to the user when placed in ~/.claude/; shared with teammates when checked into a repo.
Context field taught by Arc E
The context field is the set of files an agent's workspace gets at launch: its startup paths and its context sets, resolved through the target repo's tier, your private space and the team chain. More arrives only when an agent calls hydrate_worktree or hydrate_story.
Context repo taught by Arc A
A context repo is a plain git repo you own that holds a team's CodeSense content: agents, routines, epics, stories, planning docs and dashboards. CodeSense reads and writes files there and never commits, pushes or merges: you or your agents do.

D

Dashboard taught by factory-playbook
A dashboard is an HTML file in a context repo. CodeSense opens it as a live page that reads stories, sessions, inbox and routine results through window.codesense, and can act on them. An agent can write one with create_dashboard.
depends_on taught by Arc H
A frontmatter field in a story's markdown header listing the story IDs it waits on. The pipeline graph reads depends_on to compute the DAG and the sprint plan to compute the critical path.
Docs org taught by Arc A
The docs org is the read-only CodeSense docs context repo every install ships with. It's the training manual you're reading now. Writes refuse gracefully; copy an example into your own context repo to edit.

E

Epic taught by Arc H
A directory of related story markdown files, anchored by a top-level README.md (or index.md). The pipeline graph groups by epic; the sprint plan picks a subset.

F

Factory taught by Arc L
The factory is the end-to-end SDLC CodeSense teaches: fourteen phases from idea to retrospective, each with one agent, one skill, one inbox role, one trigger, and one dashboard. The factory playbook renders the 14 rows.
Frontmatter taught by Arc N · schemas
The metadata at the top of a story: a YAML header delimited by --- in a markdown file, or <meta name="cs:…"> tags in an HTML file. CodeSense reads type, status, depends_on, source_repo, supporting_docs and any custom key from it.

G

Generator taught by architecture
A build-time script that reads a source of truth (menu.rs, handler.rs, viewer types) and emits JSON into generated/. Dashboards and docs read the JSON. CI fails if the committed JSON drifts from a re-run.

H

Terminal server taught by Arc D
The process CodeSense runs on each machine, this Mac or a remote one over SSH, that holds its terminal sessions. Sessions keep running after the app quits and reattach when it opens again.
Hydration taught by Arc K
Copying team content into a workspace. It happens when an agent starts there (it gets what its definition's context declares) and when an agent calls hydrate_worktree (exact paths or whole folders) or hydrate_story (a story's epic folder, widened by an optional policy: referenceDepth, ancestryLevels, siblingBreadth, maxMembers). Never in the background, and you never run git pull.

I

Inbox taught by Arc F
An inbox holds messages agents and people send each other with send_message, as plain text, Markdown or HTML (an HTML message to you is a live page with buttons). Your Inbox shows conversations and role queues, and its badge counts all unread human mail of either kind, excluding archived mail. ⇧⌘I opens your Inbox; ⌘I docks the focused agent's inbox beside its terminal. Roles have inboxes too: a routine with a role_pending trigger fires when a message waits for its role.

L

Local (vs. remote) taught by Arc D
"Local" means the Mac this install is running on (This Mac). "Remote" means a machine you reach over SSH with your own account. Workspaces, terminals, agents and routines work on both; where a feature is This Mac only, the page says so.

M

Machine taught by Arc D
A machine is where work runs: This Mac, or a remote machine you added over SSH. Terminals, agents and routines carry a machine so you always see where a process is running. Open Machines from the context repo menu or with ⌘⌥C.
MCP taught by MCP explorer
Model Context Protocol. The tool-call shape CodeSense exposes to agents: a few hundred tools, and most UI actions have one, so an agent can do them without "seeing" the UI. The MCP explorer lists them with signatures and examples.

O

Org taught by Arc B
An org is the outermost unit of the model: a slug, a display name, a remote URL, people, and teams. The docs org is one; your personal context repo is another. Switch between them with ⌘⇧G.

P

Overlay taught by Arc C
In a CLI workspace, the diff, code editor, Story HUD and docked Inbox float over the terminal tile: ⌘⇧D, ⌘⇧C, ⌘⇧H and ⌘I. They work on remote worktrees too. Terminal tiles take focus with ⌘⌥ + arrow keys; ⌘⇧L cycles the terminal layout.
Parent team taught by Arc B
A team's optional ancestor. Along the team chain a parent can share its content/ and panes/ with its children, and the closest team wins; agents and routines stay with the team that defines them. Chains cannot cycle and max out at depth 64.
Pipeline taught by Arc H
The DAG CodeSense builds from story frontmatter: nodes are stories (actionable types), edges are depends_on entries. The pipeline-graph dashboard renders it; the sprint plan picks a traversal.

R

Remote taught by Arc D
A machine other than this Mac, reached over SSH with your own account. Workspaces, terminals, agents and routines run there; its terminal server keeps sessions running when the app quits, and its usage comes back to this Mac.
Role taught by Arc F
A named participant in the factory: triager, builder, reviewer, scout, resolver, analyst, pm, architect, tea, qa, designer. Each role owns an inbox; routines target roles.
Routine taught by Arc G
A routine runs an agent's task on a trigger: a schedule (cron) or an event (agent_done, inbox_idle, role_pending). In fresh mode it starts a new session; in wake mode it hands the task to a live one. Lives as config/agents/<agent>/routines/<id>/routine.yml; shown under Agents → Schedule. Up to 25 can be enabled.

S

Skill taught by Arc E
A reusable, named capability an agent can invoke by slash command, at .claude/skills/<name>/SKILL.md. Skills are written once in a team's content, and a parent team shares them down the chain when its config/sharing.yml lists them. Examples: bmad-build, update-codesense-docs.
Source repo taught by Arc C
The git repo your code lives in. Separate from the context repo, which holds planning. A team lists its source repos; a story names one in source_repo (owner/repo), and its worktree is made from your clone of it.
Sprint taught by Arc H
A time-boxed slice of the pipeline: a chosen subset of stories, their statuses, and a critical path. The sprint-analysis dashboard tracks progress; the bmad-sprint-planning skill generates and updates it.
Story taught by Arc H
A single-file unit of work: a markdown file with frontmatter, or an HTML file with cs: meta tags, inside an epic folder. By default its status is one of planning, todo, in-progress, blocked, review, qa, done, and anyone can change it. Agents work on a story in its own worktree; the pipeline graph treats it as a node.
supporting_docs taught by Arc H
A frontmatter list of relative paths (same-directory only) attached to a story: research notes, spikes, retros. They surface in the story HUD and travel with the story's worktree.
Sync taught by Arc K
How files move between a context repo and a workspace: hydration copies team content in; reverse sync, after a preview, sends edits made in a worktree back. Neither runs git: commits, pushes and pulls are yours or your agents'.

T

Tag schema taught by Arc N · schemas
A team-authored registry of tag categories and allowed values, stored under org.yml's tag_schema. Dashboards use it to colour and filter tagged items. An empty dict is a valid default.
Team taught by Arc B
A named group inside a context repo, listed in teams.yml, with its own content, source repos and an optional parent team. A parent can share content and panes down the team chain, and the closest team wins.
Team chain taught by Arc B
The ordered list [self, parent, grandparent, …, root] that resolves inheritance. A parentless team's chain is [self]. Cycles and depth > 64 are rejected at load.
Trigger taught by Arc G
What fires a routine: a schedule (a cron in a time zone) or an event: agent_done (an agent finished), inbox_idle (an agent sits idle with unread mail) or role_pending (a message waits for a role). A routine with no trigger is manual.

V

Viewer taught by Arc N · extensions
The subsystem that renders a file when you click it in the tree: markdown viewer, html viewer, excalidraw canvas, image viewer, code viewer. The viewer is selected by extension.

W

Worktree taught by Arc C
A worktree is a git worktree of a source repo for one story, on the story's own branch, at ../{repo}-wt/{slug} beside your clone by default. The first open creates it; later opens reattach. Context copied in is hidden from git. It stays until you remove it.
Workspace taught by Arc C
A workspace is where you work on one story or task: its terminal tabs and tiles, its worktree when it has one, and the overlays over them. The workspace bar holds the ones you're switching between.
