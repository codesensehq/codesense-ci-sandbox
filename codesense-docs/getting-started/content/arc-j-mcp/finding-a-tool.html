Describe the verb. Find the tool.

You know what you want to do: add a source repo to a team. You don't know the exact tool name. codesense_search_tools takes the words you'd use in a description and gives you the best matches — name hits beat description hits, shorter beats longer at equal score.

How it works

query is a string. The server lowercases it, splits on whitespace, and requires every term to appear in the tool's name or description. The hits are then ranked:

  1. Name hits beat description hits. Terms appearing in tool.name score higher.
  2. Shorter descriptions beat longer ones at the same score — more specific tools win over broad ones.
  3. Default limit: 20 results. Pass limit: 100 to see more; the server caps at 100.

Every result row is a name and its description. Every tool is in tools/list, so you can call the one you pick by name; a host that loads tool schemas lazily (Claude Code does) shows only names, so call codesense_get_tool_schema first to see its inputs.

Worked example

You're writing an agent that onboards a new team. Step one: wire a source repo. You don't know the tool name. Run: 

codesense_search_tools {
  query: 'add source repo',
  limit: 10
}

Reply (abridged):

{
  "tools": [
    {
      "name": "add_source_repo",
      "description": "Add a source repo to a team. Pass `org` (owner/repo) and `team`, …"
    },
    {
      "name": "attach_source_repo_path",
      "description": "Bind a local git clone to a tracked source repo on a team …"
    },
    {
      "name": "remove_source_repo",
      "description": "Remove a tracked source repo from a team …"
    }
  ]
}

add_source_repo is the one. Pick it, read the schema, call it. Done.

Why one tool ranks ahead of another

Query Top hit Why
"add source repo" add_source_repo All three terms in the name. Tightest match wins.
"source repo" list_source_repos Short desc, both terms in the name. Shorter wins ties.
"canvas render" render_canvas Both terms in the name.
"validate story" validate_story Exact name.
"send message to inbox" send_message Two terms name, "inbox" in description.

Tips

Use the words you'd use in a description. "List the open sessions" beats "sess_list". The tools are indexed on natural-language text; the server does the normalisation.
Narrow by role. If you're writing an agent that only reads, add "list" or "get"; add "create" or "update" for writes.
Two terms is usually enough. Three terms AND down to a tight band; more than three often cuts the right tool out.

How to do this via MCP 
// Default limit is 20. Max is 100.
codesense_search_tools {
  query: 'add source repo'
}

// Narrow further.
codesense_search_tools {
  query: 'routine list',
  limit: 5
}

// Chain: discover → schema → call
codesense_search_tools { query: 'send message' }
// → { tools: [{ name: 'send_message', … }, …] }
codesense_get_tool_schema { name: 'send_message' }
// now call send_message by name
