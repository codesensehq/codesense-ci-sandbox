Start every session here.

codesense_overview is the one call every agent should make first. One request, no arguments, nothing writes. The reply names every org, team, source repo, machine, open session, routine, and the active one of each. Most tasks are answered from this reply alone.

Why it's the universal starting point

Every other CodeSense tool is parameterised by things like org, team, source repo path, session id. codesense_overview is the one call that tells the agent all of those at once, in one shot. Skip it and the agent has to probe — list_orgs_teams, describe_setup, list_sessions, routine_list — four calls to get what overview returns in one.

It's in tools/list like every tool, and the server's instructions name it first, so an agent knows to start there.

What the reply says

Field What it is
user The user handle this process is running as. Useful for self-referential queries ("my teams", "my inboxes").
machine The machine CodeSense is on — the name you'll see in a remote-session row elsewhere.
orgs Every org the user has synced to this Mac. Each has a handle and a list of teams.
teams Every team across all orgs. active flags the one dashboards and new sessions default to.
source_repos Each team's source repos — remote key, bound local path if any, whether a worktree is open.
sessions Open agent sessions — tab or headless, foreground or background, with unread counts.
routines Routines the team has, which are armed, which fired recently.
inboxes Role queue depths at a glance — builder: 7, reviewer: 1, …
remote_machines Remote Macs this account can reach — hostname, last-seen, account.

Fields the user doesn't have anything in come back empty — the shape is stable, you don't branch on presence.

When overview is enough on its own

  • Any read of structure. "Which teams does this user have?" — right there.
  • Routing a message. You know the role queues exist and have depth; send_message takes it from there.
  • Picking the active team. It's named — no second call to confirm.

When not enough: you need per-item detail — every story in the pipeline, every message in an inbox, every field of one agent. Then search for the right verb (query_context, inbox_list, agent_get) and call it.

Try this now

Run the real call. Read-only; nothing writes. The reply is big — the "Try this" sheet shows the headings and lets you expand each.

How to do this via MCP 
// The one call every agent should make first.
codesense.invoke('codesense_overview', {})

// Everything else branches off the reply:
const { teams, source_repos, sessions, inboxes } = overview

// Example: route a message to the busiest role.
const busiest = Object.entries(inboxes)
  .sort(([, a], [, b]) => b - a)[0][0]
codesense.invoke('send_message', { to: `role:${busiest}`, body: '…' })
