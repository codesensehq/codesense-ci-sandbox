Start every session here.

codesense_overview is the one call every agent should make first. One request, no arguments needed ({guide: true} returns the concepts guide instead), nothing writes. The reply summarizes the active org and team, machines, sessions, saved Agents, routines, the inbox, role queues, open workspaces and the placed docs, and each section names the tools that return its full data.

Why it's the universal starting point

Every other CodeSense tool is parameterised by things like org, team, machine id, session handle. codesense_overview is the one call that tells the agent where to start, in one shot. Skip it and the agent has to probe — list_machines, list_sessions, routine_list, role_state — call after call to get the summary overview returns in one.

It's in tools/list like every tool, and the server's instructions name it first, so an agent knows to start there.

What the reply says

Field What it is
generatedAt When the reply was composed.
context The active org and team (org, team), or both null with a note when no team is active.
machines total, byStatus, and items: each machine's machineId, label, kind, remoteMcpControl and status.
sessions total, byState, byMachine, needsYou (who waits on you), and notExited: each running agent or terminal's handle, state, machine, workspace, story, role, who launched it and its unread count.
agents Saved Agents: total, byScope, and saved (id, name, runtime, scope, team; the built-in ones are counted, not listed).
routines total, how many are enabled, how many need you, lastRunByStatus, and items with each routine's runs_on, armed_here, schedule, next and last run.
inbox humanUnread and agentsWithUnread (sessions with unread mail, oldest first seen) for the active team.
roleQueues Each role in the active team with pending, claimed, accepted and acknowledged deliveries and liveInstances; withUnclaimedWork names the roles with pending work.
workspaces Open workspaces: each one's kind, story, repo, branch, worktree path, host, and how many tabs it has and how many are live.
docs Where the bundled CodeSense docs are on this Mac: the concepts guide, START-HERE.md, how to search them, and the placed docs' state and commits.

Every section also has detail: the tools that return its full data. A section that could not be read has error instead of data, and the rest still answer. Lists are capped, with truncated: true when cut.

When overview is enough on its own

  • Any read of state. "Who needs me?", "Which machines are down?" — right there.
  • Routing a message. roleQueues shows each role's pending work; send_role_message takes it from there.
  • Knowing the active team. context names it — no second call to confirm.

When not enough: you need per-item detail — every story in the pipeline, every message in an inbox, every field of one agent. Then search for the right verb (query_context, inbox_list, agent_get) and call it. For other orgs, teams and bound source repos, call describe_setup, list_orgs_teams or list_source_repos.

Run the real call. Read-only; nothing writes. The reply is big — the "Try this" sheet shows the headings and lets you expand each.

How to do this via MCP 
// The one call every agent should make first.
codesense_overview {}

// Everything else branches off the reply's sections: context, machines, sessions,
// agents, routines, inbox, roleQueues, workspaces, docs.

// Example: roleQueues shows builder has the most pending work, so message that role.
send_role_message { team: { org: 'acme/team-context', team: 'dev' }, role: 'builder', text: '…' }
