No UI. Just four calls.

Everything CodeSense does is reachable through MCP: it is MCP-complete. We'll build an agent that onboards a new team end-to-end without ever touching the UI: pick the active team, add a source repo, list the worktrees that are open on it. Four tool calls. The agent's whole surface area is the bridge.

The task

You've just signed into a Mac that's never used CodeSense before. There's an acme org you belong to; its default team is where you work. You want to:

  1. Make acme / default the active team.
  2. Add the repo acme/sample as a source so new worktrees can be spawned from it.
  3. Confirm by listing the worktrees the Mac now sees.

A human would click through the team switcher, the settings pane, and the worktrees panel. The agent does the three verbs via MCP alone — no UI window, no shell call, no filesystem write.

Step 0 · The agent definition

Save under config/agents/team-onboarder/agent.yaml in your context repo. Pattern from Arc E's MCP-only agents: empty mcp.servers, allowlist mcp__codesense__*, deny filesystem + shell. 

id: team-onboarder
name: Team onboarder
description: Picks the active team, attaches a source repo, confirms by listing worktrees.
runtime: claude
launch: headless
startup:
  - CLAUDE.md
  - .claude/skills/team-onboarder/
mcp:
  servers: []        # bridge is on by default; nothing else
permissions:
  claude:
    allow: [Read, Grep, Glob, "mcp__codesense__*"]
    deny:  [Edit, Write, Bash]
default_prompt: /onboard-team
revision: 1

Launch headless with your Claude CLI; CodeSense wires the bridge; the agent is live. No UI involved so far either.

The four calls

1

list_orgs_teams read

Discovery first. Returns every org / team the local user is a member of and whose content is synced. We're looking for { org: "acme", team: "default" }; if that's not in the reply, the agent stops — the user hasn't joined the team yet. 

const { entries } = await codesense.invoke('list_orgs_teams', {})
const target = entries.find(e => e.org === 'acme' && e.team === 'default')
if (!target) throw new Error('team not synced to this Mac')
2

set_active_team write

Switch the backend focus. The same move as clicking the team switcher: the backend re-targets watchers and the UI follows. Changes org if needed. 

const switched = await codesense.invoke('set_active_team', {
  org:  'acme',
  team: 'default'
})
// { status: "ok", data: { orgSlug: "acme", team: "default" } }
if (switched.status !== 'ok') throw new Error(switched.status)
3

add_source_repo write

Attach the source repo by remote shorthand owner/repo. CodeSense never clones — if the Mac doesn't have a local clone yet, the repo is tracked remote-only until a worktree is opened or attach_source_repo_path is called with the clone's path. 

const added = await codesense.invoke('add_source_repo', {
  org:  'acme',
  team: 'default',
  url:  'acme/sample'
})
// { status: "ok", data: { owner, repo, provider, host, remoteKey, remoteName } }
if (added.status === 'validation') throw new Error(added.message)
4

list_worktrees read

Confirm. Lists every managed worktree on this Mac — story worktrees, epic-integration worktrees, orphans. For a brand new source there are no worktrees yet; the result is { rows: [], reaped: 0 }. That empty answer is the "done" signal. 

const trees = await codesense.invoke('list_worktrees', {})
return {
  team:      switched.data,
  source:    added.data,
  worktrees: trees.rows.length,
}

What this proves

Zero UI calls. Zero shell calls. Zero filesystem writes outside what the bridge did on your behalf — set_active_team and add_source_repo both landed in CodeSense's own state, nothing in your source tree moved. The whole workflow is auditable, log-replayable, scriptable on a cron. MCP-complete means: every UI action has an MCP tool, so every workflow is reproducible via MCP alone.

Error paths worth handling

  • Team not synced. list_orgs_teams omits teams whose content isn't on this Mac. The agent surfaces a clear error, not a cryptic "unauthorizedTeam" later.
  • Duplicate source. If acme/sample is already attached, add_source_repo returns { status: "validation", message: "already tracked" }. Idempotent — the agent can retry without harm.
  • Permission denied. The host's deny list wins over the bridge. If mcp__codesense__add_source_repo is blocked, the call errors before reaching the handler.

Run step 1 — list_orgs_teams. Read-only. The reply shows the agent what it needs to pick a team.

How to do this via MCP (the full agent body) 
async function onboardTeam({ org, team, repo }) {
  const { entries } = await codesense.invoke('list_orgs_teams', {})
  const target = entries.find(e => e.org === org && e.team === team)
  if (!target) throw new Error(`team ${org}/${team} not synced here`)

  const switched = await codesense.invoke('set_active_team', { org, team })
  if (switched.status !== 'ok') throw new Error(switched.status)

  const added = await codesense.invoke('add_source_repo', {
    org, team, url: repo,
  })
  if (added.status === 'validation' && !/already tracked/.test(added.message)) {
    throw new Error(added.message)
  }

  const trees = await codesense.invoke('list_worktrees', {})
  return {
    team: switched.data,
    source: added.data,
    worktrees: trees.rows.length,
  }
}

onboardTeam({ org: 'acme', team: 'default', repo: 'acme/sample' })
