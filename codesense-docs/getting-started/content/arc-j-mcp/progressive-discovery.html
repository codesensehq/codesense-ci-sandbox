The four moves, in order.

You don't know every tool CodeSense has. You don't need to. Call codesense_overview first — it tells you where you are and what matters. If that answers the question, stop. If it doesn't, search for a tool, read its schema, call it.

Walkthrough

1

codesense_overview

Always start here. One read-only call. You see the active org and team, machines, sessions, saved Agents, routines, the inbox, role queues and open workspaces, each with the tools that return its full data. Many agent tasks are answered from this reply alone — "who needs me?", "is there already a session doing X?"

In tools/list with every other tool. Needs no args ({guide: true} returns the concepts guide instead). Nothing writes.

2

codesense_search_tools

You need a verb and you don't know its exact name. Pass a query that's some combination of the words you'd put in a description — "add source repo", "canvas render", "story create". Multiple terms are AND-matched against name + description. Returns the top hits, sorted so name-matches beat description-matches.

The reply lists each hit's name and description. Every tool is in tools/list; call the one you pick after get_tool_schema.

3

codesense_get_tool_schema

Hand it a tool name. Get back the full description plus the input JSON schema — the same shape tools/list carries for it. You know what fields are required, which are optional, and what the valid shapes look like. If the name isn't a tool, the reply is {status: "unknown", name}, nothing throws.

4

Call the tool

Two ways. On a host that can dispatch outside tools/list (Claude Code, the CodeSense bridge in-app), just invoke the tool by its name — add_source_repo { … }, verbatim. On a host that can't, wrap it: codesense_call_tool { name, arguments }. The inner tool's result is returned verbatim either way.

When to reach for each

Situation Call
First call of the session. You want context. codesense_overview
You know the verb exists but not the name. codesense_search_tools
Overview said there's a routine; now I want the full list. codesense_search_tools { query: "routine list" } → routine_list
Found a tool. What arguments does it take? codesense_get_tool_schema
Agent is going to call it right now. Call it by name. No wrapper needed.
Agent host literally refuses tools outside tools/list. codesense_call_tool

Why this shape

The MCP server has most CodeSense actions as tools, and tools/list advertises all its tools so strict hosts can call any of them. With a few hundred tools, an agent rarely knows a name up front, and hosts that load schemas lazily show names only. Search and schema close that gap.

Try this now

Run the second step — a search for the first verb you'd use after overview. The reply shows how name-match beats description-match.

How to do this via MCP 
// 1. Where am I?
codesense_overview {}

// 2. Find a verb.
codesense_search_tools { query: 'add source repo' }

// 3. Read the contract.
codesense_get_tool_schema { name: 'add_source_repo' }

// 4. Call it.
add_source_repo {
  org: 'acme/team-context',
  team: 'default',
  url: 'owner/repo'
}
