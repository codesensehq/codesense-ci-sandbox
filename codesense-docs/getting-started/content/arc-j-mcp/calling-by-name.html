Any tool, by name.

Every CodeSense tool is in tools/list, so most hosts just call it by name. If yours can only dispatch from a fixed manifest, wrap the call in codesense_call_tool.

Every tool is listed

tools/list advertises every CodeSense tool, a few hundred in all. Some hosts (Claude Code, for one) load tool schemas lazily, so the agent sees names first and reads a schema when it needs one. The wrapper isn't a way around a permission boundary; it's for hosts that can't call a tool outside a fixed manifest.

Permissions still apply. A host that denies mcp__codesense__send_message blocks that tool whether the agent calls it directly or wraps it in codesense_call_tool. The dispatcher re-validates every call against the host's allow / deny rules.

Two ways to call

Direct — recommended

codesense.invoke('add_source_repo', {
  org: 'acme',
  team: 'default',
  url:  'acme/sample'
})

Wrapped — escape hatch

codesense.invoke('codesense_call_tool', {
  name: 'add_source_repo',
  arguments: {
    org: 'acme',
    team: 'default',
    url:  'acme/sample'
  }
})

Both reach the same handler, both return the same { status, data }. Prefer the direct path — one fewer layer, one fewer place to typo, cleaner logs.

When to use the wrapper

  • A host that only dispatches from tools/list. Some strict MCP clients refuse any tool name they didn't see on connect, or pin the list they saw when the agent was built. The wrapper is always there, so the call goes through.
  • Agent frameworks with a fixed tool manifest. Hard-coded tool shapes at build time. The wrapper lets one manifest entry reach every CodeSense verb.
  • Routing layers. A proxy that logs tool names can present a stable surface — one tool, many targets.
Rule of thumb. If your host dispatched codesense_get_tool_schema successfully, it can dispatch any tool by name. The wrapper only earns its keep when direct dispatch fails.

Contract

Input: { name: string, arguments?: object }. arguments defaults to {}.

Returns: the inner tool's result verbatim — whatever add_source_repo would have returned if called directly.

Can't invoke itself. codesense_call_tool { name: "codesense_call_tool" } returns an error. Prevents infinite indirection.

Worked example — same call, both ways

Create an agent two ways. Both return { status: "ok", data: { id, revision, …} }. 

// Direct — in-app, Claude Code, Codex.
codesense.invoke('agent_create', {
  name: 'Docs reader',
  runtime: 'claude',
  startup: ['CLAUDE.md'],
  dryRun: true
})

// Wrapped — hosts that need it.
codesense.invoke('codesense_call_tool', {
  name: 'agent_create',
  arguments: {
    name: 'Docs reader',
    runtime: 'claude',
    startup: ['CLAUDE.md'],
    dryRun: true
  }
})

Try this now

Call a tool through codesense_call_tool. We pick who_am_i — read-only, no args, no side effects.

How to do this via MCP 
// Simplest form.
codesense.invoke('codesense_call_tool', { name: 'who_am_i' })

// Full form.
codesense.invoke('codesense_call_tool', {
  name: 'send_message',
  arguments: { to: 'role:builder', body: 'wake up' }
})

// Prefer direct dispatch when the host allows it.
codesense.invoke('send_message', { to: 'role:builder', body: 'wake up' })
