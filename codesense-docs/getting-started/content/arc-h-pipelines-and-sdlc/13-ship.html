What this phase is for

Shipping is a human-authorized moment, not a schedule. The agent previews its context edits with preview_reverse_sync_worktree, publishes them to team content with reverse_sync_worktree, then, when you ask, commits and pushes the context repo with git and reports with report_context_sync.

Nothing publishes a workspace's edits on its own. Skip the publish and they stay on that machine.

Local vs remote

Local

The preview lists every file the publish would write, plus any conflict (a conflict is never written). The agent publishes only after you say yes, and pushes only after that.

Remote (private-account)

A remote workspace publishes the same way: reverse_sync_worktree writes team content on this Mac. The push happens where the context repo's clone is, usually this Mac, so ask an agent here to push.

How to do this via MCP 
// Preview, then publish the workspace's context edits.
const target = { kind: 'local', codeRepoPath: '<worktree>', sessionId: '<session>' }
preview_reverse_sync_worktree { target }
reverse_sync_worktree { target }
// Then run git yourself (commit, push) and report how it went.
report_context_sync { state: 'ok' }
