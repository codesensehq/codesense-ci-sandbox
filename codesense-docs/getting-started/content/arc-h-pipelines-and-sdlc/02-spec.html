The itch becomes a machine contract. A spec names the invariants — the things that have to be true after the work lands — so every downstream phase projects out of one source.

What this phase is for

A spec is a kernel: the smallest statement of what has to be true after the work ships. In CodeSense, every artifact after this one — the architecture, the stories, the tests, the review checklist — is a projection of the spec. If the spec is sharp, the rest writes itself.

Mary runs the bmad-spec skill against the idea from phase 1. The skill is interactive; it pushes back when a draft captures a solution instead of an invariant.

Local vs remote

Local

Mary works against your repo in-place; the spec lands in _bmad-output/<epic>/SPEC.md alongside the idea doc. You see the diff immediately in the tab.

Remote (private-account)

Same shape, remote workspace. The remote Mary previews her edits with preview_reverse_sync_worktree, then publishes them with reverse_sync_worktree. No parity gap.
