The sweep that closes the factory loop. Run by a routine on a schedule, bmad-loop-sweep looks for work that fell through the cracks and carries it forward.

What this phase is for

The loop phase is what makes CodeSense a factory, not a one-shot. bmad-loop-sweep runs on a schedule to catch everything that slipped: stories without owners, review threads gone cold, carried-over sprint points, retro findings nobody scheduled.

A good sweep is short. If every run finds work, the earlier phases are under-planned; the retro of the next epic surfaces that pattern.

The loop sweep is the only phase whose routine runs on a schedule (a cron expression with a time zone) rather than on mail. Drop this into config/agents/loop-sweeper/routines/loop-sweep/routine.yml.

Local vs remote

Local

This Mac fires the schedule. The routines-console.html dashboard shows the next scheduled sweep, the last run, and what it found.

Remote (private-account)

routine_arm_on moves the routine onto a remote machine, which then fires it on its own clock. Keep sweeps per-machine — a sweep that touches two context repos should emit its carry-over as inbox messages, not direct writes to the other machine.
