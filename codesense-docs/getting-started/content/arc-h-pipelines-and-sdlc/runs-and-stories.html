Runs and stories

Reference for the tools that read agent runs and run events, and for the story-authoring and source-repo tools: list_runs, read_run*, list_run_events, get_story_format, validate_story, read_epic_repos, set_epic_repos and list_source_repos.

Agent runs

A run appears here once it has recorded an outcome. A run still going is not listed; list_sessions shows it. A dashboard's codesense.runs(), run(), runEvidence() and runWorkProduct() return the same data as the matching tools.

list_runs

Lists the latest recorded outcome of every agent run on this Mac, newest first by end time. Optional limit (default 50, max 500). Returns [{outcome:{story_id, run_id, status, summary?, ended_at, source, org?, team?, session_ids?, ...}, validated, has_structured_transcript, link}]. link is linked when the outcome names the session(s) that did the work (session_ids, with the trusted org and team the run was launched under) and unlinked for a run recorded before outcomes carried them. Older runs are never rewritten. Take outcome.run_id to the other run tools, and outcome.session_ids to the session record (see How a run joins its session).

{
  "tool": "list_runs",
  "arguments": {
    "limit": 20
  }
}

read_run

Reads one run in full: {outcome, transcript, artifact, artifactTruncated}. transcript is the structured conversation or null (see How a session's conversation is kept), artifact the tail of the captured terminal output (secrets redacted) or null. Optional maxArtifactBytes (default 65536, max 1048576) caps the output returned, from the end. outcome is the same row list_runs gives, with link.

{
  "tool": "read_run",
  "arguments": {
    "runId": "<outcome.run_id from list_runs>"
  }
}

read_run_evidence

Reads one run's audit record: {header, run, perNodeResults, authority}, covering what fired it, how it ended, its step-by-step spine and what each step reported. Returns null when there is no evidence. Optional storyId selects one story for a run that worked several. Use read_run for the transcript of a particular attempt.

{
  "tool": "read_run_evidence",
  "arguments": {
    "runId": "<outcome.run_id from list_runs>"
  }
}

read_run_work_product

Reads the git branch a run produced, as captured when it ended: {branch}, or null when it produced none, is still going or is unknown. The repository is outcome.work_product.source_repo from the list_runs row.

{
  "tool": "read_run_work_product",
  "arguments": {
    "runId": "<outcome.run_id from list_runs>"
  }
}

list_run_events

Reads durable run events on this Mac, newest first by record time. since_ms (inclusive epoch milliseconds) is required; until_ms, kinds (outcome, advance) and limit (default 50, max 500) are optional. Outcome and advance events have different shapes, described in the tool schema. The store spans teams, so scope a story_id to your org and team with query_context before using it in a team review. Where list_runs gives one latest row per run, this gives the event history.

{
  "tool": "list_run_events",
  "arguments": {
    "since_ms": 1792700000000,
    "kinds": [
      "outcome"
    ],
    "limit": 50
  }
}

How a run joins its session

Every managed launch of Claude or Codex writes one session record in the usage store when it binds. The record is keyed by the CodeSense session id and also holds the CLI's own session id, so a run, its usage and its timing all join in one place. Older sessions have no record; a hand-started CLI in a CodeSense tab gets a minimal one on its first hook.

  • Run → session: outcome.session_ids in list_runs and read_run. A run several sessions worked names all of them, in the order they first appeared.
  • Usage → run: each session_usage row has runId, from the record. Match it to outcome.run_id to price a run exactly. A session with no record, or one launched outside a run, has runId: null.
  • Missing facts say why. A fact the launch could not know is null and has a reason under unavailable. Nothing is guessed from a folder or a name.
  • No credentials. The record holds no env values and no raw argv. The account is only its provider, id, label and source.

A record, as stored for a managed Claude launch:

{
  "sessionId": "shell-mcp-1",
  "nativeSessionId": "c1a0de00-0000-4000-a000-000000000307",
  "org": "acme", "team": "web", "handle": "DEMO-1",
  "launchedBy": "codesense",
  "agent": "acme/web/dev@3", "manifestHash": "abc123",
  "cli": "claude", "cliVersion": "2.5.0", "model": "claude-opus-5-5",
  "mcpAllow": ["codesense"], "bridgeTools": ["send_message", "signal_done"],
  "account": {"provider": "anthropic", "accountId": "acct-1", "label": "work", "source": "explicit"},
  "storyId": "DEMO-1", "workspace": "/work/ws", "worktree": "/work/wt",
  "branch": "feat/DEMO-1", "runId": "agent-launch:1c9e...",
  "unavailable": {},
  "timing": {"startedAtMs": 1792800000000, "wallMs": 44000, "activeMs": 9000, "idleMs": 35000,
             "turnCount": 2, "toolCallCount": 2, "timingSource": "claude-hooks",
             "idleGaps": [{"afterTurn": 0, "fromMs": 1792800006000, "toMs": 1792800036000, "waitingOn": "prompt"}]}
}

Timing is derived from turns the app already observes. A turn ends waiting on prompt, permission, blocked (the latest signal_progress was blocked; its note is kept), error or unknown. Idle is the gap from one turn's end to the next turn's start, or to the session's end. Wall time is end minus start and idle is wall minus active. These are facts only: nothing here says a session was stuck or lost.

How a session's conversation is kept

CodeSense keeps the conversation of every managed Claude or Codex session, by session and not only for runs: the person's requests, the agent's replies, and each tool call with its result. It is read from the CLI's own session log and stored in the CodeSense home under session-conversations/, beside run-artifacts/. read_run reads it for the latest session a run names; an older run still reads its own record.

  • When: after a turn ends while the session runs (Claude's Stop, a Codex turn stopping, failing or being interrupted; at most once a minute per session), when the session ends, when a run completes, and just before a scoped Codex home is removed. A session that crashes keeps what its last turn end stored.
  • Secrets are removed first. Every line of the CLI's log is scrubbed before it is parsed or written. A private key is masked from its header through its body, whether the log holds it plainly or inside JSON inside JSON.
  • Size and age. A conversation is kept whole up to 20 MiB. Past that it keeps the first request and the newest turns, drops the oldest between them, and says what it dropped (truncated, with the turn range and the bytes). The tool-call index always covers every call, dropped turns included. A conversation is removed 90 days after its session ended; the index stays, so names and counts outlive the text. These are the defaults; a per-org setting comes later.
  • One format for every CLI. Each turn has an index (stable as the log grows), a time, the model, a reasoning marker (full, summary, encrypted or none), and tool calls with the CLI's own native_id, the MCP server, is_error and, for a skill, its name. A fact a CLI never records is left out and named under unavailable with the reason (Codex records no is_error, Claude's log holds no cost). Nothing is inferred. A view shows what exists and skips the rest.
  • Skills. Claude's Skill tool and OpenCode's skill tool mark the call with the skill's name. A prompt whose first word is /name or $name for a skill the session's agent provides gets one skill-prompt row; a prompt that only mentions a skill, or names one the agent was not started with, gets none.
  • States. A conversation read is present, truncated, absent (nothing stored yet, or no such session), expired, unsupported (interactive OpenCode), or unavailable when final capture could not obtain its saved session record or that durable record has no linked native ID. Unavailable includes a reason, never an empty list standing in for one. A hand-started Claude in a CodeSense tab is captured; a hand-started Codex has no record, so it reads absent before capture is attempted and unavailable if final capture reaches the record deadline.
  • Capture ordering. Final capture waits off the async runtime for the record write, for at most two seconds. A timeout keeps the native scoped home for a later session-end delivery or startup sweep. For example, a read can return {"state":"unavailable","reason":"session_record_timeout: session record was not persisted before the capture deadline","unavailable":{"conversation":"session_record_timeout: session record was not persisted before the capture deadline"}}. A failed record write uses session_record_write_failed. A durable record that has no linked native ID instead uses native_session_id_missing; this is distinct from record timeout or write failure. Previously stored conversations and their tool-call index survive failed later capture attempts.

Not followed: a Claude /clear or --resume that changes the CLI's own session id mid-tab (the conversation is kept under the id the record holds), and sub-agent logs (only the main log is read).

Authoring and validating stories

get_story_format

Returns the decision-first contract for creating CodeSense content: whether frontmatter is needed at all (most content is a plain doc and needs none), the pipeline-story frontmatter schema, the validate_story finding codes, and cross-references to list_source_repos and validate_story. It takes no arguments; call it first.

{
  "tool": "get_story_format",
  "arguments": {}
}

validate_story

Validates a candidate file before it is written. Pass path (preferred, since it anchors depends_on and supporting_docs checks) and/or inline content. It detects the intent (plain doc, pipeline story or epic main doc) and does not nag a plain doc. For a story it returns blocking and advisory findings {code, field, severity, message, hint}, and never returns valid:true for a file it could not fully evaluate.

{
  "tool": "validate_story",
  "arguments": {
    "path": "/abs/path/to/content/stories/DEMO-1.md"
  }
}

Source repos and epic repos

list_source_repos

Lists the legal source_repo values and structured repository identities, including each repo's local clone (attachment: attached, missing or unattached, plus localPath). Use sourceRepoIdentities for explicit provider, host and remote key. Never invent a source_repo; resolve it here.

{
  "tool": "list_source_repos",
  "arguments": {}
}

read_epic_repos

Reads the source repos an epic workspace is configured to assemble, from the epic doc's repos: frontmatter. Pass epicFilePath (the epic main-doc path, $CODESENSE_EPIC_DOC_PATH). Returns an array of canonical owner/repo slugs, empty if none. Read-only.

{
  "tool": "read_epic_repos",
  "arguments": {
    "epicFilePath": "/abs/path/to/epic.md"
  }
}

set_epic_repos

Replaces the epic doc's repos: frontmatter. It is read-modify-write: pass the full desired repos list, not a delta (an empty list clears it); entries are normalised to owner/repo. Rejected if the target is not an epic doc. CodeSense then re-assembles the epic's integration worktrees in the background, and the call returns the re-read list immediately.

{
  "tool": "set_epic_repos",
  "arguments": {
    "epicFilePath": "/abs/path/to/epic.md",
    "repos": [
      "owner/repo"
    ]
  }
}
