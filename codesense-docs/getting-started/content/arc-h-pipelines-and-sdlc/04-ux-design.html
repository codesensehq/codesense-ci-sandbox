Phase 04 · UX design

Sally takes the spec and the architecture and designs the surface a human will touch — buttons, modal copy, keyboard paths, reduced-motion fallbacks. The impeccable skill is the frontend design partner that runs the critique passes.

Agent… Skill… Inbox… Trigger… Dashboard…

What this phase is for

Design decides the shape of the thing you'll click, type, and trip over. This walkthrough uses one skill — impeccable, installed in the team's context like any other — for every frontend design and critique, covering cognitive load, a11y, reduced motion and visual hierarchy. Sally drives it; the output is mocks or a design canvas plus a short spec (focus order, modal copy, state transitions).

Use impeccable whenever a human has to touch the output. Skip it when the story has no new surface (an internal refactor, a schema change).

Local vs remote

Local

Sally opens design canvases via apply_canvas and flips them side-by-side with the running viewer. Hot reload shows the mock inside a real tab, with the real theme tokens.

Remote (private-account)

Same two MCP tools; the canvas lives in the remote repo. The viewer tab paints the canvas identically — pixel-perfect parity is a non-goal, but the shape and copy are canonical.
