What this phase is for

Review's job is to catch what the build phase couldn't: structural drift from the spec, edge cases the ATDD red test missed, reductions in test coverage, verification gaps. CodeSense ships two skills — bmad-code-review for parallel adversarial lenses, bmad-review for multi-lens prose/spec review.

A reviewer who gets stuck in nits is itself a signal — the retro phase will flag it and the loop sweep will adjust.

Drop this into config/agents/winston-reviewer/routines/reviewer-claim/routine.yml. A role_pending trigger fires once for each message queued for the reviewer role; in fresh mode it starts a new reviewer session, which claims the message with claim_role_messages.

Local vs remote

Local

Winston runs against your local worktree. He reads diffs via git + query_context, writes the review into the reviewer inbox thread, and posts a structured per-finding message to the author.

Remote (private-account)

Same shape; the reviewer runs where the PR branch lives. To share the review log, the reviewer publishes it with reverse_sync_worktree; the other side pulls it with hydrate_worktree.
