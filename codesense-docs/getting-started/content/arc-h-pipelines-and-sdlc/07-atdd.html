What this phase is for

ATDD — acceptance-test-driven development — writes the test the story will have to pass before anybody starts building. The test is red when it lands; the build phase's job is to turn it green. It's the fastest way to catch "the real problem isn't what we thought" moments.

Not every story needs it. Use ATDD when the story spans a new end-to-end flow or carries real UX risk. Skip it for refactors, internal tooling, or copy edits.

Local vs remote

Local

Murat drops the red test into your source repo's e2e/ or tests/ folder as a Playwright / vitest file. Local pnpm test confirms it's red.

Remote (private-account)

Remote Murat runs the same skill against the remote source repo. The test file is source code, so it comes back on the story's branch for review before builders claim the story.
