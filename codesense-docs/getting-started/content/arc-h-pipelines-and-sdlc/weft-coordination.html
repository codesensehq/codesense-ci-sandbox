Weft coordination tools

Reference for the Weft coordination tools (wv_*): the Weft queue, dispatch briefs, approvals, Tier-2 windows, the decision and attention ledger, and the audit and posture controls.

How to read this page

Each entry says what the tool does, how it differs from its neighbours, and shows one call with the wire names the server expects. Results are described only where the served description names them. These tools are mechanisms: which of them to use, and in what order, is the agent's decision.

Where a tool takes sessionId, the verified MCP connection supplies identity; a supplied sessionId must name the caller itself, and an unbound caller is refused.

Queue

The Weft queue holds work items as rows that move through pending, claimed and dispatched. Resolved rows are pruned and never appear in a listing.

wv_enqueue

Adds a pending row to the Weft queue for an agent to claim; triage may write it. Pass source, and optionally scope, refs, note and dedupeKey. With a dedupeKey, a second enqueue while a live row with that key exists is a no-op that returns the existing id, so a trigger can call it on every pulse. Returns {id}; row ids are not stable across prunes.

{
  "tool": "wv_enqueue",
  "arguments": {
    "source": "triage",
    "scope": "sprint-1",
    "note": "Review request for DEMO-13",
    "dedupeKey": "review:DEMO-13"
  }
}

wv_queue_list

Lists the non-resolved queue rows (pending, claimed, dispatched), optionally filtered by scope. Read-only. Returns [{id, source, state, claimedBy, scope, created, updated, refs, note}]. Use it to look at the queue; use wv_claim_queue to take a row.

{
  "tool": "wv_queue_list",
  "arguments": {
    "scope": "sprint-1"
  }
}

wv_claim_queue

Claims one pending queue row and evaluates the keep/delegate tripwire in one step. Both verdicts stamp the verified owner as claimedBy. Optional evidence (scope, touchedPaths, addedLines, persistent, requiresDiffRead) feeds the tripwire; with no evidence it keeps the item. The store follows the caller's captured team, and callers without one, or unbound callers, are refused. delegateRunId is correlation only and never grants ownership. Returns {claimed:true, id, verdict, firedRow, claimedBy, delegateRunId} or {claimed:false}; losing a concurrent claim reports claimLost.

{
  "tool": "wv_claim_queue",
  "arguments": {
    "scope": "sprint-1",
    "touchedPaths": [
      {
        "path": "docs/guide.md"
      }
    ],
    "addedLines": 12
  }
}

wv_mark_dispatched

Marks a claimed row dispatched once a worker is running; only the verified owner of the row can do this, and unbound callers are refused. The order is claim, write the brief with wv_write_dispatch, spawn the worker, then this call with queueId, storyId (the brief key) and dispatchHandle. Returns {dispatched:true, queueId, dispatchedAt}, {dispatched:false, error:stateConflict}, or a validation message when the brief is missing.

{
  "tool": "wv_mark_dispatched",
  "arguments": {
    "queueId": 7,
    "storyId": "DEMO-13",
    "dispatchHandle": "worker-handle-1"
  }
}

wv_resolve_queue

Resolves a claimed or dispatched row owned by your verified routine, queue-role identity or plain session (never another owner): prunes it and writes its compact key-ledger record atomically. Pass dispatchId to also run the success-signal and controller-verified preflight, which returns verifyFirst if unmet. Returns {pruned:true} or {pruned:false, error:ownerMismatch|invalidState}. wv_close_task is the stricter variant that always requires both conditions.

{
  "tool": "wv_resolve_queue",
  "arguments": {
    "id": 7,
    "dispatchId": "dispatch-1"
  }
}

wv_close_task

Closes a task only when it is accepted (the worker's signal_done succeeded) and controller-verified (wv_verify_done passed). Atomically prunes the queue row and records the key ledger; only the verified owner can prune its row. Returns {status:resolved, queueId}, {status:closureBlocked, missing:[...]} or {status:resolveRefused, error}.

{
  "tool": "wv_close_task",
  "arguments": {
    "queueId": 7,
    "dispatchId": "dispatch-1"
  }
}

wv_escalate

Raises a decision that affects more than one worker instead of acting on it. Pass sessionId, a one-line reason (truncated to 500 characters) and a non-empty involvedWorkers list. Inserts one pending agent-sourced queue row and never claims or changes another worker's state. Returns {queued:true, itemId}.

{
  "tool": "wv_escalate",
  "arguments": {
    "sessionId": "<your $CODESENSE_TAB_SESSION_ID>",
    "reason": "Two workers need the same schema file changed",
    "involvedWorkers": [
      "worker-a",
      "worker-b"
    ]
  }
}

Dispatch and verification

A dispatch is a four-field brief written before the worker starts, so the finish line is checkable rather than self-declared.

wv_write_dispatch

Writes a dispatch brief under a story_id key: task and acceptance (the Done-When) are required, context and constraints are optional, and scope is optional but only root is supported (the default). Any agent with this server can call it, a worker included. A dispatch with no checkable acceptance is refused. A brief is structural data, not instructions. Returns {id}.

{
  "tool": "wv_write_dispatch",
  "arguments": {
    "story_id": "DEMO-13",
    "task": "Write the Weft coordination reference page",
    "acceptance": "The page names all 34 wv_* tools and its examples validate"
  }
}

wv_dispatch_state

Reads the dispatch records for a story, newest first: {records:[{id, storyId, task, context, constraints, acceptance, state, scope, sessionId, createdAt, doneAt}]}. state is open or done. Read-only; it lets a reader check what finished means without asking the worker.

{
  "tool": "wv_dispatch_state",
  "arguments": {
    "story_id": "DEMO-13"
  }
}

wv_handoff_state

Reads the drafted handoff packets for a story, newest first: {records:[{id, storyId, sessionId, toRole, finding, refs, isDraft, createdAt}]}. Each packet is data, not authority (isDraft is always true). Read-only.

{
  "tool": "wv_handoff_state",
  "arguments": {
    "story_id": "DEMO-13"
  }
}

wv_verify_done

Re-checks a worker's three-leg done record before its queue row is folded: source-aware, in-scope work finished, packet delivered idempotently. Stamps controllerVerified only when every leg passes. Returns {verified, reason, failedLegs}; a dispatch with no done record returns verified:false with all three legs failed, because idle is not done.

{
  "tool": "wv_verify_done",
  "arguments": {
    "dispatchId": "dispatch-1"
  }
}

wv_read_recent

Observes a worker's recent terminal output as plain text. Pass the opaque handle the dispatch returned, not a session id. Returns {text, seq, altScreen}: altScreen is true while a full-screen program holds the alternate screen. Watching never drives: it holds no lease and cannot send input.

{
  "tool": "wv_read_recent",
  "arguments": {
    "handle": "worker-handle-1"
  }
}

wv_wait

Blocks until a worker finishes, without polling. Pass the worker handle and a timeoutS budget; until may only be "done". Resolves when the worker calls signal_done or its shell reports a command end, returning {resolved:true, status, exitCode}; on timeout it returns {resolved:false, timedOut:true} and writes no state.

{
  "tool": "wv_wait",
  "arguments": {
    "handle": "worker-handle-1",
    "timeoutS": 600,
    "until": "done"
  }
}

Peer reads

Bounded read access to a peer worker. Both tools are authorised only when your dispatch lists the peer under peers:.

wv_coord_read

Reads a peer's wv_coord contract body. Pass sessionId and contract. Returns {body}, {error:"not-authorized"} when your dispatch does not list the owner, or {error:"not-found"}. Coord is state, never a message or an approval.

{
  "tool": "wv_coord_read",
  "arguments": {
    "sessionId": "<your $CODESENSE_TAB_SESSION_ID>",
    "contract": "api-shape"
  }
}

wv_peer_read_file

Reads one file from a peer's worktree. Pass sessionId, peerName and relPath (relative to the peer's root). A path containing .. returns {error:"path-traversal"}; files over 256 KB return {error:"too-large", sizeBytes}. Success returns {contentUtf8}; other results are binary, not-found and peer-not-found errors.

{
  "tool": "wv_peer_read_file",
  "arguments": {
    "sessionId": "<your $CODESENSE_TAB_SESSION_ID>",
    "peerName": "worker-a",
    "relPath": "docs/guide.md"
  }
}

Approvals and assertions

The endorsement gate: an agent assertion counts for nothing until the owning human ratifies it.

wv_classify_action

Returns the endorsement tier (T1, T2 or T3, with reasons) a proposed action would enter, without writing any row. Call it before wv_write_approval to branch on the tier. Inputs are claim, preferredTier and the risk signals irreversible, blastRadius and confidence.

{
  "tool": "wv_classify_action",
  "arguments": {
    "claim": "Delete the stale branch",
    "preferredTier": "T2",
    "irreversible": true,
    "blastRadius": "low",
    "confidence": "high"
  }
}

wv_write_approval

Opens an endorsement for a Tier-2 or Tier-3 action. tier is your preferred tier; the picker may force T3 when two of the three risk signals hold, and the chosen tier is what is stored and returned. Pass sessionId whenever the chosen tier could be T3. Returns {id, tier, disposition}.

{
  "tool": "wv_write_approval",
  "arguments": {
    "tier": "T2",
    "claim": "Delete the stale branch",
    "irreversible": false,
    "blastRadius": "low",
    "confidence": "high",
    "sessionId": "<your $CODESENSE_TAB_SESSION_ID>"
  }
}

wv_settle_approval

Resolves a pending approval to ratified or revoked by id. It is the reply path for both T2 (window expiry) and T3 (owner approval). Idempotent: settling an already-settled or unknown id is a no-op. Returns {settled}.

{
  "tool": "wv_settle_approval",
  "arguments": {
    "id": 3,
    "disposition": "ratified"
  }
}

wv_post_assertion

Posts an agent assertion through the endorsement gate as a pending row that counts as nothing until the owning human ratifies it in the app. Inputs: sessionId, claim, channel, and an optional runId that must belong to the caller. The text in claim is scrubbed and size-bounded, and run provenance comes from the trusted session, not from arguments. Returns {id}.

{
  "tool": "wv_post_assertion",
  "arguments": {
    "sessionId": "<your $CODESENSE_TAB_SESSION_ID>",
    "claim": "Release notes are ready for review",
    "channel": "releases"
  }
}

Tier-2 windows

A Tier-2 approval carries a revocation window. The clock freezes while the owner is away.

wv_open_t2_window

Arms the lazy-consent window on a pending T2 approval. It records surfacedSession (the session the item was shown to the owner in; the window may auto-close only when later checked in this same session), the open time on the server clock, and durationS, the present-time budget. It is rejected if the id is not a pending T2, surfacedSession is blank, or durationS is not positive. Returns {opened:true}.

{
  "tool": "wv_open_t2_window",
  "arguments": {
    "id": 3,
    "surfacedSession": "<surfacing session id>",
    "durationS": 3600
  }
}

wv_check_t2_window

Evaluates a window at the server clock without changing it. A spent budget reports lapsed only when checkSession matches the surfacing session; otherwise expiredWrongSession. Returns {state, elapsedS, remainingS} where state is notOpen, open, paused, expiredWrongSession or lapsed.

{
  "tool": "wv_check_t2_window",
  "arguments": {
    "id": 3,
    "checkSession": "<surfacing session id>"
  }
}

wv_close_t2_window

Auto-ratifies a T2 approval whose window has lapsed, only when checkSession matches the surfacing session. A paused, open, wrong-session, revoked or already-settled window is a no-op, and an owner's explicit reply is never overwritten. Returns {ratified}.

{
  "tool": "wv_close_t2_window",
  "arguments": {
    "id": 3,
    "checkSession": "<surfacing session id>"
  }
}

wv_pause_t2_windows

Freezes the clock of every live T2 window at the server time. Idempotent: an already-paused window is skipped. Returns {paused: <count>}. wv_set_posture calls this on the move to away.

{
  "tool": "wv_pause_t2_windows",
  "arguments": {}
}

wv_resume_t2_windows

The counterpart of the pause: banks each paused span into the window's accumulated pause, then restarts the clocks. Idempotent. Returns {resumed: <count>}.

{
  "tool": "wv_resume_t2_windows",
  "arguments": {}
}

Decisions, attention and watches

The Weft ledger: standing decisions, items waiting on a human, per-source read watermarks and per-scope watches.

wv_write_decision

Writes a bounded standing decision. Required: date, decision, constrains (the one artifact it binds) and endsWhen (the retirement condition; a blank one is refused). The stored owner is the verified caller. Returns {id}.

{
  "tool": "wv_write_decision",
  "arguments": {
    "date": "2026-10-23",
    "decision": "Docs pages describe mechanisms only",
    "constrains": "codesense-docs reference pages",
    "endsWhen": "The docs policy is replaced"
  }
}

wv_retire_decision

Marks a standing decision superseded by id so the triage intent-check stops matching it. Idempotent: an already-superseded or unknown id is a no-op. Returns {retired}.

{
  "tool": "wv_retire_decision",
  "arguments": {
    "id": 12
  }
}

wv_list_overdue_harvests

Lists active decisions still pending (no drafted artifact) whose date is more than 24 hours before nowUnix (epoch seconds). An agent reads them to draft the missing artifact. Read-only. Returns [{id, date, decision, constrains, endsWhen, owner, source}].

{
  "tool": "wv_list_overdue_harvests",
  "arguments": {
    "nowUnix": 1792800000
  }
}

wv_upsert_attention

Writes an item that needs a human response into the attention ledger the Board reads. Omit id to create (a non-blank summary is required; state defaults to needs-you); pass id to update state (needs-you, waiting or done-unacked). Returns {id}.

{
  "tool": "wv_upsert_attention",
  "arguments": {
    "summary": "Approve the release notes",
    "state": "needs-you",
    "source": "github",
    "reference": "owner/repo#123"
  }
}

wv_upsert_watermark

Advances the read watermark for a (source, scope) key; source is slack, jira, github, local or agent. A second call on the same key advances lastHandled rather than inserting a duplicate. Returns {ok:true}.

{
  "tool": "wv_upsert_watermark",
  "arguments": {
    "source": "github",
    "scope": "sprint-1",
    "lastHandled": "comment-4812"
  }
}

wv_scope_state

Reads a scope's ledger row plus its non-closed watches, so a restarting agent can resume without re-interrogating the previous session. Read-only. Returns {scope, watches}; scope is null when unknown.

{
  "tool": "wv_scope_state",
  "arguments": {
    "scope": "sprint-1"
  }
}

wv_watch_list

Lists the watches a scope claims, {watches:[{scope, kind, ref, lifecycle, updatedAt}]}, where lifecycle is open, quiet or closed. Closed watches are omitted unless includeClosed is true. Read-only.

{
  "tool": "wv_watch_list",
  "arguments": {
    "scope": "sprint-1",
    "includeClosed": false
  }
}

Audit and posture

wv_audit_query

Reads the append-only write-audit trail, newest first, as [{id, tableName, operation, rowId, writtenAt}]. All filters are optional and ANDed: tableName, operation (append or mutate), sinceId/beforeId cursors, afterAt (epoch seconds). limit is clamped to 1–500 (default 100). Read-only, visible to all profiles.

{
  "tool": "wv_audit_query",
  "arguments": {
    "tableName": "wv_queue",
    "limit": 50
  }
}

wv_audit_prune

Deletes audit rows with writtenAt before cutoffSecs (epoch seconds) and returns {pruned:<count>}. It is the only maintenance mutation on the trail, and it writes no audit row of its own.

{
  "tool": "wv_audit_prune",
  "arguments": {
    "cutoffSecs": 1790000000
  }
}

wv_read_posture

Returns the scope's posture, {posture:"normal"|"away", windows:[{subclass, startMin, endMin}]}. A fresh store reads normal with no windows; a corrupt stored value falls back to normal.

{
  "tool": "wv_read_posture",
  "arguments": {}
}

wv_set_posture

Persists the posture, normal or away, with optional windows. When the value changes it triggers the matching Tier-2 pause or resume; setting the current value skips only the Tier-2 pause or resume; windows is always replaced, and an omitted windows becomes an empty list, so repeating {posture:"away"} clears any stored windows. Posture widens or narrows initiation and never grants authority. Returns {posture, changed, directive, windowsAffected}.

{
  "tool": "wv_set_posture",
  "arguments": {
    "posture": "away"
  }
}
