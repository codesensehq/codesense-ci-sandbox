Phase 08 · Build (parallel)

Amelia claims stories off the builder inbox and turns each into shipping code. CodeSense gives every story its own worktree, so five Amelias can work in parallel without stepping on each other.

Agent… Skill… Inbox… Trigger… Dashboard…

What this phase is for

This is where the code shows up. Each builder (Amelia × N) is an instance of bmad-build bound to one worktree + one story. A routine with a role_pending trigger hears of each message queued for the builder role, and a builder takes it with claim_role_messages.

This phase does not run blind — Scout monitors CI, Reviewer waits in the queue, and if Amelia hits a decision she can't make she escalates up to the Resolver and sleeps until the answer lands.

Massively parallel — shipping 5 stories at once

A sprint committed 5 stories. CodeSense creates 5 worktrees (one per story) via open_workspace. Each Amelia session binds to its own worktree + branch. Scout (role_pending on scout) catches a CI failure and inboxes the builder. Reviewer (role_pending on reviewer) picks up a merge-ready PR. The whole shape is N copies of the single-story loop, not a bespoke orchestration.

All local

5 Amelias on your Mac

Everything on-device. Fastest feedback loop, bounded by your CPU and the number of context windows you can open.

Hybrid

2 local + 3 remote

Keep the touchy ones local (where you want eyes on the diff) and offload the long-running builds to the private-account remote.

All remote

5 remote tabs, drive from the laptop

All five builders on the remote macbook. You drive from your laptop; merged work comes home through each story's PR.

Drop this into config/agents/amelia-builder/routines/builder-claim/routine.yml. A role_pending trigger fires once for each message queued for the builder role (send_role_message); in fresh mode it starts a new builder session, which claims the message with claim_role_messages. To nudge one long-running Amelia instead, use an inbox_idle trigger in wake mode: it types the task into her session when it sits idle at its prompt with unread mail.

Local vs remote

Local

Each builder's worktree is made beside your clone of the story's repo, at ../<repo>-wt/<story>, on the story's branch_name or feat/<story>. The agent-dag.html dashboard shows all five at once; click a node to go to that agent. Stop one from the Agents list (Stop…).

Remote (private-account)

Open the story workspace on the machine (open_workspace with machine_id) and its worktree is made there. A claim (claim_role_messages) is atomic, so a sixth builder started locally while three are busy remote can't take a story another builder holds.
