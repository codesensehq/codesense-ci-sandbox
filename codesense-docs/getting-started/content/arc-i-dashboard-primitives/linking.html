Arc I · Linking

A plain <a> tag knows where to go.

Links inside a dashboard are plain <a href="…"> tags. The viewer intercepts clicks on anything that looks like a doc path, routes same-tab by default, opens a new tab on ⌘-click, and shells out to the OS for http(s):// and mailto:. You almost never call a navigation verb by hand — the link interceptor does the right thing. This page lists what the interceptor recognises, when to reach past it with the bridge, and how to deep-link into the explorers.

What the interceptor recognises

The bridge injects a script before your doc runs that attaches a global click listener. It emits codesense:navigate for any link whose href ends in a known doc extension; the host receives the event and opens the file in the right place:

LinkWhat happensWho routes
href="./notes.md" Open the doc in the same tab. Interceptor → codesense:navigate
href="./notes.md" + ⌘-click Open the doc in a new tab. Interceptor sends metaKey:true
href="./dashboards/x.html" Open the HTML as a centre tab. Interceptor
href="./x.htm" Same as .html. Interceptor
href="https://example.com" Open in the OS browser via codesense:external-link. Interceptor
href="mailto:you@…" OS mail handler. Interceptor
href="#section-id" In-page anchor jump, no interception. Browser default
href="./x.png" (image) Nothing — unknown extension, link opens inside the frame. Browser default

If you want to force a new tab without relying on the user holding ⌘, reach past the interceptor and call the bridge explicitly: 

// Same tab
codesense.openFile({ path: "docs/notes.md" });

// New tab
codesense.openFile({ path: "docs/notes.md", newTab: true });

Put a fragment in path to target a route or section, for example codesense.openFile({path: "docs/notes.html#section", newTab: true}). It is separated before file validation and delivered to the HTML or Markdown viewer, including when that file is already open or belongs to another team. HTML file routes are retained with their tab view state across viewer eviction and remount.

Deep links into the explorers

The three reference dashboards — primitives-explorer, mcp-explorer, schema-browser — all parse the URL hash into a <tab>/<name> pair and open that detail pane on load. Which means a dashboard, or any content page, can link straight to the right row without a search step:

ExplorerHash grammarExample
primitives-explorer #<tab>/<name> #invoke/queryContext · #classes/cs-sidebar-item · #tokens/--cs-accent · #events/codesense:theme · #contexts/right-pane
mcp-explorer #tool/<name> #tool/codesense_overview
schema-browser #<schema-slug> #agent-yaml · #routine-yml

A link into another explorer is the right call whenever a sentence in your dashboard names a specific primitive. The explorer's filter box is a good fallback, but a direct hash link lets a reader land exactly where you meant.

Linking inside your context repo

Content paths resolve relative to the file that holds the link, same as any filesystem link. From a dashboard at dashboards/validator.html: 

<!-- another dashboard in the same repo -->
<a href="./agent-dag.html">Agent DAG</a>

<!-- a story file one directory up -->
<a href="../stories/DEMO-20.md">DEMO-20</a>

<!-- the shipped docs org (always available alongside yours) -->
<a href="codesense-docs/getting-started/content/arc-i-dashboard-primitives/index.html"
   >Arc I primitives</a>

The host resolves against the context root for the active team, so a link that works in your workspace works in a teammate's workspace too — their copy of the file lives at the same relative path, just under a different user prefix on disk.

When you need custom routing

The interceptor is intentionally minimal. If your dashboard needs to route a click through a condition — "open the story if the agent is idle, otherwise open the inbox thread" — do the branch in JavaScript and call the matching navigation verb: 

document.getElementById("story-link").addEventListener("click", async (e) => {
  e.preventDefault();
  const agents = await codesense.invoke("agents", {});
  const target = agents.some((a) => a.state === "running")
    ? { verb: "openFile", args: { path: "stories/DEMO-20.md" } }
    : { verb: "gotoAgent", args: { agentId: "amelia-primary" } };
  codesense.invoke(target.verb, target.args);
});

Keep the fallback href populated — a user who ⌘-clicks the link should get a plain file open even if your script hasn't attached yet.

Agent-list actions

Use codesense.act for the same actions as the native agent list. Handles come from codesense.sessions(); workspace ids and team keys come from agentList.

Keep live list rows as plain objects with stable id values. Pass a layoutKey(row) describing their markup and captured controls to kit.virtualList; patch live text, status, counts and tooltips with update(element, row, index). Initialize those same fields in render. Heartbeats then keep the row, hover and focus intact, and inserts do not rebuild the rows below them. Event handlers that use live fields should read the current row stored by the updater. 

<div id="agent-list" style="height:240px;overflow:auto"></div>
<script src="/kit/v1/kit.js"></script>
<script src="/kit/v1/virtual-list.js"></script>
<script>
const kit = codesense.kit;
function patchAgent(el, row) {
  el.session = row;
  el.querySelector(".name").textContent = row.displayName || row.id;
  el.querySelector(".status").textContent = row.effectiveStatus || row.state;
}
const list = kit.virtualList({
  container: document.getElementById("agent-list"), rows: [], rowHeight: 28,
  layoutKey: row => row.id, // This example always has the same two spans.
  render(row) {
    const el = kit.h("button", {type: "button"},
      kit.h("span", {class: "name"}), " · ", kit.h("span", {class: "status"}));
    el.onclick = () => codesense.act("gotoAgent", {agentId: el.session.handle});
    patchAgent(el, row);
    return el;
  },
  update: patchAgent
});
codesense.subscribe("sessions", {onChange: snapshot => list.setRows(snapshot.snapshot)});
codesense.ready();
</script>

If a row's shape changes, include that shape in its layout key, for example JSON.stringify([row.id, row.kind, row.hasActions]). Omit layoutKey to rebuild on any payload change. The built-in agent-list source shows the full layout signature and per-row updater, including pinned copies and workspace tallies. The stable live-list recipe covers local rows, hub windows and keyed lists. No non-enumerable properties or separate patch pass are needed.

Agent rows use click for the terminal; Enter, Space, Q and Option-click for Quick view; and M or the Messages button for the inbox chat. Offline rows keep Enter/Space for showing the agent; Q and Option-click do nothing. M still opens their inbox. Use the host popover and return focus to the row when it closes:

Hover or focus a row to replace its state word with Quick view and Messages actions. At dock widths of 260px or more, Pin/Unpin appears alongside them. A pinned row’s pin also unpins it at narrower widths. An amber messages badge counts unread messages from that agent that need you; open it to read the conversation. It does not add to the number of agents waiting on you.

Working covers running, thinking and tool use. A parent with active subagents stays Working with a subagent count, even while its own turn is idle or stalled. Needs-you, crashed, offline and ended states take precedence. Blocked agents count as needs-you. Needs-you appears in place; it does not move a row ahead of its crew or manual pins.

The waiting and working tallies filter the list. These filters, search, arrangement, manual pins, folds and hidden teams persist in the shared ui:dock state and restore when the app reopens. 

// Give the row a stable id and its main button data-cs-focus-key="main".
codesense.onFocusReturn(({anchorId}) => {
  document.getElementById(anchorId)?.querySelector('[data-cs-focus-key="main"]')
    ?.focus({preventScroll: true});
});
const rect = row.getBoundingClientRect();
await codesense.showPopover({
  kind: "agent-quick-send", // "agent-inbox-chat" for M or Messages
  sessionId, anchorId: row.id,
  anchorRect: {x: rect.x, y: rect.y, width: rect.width, height: rect.height}
});
// Team/workspace + controls open the existing launch sheet.
await codesense.openLauncher({team: "web", task: ""});

Pass {org: "beta", team: "ops", task: ""} to launch in that admitted team; team-only uses the active org, unknown or unadmitted teams reject, and Launch does not preselect a workspace. Role chips stay inert; use Role in the host row menu to edit them. 

await codesense.act("moveWorkspace", {teamKey, workspaceId, before: otherWorkspaceId});
await codesense.act("launchUnder", {handle, task: "Review the change"});
await codesense.act("openAgentInbox", {handle});
await codesense.act("gotoAgent", {agentId: handle, preserveFocus: true});

moveWorkspace takes exactly one of before or after and returns {moved: boolean}. An unknown id or unchanged placement returns false; the new order arrives through the existing agentList update. Its MCP twin is reorder_workspace. The separate move_workspace tool moves a workspace between machines.

For card drag or Option+↑ / Option+↓, read the state row's pane.workspaceOrder[teamKey]: workspace ids in the tray's resolved order, delivered only for teams the frame may see. An id in this list has a tray pill and can be a move anchor. Keep cards without pills in their slots; never anchor on one. Move only in By team with no search, status, workspace, group or agent filter: hidden cards make the drop position ambiguous. A single movable card has nowhere to go. 

const state = snapshot.snapshot.find(row => row.rowType === "state");
const movable = state.pane.workspaceOrder[teamKey] || [];
if (movable.includes(workspaceId) && movable.includes(otherWorkspaceId)) {
  const {moved} = await codesense.act("moveWorkspace", {
    teamKey, workspaceId, before: otherWorkspaceId
  });
  if (!moved) announce("This card couldn't move. Its place in the order may have changed.");
  // Architecture: wait for agentList to deliver the new order before reordering cards.
}

Use full row heights, including undrawn virtual rows, to pick a gap by card-block midpoints. Keep the drop in its team. Show a lifted preview, placeholder and drop line; announce refusals and successful moves. Capture the pointer on a stable container and clear the gesture on Escape, pointer cancellation, capture loss, blur or teardown. Escape during a drag is handled; otherwise the SDK returns to the terminal. After a keyboard move, follow the card only while it retains focus. Cancel pending focus restoration when focus leaves the card or frame, including Escape to the terminal.

Put data-codesense-row on agent rows and workspace cards and omit menu declarations to get the standard host menu. Give each row and card a stable anchor id. Quick view, Launch under and Stop run in the host; Stop's confirmation cannot be answered by the pane. On focus return, restore the row's control or card's heading, or the first visible control when the anchor has gone.

launchUnder opens the launch sheet with that running agent's team, manager and story. The optional task fills the sheet; the person still clicks Launch. An unknown handle rejects with unavailable: no such agent. openAgentInbox reveals a running agent and opens its inbox rail, or rejects with unavailable: agent is not running. Both return {opened: true} when opened.

gotoAgent accepts a handle or bare agent definition id and returns {located, outcome}. Set preserveFocus: true to select and reveal the terminal tab while keeping keyboard focus in your frame. Omit it to focus the terminal.

Build a file tree pane

Declare file-nav right-pane slots. Subscribe to files with {scope: "team"} (or private, story with storyId, agent with agentId). Subscribe to a folder with dir; follow each snapshot's cursor with page("files", cursor, options). Use ui:file-nav for expanded paths, scope and selection. The host supplies recent story and team agent choices in sources.

codesense.kit.virtualList({container, rows, tree: true, rowHeight: 24, render, expanded, onExpandedChange, onActivate}) accepts nested children and reuses the list's windowing. It supplies tree ARIA, indentation, roving focus, arrows, Home/End, PageUp/PageDown and type-ahead. setExpanded, toggle, focus and reveal control its tree state.

Use onRangeChange(rows) to subscribe only to expanded folders in the rendered window. Keep their last listings when unsubscribing; persist a bounded cache and scroll position in ui:file-nav so a reloaded pane can paint before its live subscriptions reconcile. Prefetch one level below expanded folders with files.list, without retaining offscreen subscriptions. Keep cached rows visible on a failed refresh and put a Retry action under the affected folder. Await codesense.unsubscribe(...) before reopening that subscription; it resolves after the host has released the old backend subscription.

codesense.onCommand(command => {
  if (command.id !== "nav.reveal-file") return;
  const path = command.args.path;
  // Clear a local filter, load and expand the path's ancestors, then:
  tree.reveal(path);
});

The host writes the selected path to ui:file-nav.selected and sends nav.reveal-file for the same native tab-header action, even when the path is already selected. A pane should restore its saved scroll position on reload and reveal again only for a changed selection or this explicit command.

const row = {kind: "file", path: file.path}; // also "story" or "epic"
element.dataset.codesenseRow = JSON.stringify(row);
// No custom context-menu handler: the host opens the native file menu.
element.onclick = () => codesense.openFile({path: file.path, preview: true});
element.ondblclick = () => codesense.openFile({path: file.path, preview: false});
// F2 / Delete: run the same host action, with the native dialog and inherited warning.
await codesense.showMenu({builtinAction: "builtin:rename", row, anchorRect});
await codesense.showMenu({builtinAction: "builtin:delete", row, anchorRect});

Those built-ins can also appear in items. The per-team file-actions owner serves both native navigation and dashboard rows, including inherited paths. Folder rows use kind file; story and epic rows use their respective kinds. A deleted row carries no menu tag. Drag to a folder with files.move({from, to}).

Use data-surface="sidebar" and semantic --cs-bg, --cs-fg, --cs-selected, --cs-git-* and --cs-story-<status> tokens. Theme updates apply live. Declare Collapse all folders without a default chord; handle the existing nav.focus-left-search command to focus the filter. Escape calls focusTerminal(). A meta-click can send the path without Enter through sendPrompt({handle: "active", text: file.path, submit: false}).
