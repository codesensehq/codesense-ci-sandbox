Arc I · Dashboard patterns

Fast, light dashboards

A dashboard that opens at once and never floods the Mac: a cached list, totals only for the rows on screen, and each section reading when it is opened. The patterns are in the kit already, with the same names in the app (codesense.kit, also window.CS) and on a shared page (CS). Use them instead of writing your own cache, queue or loading states.

Six rules

  1. One entry, one boot. CS.boot picks the host from the bridge that is present. Never test script[src], currentScript or a file name: the share host strips every script src, and the page would stay blank.
  2. Paint the last answer first. Read the list with CS.cachedQuery. It paints from storage at once, then reads once.
  3. Ask totals for visible rows only. CS.visibleTotals watches the rows and asks one storyTotals call for the ids on screen.
  4. Read detail when it is opened. CS.section loads a <details> or a region when it opens or scrolls into view, with its own states.
  5. One budget per page. Every kit read goes through CS.budget: at most 2 in flight. A Mac that answers busy shows "Waiting for the Mac", never an error. A read frees its slot when it answers, when it is cancelled, or at the engine's 900-second backstop in the app (pass timeoutMs to an ask to change that). On a shared page each read also has the page's own limit of about 20 seconds; a read that goes over reads "The Mac didn't answer in time".
  6. Never a false zero. Show every figure through CS.value: known, Counting…, Loading…, Unknown · reason or Not loaded.

Tabbing away and back never reloads

A dashboard's state stays in memory and shows at once when you come back. The kit makes no read on visibilitychange, focus, blur, pageshow or online: hiding the page only pauses timers (poll intervals, totals follow-ups), and showing it only starts them again. A section that has read shows it again however long the page was hidden or scrolled away. Write your own page the same way: never read from those events.

Live data patches in place

A data-change event names what changed, and only that is read again. CS.dataChanged({ids, keys}) asks visibleTotals again for the visible rows named by ids (one ask, just those ids; the others are marked and asked when they scroll in) and re-reads only the sections named by keys, quietly, in place; paint the result with CS.keyedRegion so only the changed rows move. In the app, a hub codesense:delta carries the ids (upserts[].id and removes). The payloadless nudges (agent-activity-changed, worktrees-changed and the like) and the hosted viewer and subscribe notices carry none, so they name nothing: nothing requeries a whole list or story on an event. Call refresh() yourself, deliberately, when you want everything again.

The pieces

CallWhat you get
CS.boot({render, queries, key}) One entry for both hosts. render(ctx) runs at once, from cached answers, and again whenever a query changes; keep it idempotent. ctx.host is "app" or "hosted". Returns {host, call, subscribe, state, refresh, stop}.
CS.cachedQuery(name, args, {maxAgeMs, key}) peek() gives {value, ageMs, state} with state one of cached (from storage, younger than maxAgeMs), stale (older; one read is revalidating it), fresh (just read) or none (nothing yet). A failed read keeps the value and sets error. Storage is keyed by host, dashboard key and args; a frame with no storage uses memory. maxAgeMs is required.
CS.visibleTotals(container, {rowSelector, idAttr, root}) Gathers the ids of visible rows, batches and debounces them into storyTotals, and caches each id with its computedAtMs. A pending id, or one that failed in a way that clears by itself, is asked again with backoff (2, 4, 8, then every 16 s) while it is visible. A row that already shows values and is only refreshing is asked at most every 60 s, backing off to 240 s, while it is visible. An id that was never in view is never asked. Hiding or showing the page, or rows coming back into view, asks nothing for an id that was already asked: only an id never asked (or one a data-change event named while off screen) is asked when it scrolls in, and a pending row that scrolls back in is picked up by the follow-up timer. An ask refused for some ids is halved down to the single ids refused; only a refusal of the whole verb (query_not_declared, not_declared, undeclared, access_ended, a verb that is not allowlisted) is known from one ask. arg_not_allowed on many ids is probed with the first, middle and last id in one round: if all three are refused before the page has had any answer, the page is treated as unpinned (every id refused, one console warning) until refresh({refused: true}), so check the storyIds pin in your manifest. That is a deliberate trade-off: a page whose first, middle and last visible ids are all out of pin on its very first read looks the same as one with no pin at all. Once any answer has come back, nothing is inferred: only the ids actually refused are marked, and the rest are asked. A named id is asked at once; if it comes back pending or failed in transit it is asked again, alone, after 2, 4, 8 then every 16 seconds, and if it comes back refreshing it moves to the 60 to 240 s interval. A story that fails (refused, or left out of an answer) is left out of every automatic pull; refresh({refused: true}) asks refused ones again. An ask refused with invalid_args, not_approved, arg_not_allowed or query_invalid is halved and asked again to isolate the refused ids; any other thrown error is asked again whole, with backoff. get(id) returns {kind: ready|pending|error, totals, computedAtMs}.
CS.batchTotals(ids) The same reader for a fixed list: one storyTotals call per 500 ids (fewer on a shared page, where an ask is 2 KB).
CS.section(el, {key, load, render, when, scope}) One bounded read when a <details> opens (when: "open") or a region scrolls into view ("visible"). It draws a skeleton, empty, Unknown · reason (when load resolves {unknown: reason}), an error with Retry, "Read N min ago", and "Still reading (N s)" with Cancel, which frees the read at once. A read a minute old offers a small Refresh button. scope names the owner of the answer (the selected story): an answer for another scope, or one for a scope closed with CS.closeScope, is dropped.
CS.budget({inFlight, minGapMs, bytesPerMinute}) Configures the page-wide queue every kit read goes through (default 2 in flight). stats() and onChange report calls, bytes, in flight, queued, waiting and busy. Add ?csmeter=1 to the page URL for a meter.
CS.paced(query, {key, inFlight, ttlMs, minGapMs}) A paced read: runs no closer than minGapMs apart, shares one trailing run among a burst, retries a busy Mac with backoff and restarts a dead cursor silently. observe(el, args) reads when the element nears the viewport.
CS.value(v, {pending, waiting, loading, error, unavailable, stale, ageMs}) An element for a figure. A known 0 stays 0; pending reads Counting…, distinct from loading, unknown and error; waiting (pass CS.budget().stats().busy) or a busy error reads Waiting for the Mac. CS.errorText(err) turns any kit read's error into a sentence, never a raw code: "The Mac didn't answer in time", "The Mac is offline", "The Mac is busy", "This page can't show this" (a refusal), "Access to this dashboard has ended", "The Mac couldn't answer", "Too much to show at once", else "Could not read this". CS.errorKind(err) says whether it is a refusal, transient or other. And CS.value({error}) uses it. CS.stateBanner({offline, stale, asOf}) says when the page shows old data; CS.partial(known, total) says "Totals loading · 3 of 9 stories".
CS.keyedRegion(el, scope) Repaints a list in place when the selection changes, keeping focus, text selection, scroll and a click in progress. paint(items, {key, render}, forScope) drops a paint for a scope that is no longer current.

Handles and options

CallHandle and options
CS.cachedQuery Returns {peek(), refresh(), onChange(cb), ready}. refresh() reads again and resolves the new peek(); onChange(cb) calls cb(result) on each answer or failure and returns an unsubscribe; ready is the promise of the read in flight. Asking again for the same name, args and key returns the same handle; the same with another maxAgeMs gets its own (same stored answer, own label). On a shared page the frame is sandboxed (an opaque origin) and has no storage, so the answer is kept in memory for the page's life: warm within the page, not across loads.
CS.section Options: key, load, render, when, scope, isEmpty(value) (default: an empty array or null), emptyText, stillMs (default 15000). Returns {refresh(), cancel(), stop(), loaded}. A section reads once: after Cancel or an error it shows that again however often it scrolls back in, and only Retry or Refresh (a small button once a read is a minute old), dataChanged({keys}) naming it, or its busy backoff reads again. A render that throws shows "Could not show this."
CS.visibleTotals Options: rowSelector, idAttr (default data-id), root, debounceMs, onChange(handle) (after each answer), onError(err) (a failed ask; it is asked again with backoff). Returns {get(id), ids(), known(), refresh({refused}), changed(ids), stop()}. stop() cancels its reads in flight.
CS.keyedRegion Returns {paint(items, {key, render, version, update}, forScope), setScope(scope), text, defer, flush, stop()}. Without version a row's version is the JSON of its item, so a changed row repaints. setScope(next) names the scope that may paint now; a paint for another scope is dropped.
kit.call The raw bridge verb, in the app only, and not budgeted: use it for actions. Reads go through kit.query, queryAll, storyTotals and the patterns above, which share the budget. Bytes are counted only when bytesPerMinute is set or ?csmeter=1 is on.

A complete example

A story list that opens warm, asks totals for the rows on screen and reads a story's commits only when its section opens. The same file runs in the app and on a shared page: load cs-live.js there (or nothing extra in the app, where the kit is injected). 

<div id="banner"></div>
<div id="list" style="height: 480px; overflow: auto"></div>
<details id="commits"><summary>Commits</summary></details>
<script>
  var list = document.getElementById("list");
  var selected = null;       // the story the page shows; also the scope of its sections
  var section = null, totals = null, rows = [];

  CS.budget({ inFlight: 2 });
  var region = CS.keyedRegion(list, "list");

  // Rows are painted in place, by key. A row's version names what it shows, so it repaints only when that changes.
  function paint() {
    region.paint(rows, {
      key: function (story) { return story.id; },
      version: function (story) {
        var entry = totals && totals.get(story.id);
        return [story.title, entry ? entry.kind + ":" + (entry.computedAtMs || entry.error || "") : "-"].join("|");
      },
      render: function (story) {
        var entry = totals && totals.get(story.id);
        var sessions = entry && entry.kind === "ready" ? entry.totals.sessions : null;
        var row = document.createElement("div");
        row.className = "row";
        row.setAttribute("data-id", story.id);
        row.innerHTML = "<span class=title></span> <span class=sessions></span>";
        row.querySelector(".title").textContent = story.title || story.id;
        row.querySelector(".sessions").replaceChildren(
          CS.value(sessions, {
            waiting: CS.budget().stats().busy,
            pending: !entry || entry.kind === "pending",
            error: entry && entry.kind === "error" ? entry.error : false,
            unavailable: entry && entry.unavailable && entry.unavailable.sessions,
          }),
        );
        row.addEventListener("click", function () { choose(story.id); });
        return row;
      },
    }, "list");
  }

  CS.boot({
    key: "story-list",
    queries: { stories: { name: "queryContext", args: { where: { kinds: ["story"] }, limit: 50 }, maxAgeMs: 60000 } },
    render: function (ctx) {
      var stories = ctx.state.data.stories;
      document.getElementById("banner").replaceChildren(
        CS.stateBanner({ stale: stories.state === "stale", asOf: Date.now() - (stories.ageMs || 0) }) || "",
        stories.error ? CS.errorText(stories.error) : "",
      );
      rows = (stories.value && stories.value.rows) || [];
      paint();
      // Totals are asked for the rows on screen only; a live event naming ids is CS.dataChanged({ids}).
      if (!totals) totals = CS.visibleTotals(list, { rowSelector: ".row", root: list, onChange: paint });
    },
  });

  // One section per region, loaded when it opens; a late answer for the story you left is dropped.
  function choose(id) {
    selected = id;
    if (section) section.stop();
    section = CS.section(document.getElementById("commits"), {
      key: "commits:" + id,
      scope: function () { return selected; },
      load: function (ctx) { return ctx.read("storyChanges", { storyId: id, limit: 20 }); },
      isEmpty: function (value) { return !value.commits || !value.commits.length; },
      render: function (value, into) { into.textContent = value.commits.length + " of " + value.total + " commits"; },
    });
  }
</script>

Review the six states

Every dashboard is reviewed in six states, and ships a screenshot of each:

  • cold: nothing cached. Skeletons and Counting…, never a zero.
  • warm: the last answers are cached. The page paints them at once and says how old they are.
  • section: a section is reading slowly. It shows "Still reading (N s)" with Cancel.
  • switch: the selection changed. The shell stays; late answers for the old selection are dropped.
  • offline: every read fails. The page shows its offline banner and keeps what it had.
  • return: the page was hidden for ten minutes and is shown again. Zero reads, the DOM identical, scroll and focus kept.

Source checkouts get scripts/lib/dashboard-state-fixtures.mjs (stateFixture, bridgeScript, shootStates) for a Playwright test on a virtual clock (page.clock), and scripts/lib/dashboard-check-rules.mjs for the source rules below.
