Slots and pane shapes

Choose a right pane or the dock, then adapt to the slot context. The host owns the surrounding chrome; your HTML owns its content.

Two slots

The right-pane holds several panels beside the current surface. The dock holds one dashboard in the Agents area. Both can appear docked or as an overlay. Declare supported slots in HTML; the generated slot contract names their current widths, grant ceilings and host responsibilities. 

<meta name="codesense:slots" content="right-pane dock">
<meta name="codesense:capabilities" content="sessions:read">

pane_write creates a custom pane; pane_open reveals its right-pane panel. Choosing a dock replacement currently requires the person's Settings. A centre HTML tab and a rich inbox message are other rendering routes, not slot ids. Historical baseline views have no live bridge.

codesense.setBadge({ count: 3 }) publishes a pane badge; setBadge(null) clears it. The closed right-pane edge shows the last known count for default paused panes. Refresh and publish again when shown. Architecture: to keep a badge fresh while hidden, declare <meta name="codesense:badge" content="live"> and update only the count in hidden callbacks. Policy: the built-in Inbox opts in; other panes default off. Delivery is coalesced every 2 seconds for at most 4 hidden frames. See live badges for the cost and Inbox example.

Pane manifest

Declare slots, surface, capabilities and commands in the pane's HTML head. The generated pane declaration reference lists every field; the slot contract lists supported slots.

Read slot context

const cs = window.codesense;
cs.onSlotContext(context => {
  document.body.dataset.narrow = String(context.narrow);
  document.body.dataset.presentation = context.presentation;
  const team = context.team; // {org, team} or null
  // context.slotId is "right-pane" or "dock" in these slots.
});
cs.ready();

Every pane must call ready() once its first useful state is painted, or the host reports that it didn't finish starting within 30 seconds; see Lifecycle and liveness. Register onSlotContext before ready(). The host sends context after readiness and again when width, presentation, selection or team changes. Use context.narrow to hide secondary detail, wrap long labels and keep keyboard targets usable; avoid a fixed page width. Read current fields in the SDK typings.

Team binding

A right pane keeps its team binding. The dock follows the active context: the host rebinds its grant and the SDK resyncs subscribed topics when the team changes. Read the new context.team for the binding and the snapshot's viewKey for the data scope. Clear cached rows when that view changes. Under the Open policy the all view can stay unchanged across team switches. LiveHub subscriptions carry the permitted view, so do not poll or invent a team filter to bypass it.

Theme tokens arrive through the host. Use the generated tokens with standalone fallbacks, and let the host own section headers, resize, drag and maximize controls.

File navigation panes

A pane can declare <meta name="codesense:slots" content="file-nav"> and files:read (plus files:write for mutations). The file-nav slot has one body, follows the active team, and leaves width, resize and collapse to the host. The native file list remains the default. When a compatible pane is listed, Settings › General › “Use the classic file list” selects it.

Use files.list for a one-off read and subscribe('files') for live rows. Subscribe once per directory or scope, keep the returned revision, and render the current snapshot on change. The host feeds this from its existing file watcher. Never poll, add a watcher, or refresh the whole pane after every delta.

<meta name="codesense:slots" content="file-nav">
<meta name="codesense:capabilities" content="files:read">
<ul id="files"></ul>
<script type="module">
const options = { scope: 'team', window: [0, 200] };
function render(rows) {
  document.querySelector('#files').replaceChildren(...rows.map(row => {
    const item = document.createElement('li');
    item.textContent = row.name;
    return item;
  }));
}
const first = await codesense.files.list({ scope: 'team' });
render(first.rows);
await codesense.subscribe('files', {
  ...options, onChange: snapshot => render(snapshot.snapshot)
});
codesense.ready();
</script>

Rows have id, path, name and kind: dir|file|story|epic, with file size and mtime where available. Pass dir to list a folder, scope: 'private' for your private space, scope: 'story', storyId for the default hydration closure, or scope: 'agent', agentId for an agent's full key and context want set. Reads currently exclude parent-team content. A missing or denied path has the same “File not found” result. A rename arrives as one remove and one upsert.

Views start with at most 200 rows; request more with codesense.page('files', snapshot.cursor, options). Stop with codesense.unsubscribe('files', callback, options). files.read({path,maxBytes?}) returns {text?,bytesUrl?,size,truncated,sha256}; text is capped at 1.5 MB, and a relative /viewer/… URL streams large or binary files in the frame. Mutations are files.create({path,content?,onCollision:'keep-both'|'fail'}), files.move({from,to}) and files.delete({path}), using the same Rust operations and results as their MCP twins.

Subscribe to ui:file-nav for the active team's {expanded,selected?,scope?}. Save folder changes with codesense.setUiState('ui:file-nav', {expanded: paths}). The native file list and pane use one expansion store, so switching between them keeps your place. This state belongs to each team; the pane choice belongs to the org profile.

Native navigation model

stories is a windowed, team-wide topic. Its grant-derived team: view includes story, epic, doc and main-doc rows, keyed by path. Stories carry storyId, title, status, role, label, ready, blockedBy, dependencyCount, mark, sprint, metadataValid, metadataInvalidReason. lensRole preserves the native lens normalization separately from the rail’s raw taxonomy role, including off-taxonomy statuses. Titles are declared titles without a repeated id; absent values are null. Epics carry recursive total and done counts and a rolled-up mark. Docs and main docs carry ownerPath, so list order can match native.

The existing full-team scan and watcher feed the native graph, taxonomy, marks and counts. Rust LiveHub delivers snapshots and deltas; do not poll. files rows additionally carry starterPage, mergeMarked, shadows, overrides, installedSourceRepo, repoGlyph, repoTint. Installed groups retain their native installed:// paths.

ui:file-nav mirrors the native lens: source ({kind:'clone'|'private'} or {kind:'worktree',id}), view (files, changes, history), lens (everything, needs, agents, ready, active, review, blocked, not_started, done), arrange (folders, stage), storiesOnly, doneOpen and historyBranches. The native viewer store owns these fields; dashboard writes use its setter. Selection and expansion remain shared.

const cs = window.codesense;
const first = await cs.subscribe('stories', {
  window: [0, 200], onChange: renderStories
});
// Use first.cursor with cs.page('stories', first.cursor) to load more.
await cs.setUiState('ui:file-nav', {lens: 'ready', arrange: 'stage'});
const rail = cs.kit.stageRail('not_started', true);
const mark = cs.kit.statusMark('question');
const file = cs.kit.fileKindIcon('dashboard');
const picked = await cs.showMenu({anchorRect, items: [

The kit's rail (18×14), mark (7×7) and file icon (14×14) are generated from native renders. They include native animation, reduced-motion and ink classes, --cs-status-needs, rail fill/empty tokens and --cs-sidebar-selected-text. Menu icons accept a kit icon name or a native glyph descriptor. Radio and segmented selections return the chosen item's id through the ordinary menu result.

Native menus, story opens and glyph options

A file-nav pane can hand its View, Show stories and Arrange controls, a story's status picker and the new-file dialog to the app instead of redrawing them. Pass type: 'native' with nativeSurface: 'nav-filter', or 'nav-status' with row.path naming the story. Run the new-file dialog directly with builtinAction: 'builtin:new-file'; it opens at the content root. Open a story's workspace with openWorkspace and target: {kind: 'story', path}. That path form opens the visible workspace, needs the launch grant and rejects headed: false before doing anything; use storyId for a background open.

const cs = window.codesense;
filterButton.append(cs.kit.navGlyph('grouped'));
filterButton.onclick = () => cs.showMenu({
  type: 'native', nativeSurface: 'nav-filter',
  anchorRect: filterButton.getBoundingClientRect()
});
statusDot.replaceChildren(cs.kit.statusMark('question', {size: 8, still: true}));
statusDot.onclick = () => cs.showMenu({
  type: 'native', nativeSurface: 'nav-status', row: {path: story.path},
  anchorRect: statusDot.getBoundingClientRect()
});
newFileButton.onclick = () => cs.showMenu({
  builtinAction: 'builtin:new-file',
  anchorRect: newFileButton.getBoundingClientRect()
});
openButton.onclick = () => cs.openWorkspace({target: {kind: 'story', path: story.path}});

kit.navGlyph takes changes, history or grouped. kit.statusMark takes {size: 6|7|8, still}; a menu item's {kind: 'statusMark'} icon accepts the same options (6 or 8). still drops the native motion.
