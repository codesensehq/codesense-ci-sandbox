Arc I · Tutorial · 10 min

A working dashboard in ten minutes.

You will finish this page with a real HTML file open as a centre tab, querying your context through the CodeSense bridge, re-rendering when the data changes, and respecting the theme. No build step. No framework. No install. If you want to see the finished file before the walkthrough, it's the full source block at the bottom — copy it, drop it under dashboards/ in your team's content folder, open it.

Walkthrough

  1. Make a file

    In your team's content folder, in an editable context repo (not the CodeSense docs org, which is read-only), create a folder dashboards/ and a file inside it: 

    dashboards/stories-in-flight.html

    CodeSense recognises .html files in the content tree. Open the file from the left nav, or press ⌘P and type its name: it renders in the dashboard viewer with the bridge already wired.

  2. Drop in the HTML skeleton

    The viewer injects everything it needs into a plain <html> document: the bridge, the theme tokens, the dashboard kit and the link interceptor. Put class="cs-app" on <body> to take the app's font, colours and background, and style anything else with the --cs-* tokens. 

    <!doctype html>
<html>
  <head>
    <meta charset="utf-8" />
    <title>Stories in flight</title>
    <style>
      body { margin: 0; padding: 24px; }
      h1   { margin: 0 0 12px; font-size: 20px; }
      .row { padding: 8px 12px; border: 1px solid var(--cs-border);
             border-radius: 6px; margin: 6px 0; background: var(--cs-surface); }
      .empty { color: var(--cs-muted-fg); font-style: italic; }
    </style>
  </head>
  <body class="cs-app">
    <h1>Stories in flight</h1>
    <div id="out" class="empty">Loading…</div>
  </body>
</html>

    Save it. The open tab reloads whenever the file changes on disk. You should see the heading and a Loading… placeholder on the app's theme.

  3. Add a <script>

    Everything after this point goes inside one <script> at the end of the body. You don't need to import anything: the bridge is injected before your script runs, and window.codesense is already defined. 

    <script>
  (function () {
    const out = document.getElementById("out");

    function render(rows) {
      out.innerHTML = "";
      rows.forEach((r) => {
        const div = document.createElement("div");
        div.className = "row";
        div.textContent = r.title + " · " + r.fields.status;
        out.appendChild(div);
      });
    }
  })();
</script>

    Nothing happens yet: you've defined render and taken a reference to the output div. The next step gives it something to render.

  4. Query your context

    codesense.queryContext(q) finds context files by their metadata and returns a Promise of {total, rows}. This query asks for stories that are in progress or in review, with their status: 

    const q = {
  where: { kinds: ["story"] },
  filters: [{ key: "status", op: "in", value: ["in-progress", "review"] }],
  select: ["status"],
  sort: ["status"],
};

codesense.queryContext(q).then((result) => render(result.rows));

    Save again. The Loading… placeholder is replaced with one row per story:

    Refund button · in-progress●
    Payment intents · review●

    Team content is read across every synced org unless you narrow it. To keep to this page's own team, read const {org, team} = await codesense.context() and add orgs: [org], teams: [team] to where.

  5. Re-render when the context changes

    A dashboard that reads once and freezes is a report. Swap queryContext for subscribeContext: it runs the same query now and again whenever the context changes (an agent moves a story, a file lands), and returns a function that stops it. 

    const off = codesense.subscribeContext(q, (result, err) => {
  if (err) {
    out.textContent = "Query failed: " + err.message;
    return;
  }
  render(result.rows);
});

    You don't poll and you don't manage sockets. The handler gets each new result.

  6. Tell the host it's ready

    Once the page has painted its first useful state, and after you've registered your handlers, call codesense.ready(). The host waits for it before it treats the pane as live. 

    render([]);        // first paint
codesense.ready(); // now the host knows the page is up

    A first codesense.subscribe(...) also counts, but subscribeContext does not, so always call ready() yourself. If neither arrives within 30 seconds, the pane shows "It didn't finish starting within 30 seconds" and falls back. See Lifecycle and liveness for the full rule.

  7. Watch it update

    With the file open as a centre tab, change a story's status to review (in the story's metadata, or have an agent do it). The list updates without a reload.

The whole file

Everything above, in one block. Paste it into dashboards/stories-in-flight.html in your team's content folder. 

<!doctype html>
<html>
  <head>
    <meta charset="utf-8" />
    <title>Stories in flight</title>
    <style>
      body { margin: 0; padding: 24px; }
      h1   { margin: 0 0 12px; font-size: 20px; }
      .row { padding: 8px 12px; border: 1px solid var(--cs-border);
             border-radius: 6px; margin: 6px 0; background: var(--cs-surface); }
      .empty { color: var(--cs-muted-fg); font-style: italic; }
    </style>
  </head>
  <body class="cs-app">
    <h1>Stories in flight</h1>
    <div id="out" class="empty">Loading…</div>

    <script>
      (function () {
        const out = document.getElementById("out");
        const q = {
          where: { kinds: ["story"] },
          filters: [{ key: "status", op: "in", value: ["in-progress", "review"] }],
          select: ["status"],
          sort: ["status"],
        };

        function render(rows) {
          out.className = rows.length ? "" : "empty";
          out.innerHTML = "";
          if (!rows.length) {
            out.textContent = "Nothing in progress or in review.";
            return;
          }
          rows.forEach((r) => {
            const div = document.createElement("div");
            div.className = "row";
            div.textContent = r.title + " · " + r.fields.status;
            out.appendChild(div);
          });
        }

        codesense.subscribeContext(q, (result, err) => {
          if (err) {
            out.className = "empty";
            out.textContent = "Query failed: " + (err.message || err);
            return;
          }
          render(result.rows);
        });
        codesense.ready();
      })();
    </script>
  </body>
</html>

About 50 lines. One query, one subscription, one render. The viewer handles everything else.

What to try next

  • Show what each story cost. codesense.sessionUsage({story: "DEMO-1"}) returns the tokens and cost of every agent session CodeSense launched for that story; without story, each session carries its own story {id, title, status, epic}, so you can group cost by story or epic and set it beside the stories that reached done.
  • Add a button that runs an action (openWorkspace, setStatus). See calling CodeSense.
  • Theme without authoring colours: use the cs-* classes and tokens, and the page follows the app's light and dark themes. Theme & tokens.
  • Link to another doc with a plain <a href="…/story.md">. The bridge routes the click; ⌘-click opens a new tab. See linking.
  • Iterate without rebuilding: edit the file and watch the tab reload. See testing.

For worked examples that go further (inboxes, agent cards, routine dashboards), browse recipes-gallery.

How an agent does this

Agent-side equivalent

An agent launched from CodeSense reads the page SDK, writes the same file into the team's content folder with its own file tools, and checks it. The outcome is the same: an HTML file in the context repo that CodeSense opens as a live page. 

# 1. Read the page SDK: verbs, query shape, theme tokens
get_live_data_contract {}

# 2. Write dashboards/stories-in-flight.html in the team's content folder

# 3. Check it, and fix any blocking findings
validate_live_data_doc { "path": "<absolute path of the file>" }
