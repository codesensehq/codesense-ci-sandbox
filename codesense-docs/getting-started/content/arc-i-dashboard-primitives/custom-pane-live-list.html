Add a custom pane with a live list and a command

Five steps from a single HTML file to a visible, verifiable pane. Start with the golden live sessions example; no source checkout or bundler is needed.

1. Write the HTML

Read or copy live-list-with-command.html from the docs team's content/examples/dashboards/. It subscribes to live sessions, exposes a running-only filter command and uses native agent row menus. It handles initial/empty/error states, narrow slot context, focus/Escape and flush. Keep its declarations and handlers before ready().

Adjust it using the generated SDK, declarations, capabilities, slots, LiveHub and token references below. Call validate_live_data_doc {content: "…", path:"panes/live-list-with-command.html"} and resolve blocking findings.

Keep live rows stable

Load /kit/v1/virtual-list.js after the kit. Each row needs a stable id. Split its layout payload from live fields: layoutKey(row) returns a string or number describing the markup, while update(element, row, index) patches every reused row on each paint. Initialize the same fields in render. Heartbeats, counts and status changes then keep hover, focus and selection on the same node. 

<div id="sessions" style="height:240px;overflow:auto"></div>
<script src="/kit/v1/kit.js"></script>
<script src="/kit/v1/virtual-list.js"></script>
<script>
  const kit = codesense.kit;
  function patch(el, row, index) {
    el.querySelector(".name").textContent = row.displayName || row.id;
    el.querySelector(".status").textContent = row.effectiveStatus || row.state;
    el.dataset.index = String(index);
  }
  const list = kit.virtualList({
    container: document.getElementById("sessions"),
    rows: [], rowHeight: 28,
    layoutKey: row => row.id,
    render(row, index) {
      const el = document.createElement("button");
      el.append(kit.h("span", {class: "name"}), " · ", kit.h("span", {class: "status"}));
      patch(el, row, index);
      return el;
    },
    update: patch
  });
  codesense.subscribe("sessions", {onChange: snapshot => list.setRows(snapshot.snapshot)});
  codesense.ready();
</script>

This layout always has the same two spans, so its stable id is sufficient. If your markup changes, return JSON.stringify([row.id, row.kind, row.hasActions]) instead. The kit compares the returned value as a string and rebuilds only that row when it changes. update receives the current index after an insert or remove; indexes never determine row versions. Tree ARIA attributes and roving tab stops are refreshed each paint. Omit layoutKey to rebuild on any row payload change (the default).

The same options work with topic: "sessions" instead of local rows; the kit requests the visible hub window. For an unwindowed list, kit.keyed(container, items, {key, render, version, update}) patches same-key, same-version nodes with update(element, item); changed versions call render. Keep event handlers reading the current patched row when their behavior depends on live fields.

2. Save with pane_write

pane_write {org:"your-org/repo", team:"your-team", scope:"team",
  id:"live-list-with-command", html:"…the complete golden HTML…"}

Use your actual org/team values. A private variant uses scope:"personal" with org and no team. This writes the pane file and returns its absolute path; use that path instead of guessing a backing directory.

3. Open with pane_open

pane_open {org:"your-org/repo", team:"your-team", id:"live-list-with-command"}
pane_list {org:"your-org/repo", team:"your-team"}

Check that placed is true. If it is false, follow the returned reason and switch to a team that shows the pane. Pick its current absolute path from pane_list. The open tool reveals a right pane; dock replacement selection is in Settings.

4. Verify visible behavior

read_rendered_document {path:"<absolute pane_list path>", format:"text"}
command_list {}
command_run {id:"<the returned dashboard/command id for toggle-filter>"}
read_rendered_document {path:"<the same absolute pane path>", format:"text"}

The first capture should show “All sessions”; after running the command it should show “Running only” and the changed row count/list. This feedback works even when the team has no sessions. Commands are delivered after readiness. Allow capture after the command has rendered; if necessary take another point-in-time read. A refusal explains whether to open/show the pane or fix its fallback. Wait beyond the 30-second startup deadline and capture again to check it stays live.

Also try the visible filter button, its configured chord and an agent row's native menu. Those human interactions need a real-app walk; report them as unproven until performed. See proof boundaries.

5. Share the file

A team pane is a file in the context repository. Review the diff, then share through whatever git sync workflow you and the user choose. CodeSense provides git state and sync tools; the agent decides when to commit and push. Private panes remain in the person's space unless deliberately copied to a team. Keep the validation and visible before/after evidence with your handoff.
