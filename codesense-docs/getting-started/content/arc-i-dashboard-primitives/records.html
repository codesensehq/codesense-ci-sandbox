Records

Collections give a pane structured records with scoped access, live updates and version-aware writes.

Declare a collection

Place this file at the team's content/schema/checklist.yaml. The folder is relative to the team root. Each record is stored separately. Collection names must match their schema filenames. 

collection: checklist
scope: team
folder: content/checklist
id: slug
title: title
fields:
  title: { type: text, required: true }
  done: { type: yes-no }
order: [title]

Team collections belong to their team root; private collections belong to the person's private org space and include the built-in notes collection. A story collection declares scope: story in the team schema, with a folder relative to content. Scope is resolved from the collection and the caller's grant; page calls must not pass their own scope, org or team. Use distinct names for private and team collections to avoid ambiguous resolution.

Keep records append-only for agents

A collection reserves actions for the person with a top-level humanOnly key in its schema file. Do not nest it under options; a nested map is ignored. An agent's records_* call is refused with only a human can … records in this collection; a person is never refused. A schema that names any other action fails to load. 

humanOnly: [write, setFields, delete]
  • delete: agents cannot delete a record (the built-in notes collection lists this).
  • write: agents cannot edit a record: records_write, records_set_fields and records_restore are all refused.
  • setFields: agents cannot change frontmatter fields: records_set_fields, a records_write that sends fields (with an append, a replacement or the same body) and a full records_restore are refused. A body-only records_write stays allowed unless write is listed.

records_create is never refused. “Append-only” means humanOnly: [write, setFields, delete]: agents add records, people correct them.

humanOnly applies to records_* calls. It sets how agents are expected to use a collection; it is not a security boundary. File tools and update_frontmatter write the Markdown files directly, and a page or dashboard call runs as the person, so keep a checker if a collection must stay append-only.

Read and subscribe

<meta name="codesense:capabilities" content="records:read:team records:write:team">
<ul id="records" aria-label="Checklist"></ul>
<p id="status" role="status">Loading…</p>
<script>
const cs = window.codesense;
const list = document.getElementById('records');
const status = document.getElementById('status');
function showError(error) { status.textContent = String(error.message || error); }
function receive(snapshot) {
  list.replaceChildren();
  for (const record of snapshot.snapshot) {
    const item = document.createElement('li');
    item.textContent = record.title || record.id;
    list.append(item);
  }
  status.textContent = snapshot.snapshot.length ? 'Checklist updated' : 'No checklist records yet';
}
cs.onTeardown(() => cs.unsubscribe('records', receive, {collection: 'checklist'}));
cs.ready();
cs.subscribe('records', {collection: 'checklist', onChange: receive})
  .then(receive).catch(showError);
</script>

Use records.collections() to discover declared collections, records.list({collection}) for a one-time list, and records.read({collection,id}) for one full record. The records LiveHub topic pushes snapshots and deltas through the same hidden/stale lifecycle as sessions. Private records require own-scope grants, which the dock ceiling does not offer.

Write safely

// Run inside an async button handler; catch errors and keep the edit visible.
await cs.records.create({collection: 'checklist', id: 'review',
  body: 'Read the draft', fields: {title: 'Review', done: false}});
const current = await cs.records.read({collection: 'checklist', id: 'review'});
const result = await cs.records.write({collection: 'checklist', id: 'review',
  base: current.body, body: 'Read the revised draft'});
if (result.overlaps.length) {
  status.textContent = 'Concurrent edit overlaps: review the merged record';
} else {
  await cs.records.setFields({collection: 'checklist', id: 'review', fields: {done: true}});
}

Use the exact body you read as base for a replacement. Concurrent edits are merged; the result reports merged and overlaps. Show overlapping regions for review instead of silently claiming the edit is final. For an append or a find/replace patch use the operation's documented fields. Update only fields you intend to change, await writes and preserve the person's unsaved input on an error. Keep a stable requestId when retrying an uncertain write; do not blindly repeat creates. Private collections have history, readAt and restore; team and story collections have no automatic history. See records verb signatures; the engine, collection schema and grant still validate every call.
